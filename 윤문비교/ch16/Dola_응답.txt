[47] 그렇다면 더하기 버튼의 클릭 이벤트 처리 첫 부분에 이벤트 전파 차단 명령이 포함된 이유는 무엇일까요? 이는 클릭 이벤트가 상위 요소로 더 이상 전달되지 않도록 하기 위한 조치입니다. 비록 현재의 구조에서는 이벤트 적용 범위를 구분하여 두었기 때문에 이 명령이 없어도 문제가 발생하지 않을 수 있지만, 추후 검색 결과 목록 전체에 다른 이벤트를 추가하는 경우 예기치 않은 충돌이 발생할 수 있습니다. 따라서 이 한 줄은 추후의 변경 사항에 대응하기 위한 예방적 조치입니다. 검색 결과 목록과 같이 내부에 버튼이 포함되는 구조를 제작하는 경우, 클릭 이벤트의 적용 범위를 구분하고, 내부 버튼에서는 이벤트 전파를 차단하는 두 가지 조치를 함께 적용하여 주시기 바랍니다.
[48] 마지막으로, 장소 추가 기능 구현 시 화면 사용 환경을 개선하기 위한 조치가 포함되었습니다. 장소 추가 양식이 열리는 동안에는 배경의 검색 결과 목록을 숨기도록 설정하였습니다. 이는 여러 정보가 동시에 표시되어 화면이 복잡하고 혼란스러워지는 것을 방지하기 위한 조치입니다.
[49] 그림 16.4 — 각 검색 결과 항목에 추가된 더하기 버튼
[50] 이제 브라우저에서 실제로 기능을 확인하여 보겠습니다. 원하는 장소를 검색한 후 해당 항목의 더하기 버튼을 클릭하면, 검색 결과 목록은 사라지고 장소 추가 양식이 표시됩니다. 이름 입력란에 해당 장소의 이름이 자동으로 입력되어 있는 것을 확인하여 주십시오. 검색 결과로부터 전달받은 이름 정보가 입력 양식에 정상적으로 반영된 결과입니다. 카테고리는 기본값으로 '맛집'이 선택되어 있으므로, 필요한 경우 '카페' 등으로 변경한 후 추가 버튼을 누르면 안내 메시지가 표시되고 즉시 지도에 마커가 추가되는 것을 확인할 수 있습니다.
[51] 그림 16.5 — 더하기 버튼 클릭 시 이름이 자동으로 입력된 상태의 장소 추가 양식
[52] 두 번째 장소 추가 경로는 구현 방식이 비교적 간단합니다. 장소 추가를 위한 입력 양식이 이미 준비되어 있으므로, 지도 클릭 이벤트와 연결하는 작업만 수행하면 완료됩니다. 10장에서 지도를 클릭하면 해당 위치의 좌표를 확인할 수 있다고 말씀드린 바 있습니다. 바로 이번 장에서 그 기능을 실제로 활용하게 됩니다.
[53] 인공지능이 지도 관련 파일에 추가한 코드는 단 세 줄에 불과합니다. 관련 라이브러리 불러오기 명령을 포함하여도 네 줄입니다.
[54] 지도 클릭 이벤트를 등록하는 방식은 10장에서 배운 카카오 지도 API의 사용 방식과 동일합니다. 클릭 이벤트로부터 전달받은 정보에서 해당 지점의 좌표 정보를 추출하며, 위도와 경도 값을 각각 분리하여 확인할 수 있습니다. 10장에서는 이 좌표 값을 단순히 콘솔에 출력하는 데 그쳤지만, 이번에는 해당 좌표 정보를 장소 추가 함수에 전달하여 호출합니다. 장소 이름에 관한 정보는 전달하지 않았으므로, 입력 양식의 이름 입력란은 비어 있는 상태로 표시됩니다. 장소 추가 시 이름 유효성 검증, 정보 저장, 화면 갱신의 순서로 작동하는 로직은 이미 완성되어 있으므로, 지도 클릭을 통하여 장소를 추가하는 경우에도 즉시 지도에 마커가 표시됩니다. 10장의 간단한 실습이 실제 서비스의 핵심 기능으로 구현된 것입니다.
[55] 이제 이번 장에서 구현한 모든 내용을 처음부터 끝까지 다시 한번 점검하여 보겠습니다. 브라우저를 새로고침한 후 아래 설명하는 순서대로 따라하여 확인하여 주십시오.
[56] 그림 16.6 — 지도 클릭을 통하여 추가한 장소에 마커가 표시된 모습
[57] 아래의 네 가지 항목이 모두 정상적으로 작동하는 것을 확인하시면, 이제 실제로 원하는 장소를 직접 추가할 수 있습니다. 카카오의 방대한 장소 데이터베이스에서 원하는 장소를 찾아 추가할 수도 있으며, 지도 상의 아무 곳이나 클릭하여 자신만 알고 있는 장소를 등록할 수도 있습니다.
[58] 더하기 버튼을 클릭하였을 때 장소 추가 양식과 함께 지도가 예기치 않게 이동하는 경우, 지도 이동 기능의 적용 범위가 검색 결과 항목 전체로 설정되어 있을 가능성이 높습니다. 이 경우 앞서 설명한 바와 같이 이벤트 적용 범위를 조정하여야 합니다. 추가 버튼을 눌렀으나 마커가 표시되지 않는 경우, 데이터 변경 후 화면 갱신 함수를 정상적으로 호출하였는지 확인하여 주십시오. 추가한 마커가 장소 분류 필터에 따라 정상적으로 표시되지 않는 경우, 필터링 로직이 올바르게 작동하는지 확인하여 주십시오. 이와 같이 증상에 따라 문제의 원인이 될 수 있는 부분을 특정할 수 있으면, 해당 부분의 수정 작업은 인공지능에게 요청하여 처리할 수 있습니다.
[59] 마지막으로 한 가지 더 확인하여 보겠습니다. 방금 추가한 장소가 지도에 정상적으로 표시되어 있을 것입니다. 이제 브라우저를 새로고침하여 보십시오. 추가하였던 장소는 사라지고 12장에서 등록한 기본 장소만 표시될 것입니다. 현재 장소 데이터가 브라우저의 메모리에만 임시로 저장되고 있기 때문입니다. 브라우저의 메모리에 보관된 정보는 브라우저를 재시작하거나 새로고침하면 모두 사라집니다. 이 문제는 다음 장에서 해결하겠습니다.
[60] 질문 1. 장소 추가용 입력 양식을 검색용과 지도 클릭용으로 별도로 두 개를 만들었다면, 추후 어떤 상황에서 어떤 문제가 발생할 수 있을까요? 구체적인 예를 들어 설명하여 보십시오.
