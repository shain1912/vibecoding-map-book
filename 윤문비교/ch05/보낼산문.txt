[56] 브라우저에 【34】 페이지가 뜨고, 방금 만든 README가 보이면 성공입니다. 저장소 페이지를 살펴봅시다. 가운데에 파일 목록이 나오고, 그 아래에는 README 내용이 자동으로 펼쳐집니다. 파일 목록 위의 【35】 같은 표시를 누르면 커밋 이력을 볼 수 있습니다. 커밋이 쌓일수록 이 이력이 길어지고, 프로필의 기여 그래프에도 초록 칸이 하나씩 늘어날 겁니다.

[57] 이 순서를 이 책 전체에서 계속 되풀이할 겁니다. 작업이 하나 끝날 때마다 커밋하고(commit) 올립니다(push). 저자는 기능 하나를 완성할 때마다 Claude Code에게 【36】라고 시킵니다. 이 두 단계를 습관으로 들이면 하루 작업이 통째로 사라지는 일을 막을 수 있습니다. 24장에서는 지도 웹앱을 이 방법 그대로 올리고, 25장에서는 그 저장소로 배포합니다.

[58] 연습이 끝난 【37】 저장소는 지워도 되고 그냥 두어도 됩니다. 지우려면 깃허브 저장소 페이지에서 Settings 탭 맨 아래 Danger Zone의 Delete this repository를 누릅니다. 저장소 이름을 직접 입력해야 지워집니다. 실수로 지우는 일을 막으려는 장치입니다.

[59] 이것으로 작업 환경을 다 갖췄습니다. Node.js(2장) 위에서 도구가 실행되고, Git(3장)이 변경 이력을 기록합니다. Claude Code(4장)가 코드를 작성하고, GitHub CLI(5장)가 그 결과를 인터넷에 올립니다. 앞으로 어떤 장에서든 【39】라고 시키면 커밋과 푸시를 함께 처리해 줄 겁니다. 터미널에서 【38】 한 줄이면 언제든 연결 상태를 확인할 수 있으니 이 명령도 기억해 두세요.
