# 4장 Claude Code 설치와 첫 사용

!!! note "이 장에서 배우는 것"
    - Claude 계정을 만들고 Pro 플랜을 준비하는 방법

## 4.1 Claude Code란

2장에서 Node.js를, 3장에서 Git을 설치했습니다. 이제 이 책에서 가장 많이 쓰게 될 Claude Code를 설치하겠습니다.

Claude Code는 Anthropic이 만들었고 터미널에서 동작합니다. 챗봇에게 질문하고 답을 복사해 오는 방식으로 쓰는 도구는 아닙니다. 프로젝트 폴더 안에 직접 들어와서 파일을 읽고, 코드를 쓰고, 명령을 실행하고, 에러가 나면 스스로 고칩니다. "지도를 화면에 띄워줘"라고 요청하면 어떤 파일을 만들어야 하는지 스스로 판단해 만들어 줍니다.

코드를 복사해서 붙여 넣지 않아도 된다는 점이 다릅니다.

챗봇으로 코딩을 해 보면 이런 과정을 거치게 됩니다. 코드를 받아서 붙여넣었는데 에러가 나고, 에러 메시지를 다시 복사해서 챗봇에게 보여주고, 고친 코드를 또 붙여넣습니다. 이 왕복이 작업 시간의 상당 부분을 차지할 수도 있습니다. Claude Code에서는 이 과정이 없습니다. 에러가 나면 스스로 읽고 고칩니다. 여러분은 방향만 정해 주면 됩니다.

![챗봇 방식과 Claude Code 방식의 차이](images/ch04/ch04-f01.jpg){ width="760" }
/// caption
그림 4.1 — 챗봇 방식과 Claude Code 방식의 차이
///

이런 방식으로 일하는 프로그램을 에이전트(agent)라고 부릅니다. 질문에 답만 하지 않고, 목표를 받으면 계획을 세우고, 도구를 골라 쓰고, 중간 결과를 확인하면서 다음 행동을 스스로 정할 수 있습니다. 1장에서 에이전트에게 일을 시킬 때 지킬 것을 이야기했는데, 그 에이전트가 Claude Code를 가리킵니다. 여러분은 코드를 쓰지 않고 일을 시킵니다. 무엇을 만들지 정하고, 진행 상황을 확인하고, 방향이 틀어지면 바로잡습니다.

지도를 띄우고 마커를 찍고 검색을 붙이고 배포하는 일까지, 이 책의 나머지 작업은 모두 이 도구에게 시켜 진행하게 됩니다. 그래서 이번 장에서는 설치와 함께, 어떻게 요청해야 원하는 결과가 나올지도 함께 다루겠습니다.

## 4.2 계정 만들기와 Pro 플랜

Claude Code를 쓰려면 Claude 계정이 필요합니다. 아직 없으시면 지금 만들어 봅시다.

1. 브라우저에서 claude.ai 에 접속합니다.
2. 구글 계정으로 가입하거나 이메일 주소로 가입합니다. 이메일로 가입하면 인증 메일이 오니 받은편지함을 확인해 주세요.
3. 가입이 끝나면 채팅 화면이 열릴 겁니다. 이 계정 하나로 웹의 Claude와 터미널의 Claude Code를 모두 쓸 수 있습니다.

![claude.ai 가입 화면 (예시)](images/ch04/ch04-f02.png){ width="560" }
/// caption
그림 4.2 — claude.ai 가입 화면 (예시)
///

가입할 때 쓴 이메일 주소는 기억해 두시는 게 좋습니다. 잠시 뒤 터미널에서 로그인할 때 같은 계정을 쓰게 됩니다. 계정이 두 개면 결제한 계정과 로그인한 계정이 달라져 원인을 찾기 어려워질 수 있습니다.

플랜도 정해야 합니다. 무료 플랜으로도 Claude와 대화할 수 있지만, Claude Code를 계속 쓰려면 월 20달러 수준의 Pro 플랜을 권합니다. 이 책의 실습은 Pro 플랜 기준으로 진행하겠습니다. 화면 왼쪽 아래 프로필 → 설정에서 플랜을 업그레이드할 수 있습니다.

책 한 권을 따라 하려고 유료 결제를 해야 하는지 망설여질 수 있습니다. 이 책의 실습을 처음부터 끝까지 진행하는 데는 한 달이면 충분하므로, 한 달만 구독하고 해지해도 됩니다. 결제가 부담스럽다면 이 장 끝의 무료 대안 박스를 참고하세요. 책의 흐름은 다른 도구로도 따라올 수 있습니다.

!!! warning "주의"
    Pro 플랜에도 사용량 한도가 있습니다. 일정 시간 안에 쓸 수 있는 양이 정해져 있어서, 긴 작업을 쉬지 않고 시키면 "한도에 도달했다"는 안내와 함께 잠시 기다리게 되기도 합니다. 고장이 아니라 정상 동작이니, 안내된 시간이 지나면 다시 쓰실 수 있습니다. 이 책의 실습 분량은 Pro 한도 안에서 처리할 수 있습니다.

## 4.3 설치: 명령어 한 줄이면 됩니다

2장에서 Node.js를 설치할 때 npm이 함께 깔렸습니다. 그 npm을 여기서 처음 씁니다. Windows Terminal이나 PowerShell을 열고 아래 한 줄을 입력하세요.

```
npm install -g @anthropic-ai/claude-code
```

명령어를 뜯어보면 이렇습니다.

- `npm install` — 패키지를 설치하라.
- `-g` — global(전역)의 약자. 지금 폴더만이 아니라 컴퓨터 어디서든 쓸 수 있게 설치하라는 뜻입니다. Claude Code는 앞으로 모든 프로젝트에서 부를 도구니까 전역으로 설치합니다.
- `@anthropic-ai/claude-code` — 패키지 이름. `@anthropic-ai/`는 Anthropic 팀이 배포한 공식 패키지라는 소속 표시입니다.

진행 막대가 지나가고 몇 줄의 로그가 출력되면 설치가 끝납니다.

![npm으로 Claude Code 설치 (출력 예시)](images/ch04/ch04-f03.png){ width="760" }
/// caption
그림 4.3 — npm으로 Claude Code 설치 (출력 예시)
///

잘 설치됐는지 확인해 봅시다. Node.js에서 `node -v`로 확인했던 것과 같은 방식이라고 보시면 됩니다.

```
claude --version
```

버전 번호가 출력되면 설치된 것입니다. Claude Code는 업데이트가 잦은 도구라서, 책의 화면과 여러분의 화면이 조금 다를 수 있습니다. 다만 설치하고, 실행하고, 말로 시키고, 승인하는 구조까지 바뀌는 것은 아닙니다. 최신 버전으로 올리려면 설치 때와 똑같은 명령을 한 번 더 실행하면 됩니다.

![claude --version으로 설치 확인](images/ch04/ch04-f04.png){ width="760" }
/// caption
그림 4.4 — claude --version으로 설치 확인
///

!!! tip "팁"
    `claude`를 입력했는데 "명령을 찾을 수 없습니다"라는 에러가 나면, 대부분 터미널을 새로 열면 해결됩니다. 설치 직후에는 이미 열려 있던 터미널 창이 새 명령어의 위치를 알지 못합니다. 2장에서 다룬 PATH 때문에 생기는 문제입니다. 새 창에서도 안 되면 `npm install -g @anthropic-ai/claude-code`를 한 번 더 실행해 보세요.

## 4.4 첫 실행과 로그인

이제 실행해 봅시다. 연습용 폴더를 하나 만들고 그 안에서 실행하겠습니다. Claude Code는 실행한 폴더 안의 파일만 다루기 때문에, 아무 곳에서나 실행하지 말고 프로젝트 폴더 안에서 실행하는 습관을 들이는 것이 좋습니다.

```
mkdir hello-claude
cd hello-claude
claude
```

`mkdir`은 폴더를 만들고 `cd`는 그 폴더로 이동합니다. 마지막 줄의 `claude`가 Claude Code를 실행해 줍니다.

처음 실행하면 몇 가지 초기 설정 화면이 나옵니다. 화면 테마를 고르는 정도이니 마음에 드는 것을 선택하면 됩니다. 그다음에 로그인을 합니다. 로그인 방법을 묻는 화면에서 Pro 플랜 구독 계정으로 로그인하는 항목을 선택하세요. 그러면 브라우저가 자동으로 열리면서 claude.ai 인증 페이지로 이동합니다. 4.2절에서 만든 계정으로 로그인하고 승인 버튼을 누르면, 터미널로 돌아와 "로그인 완료" 안내를 볼 수 있습니다.

![Claude Code 첫 실행 화면](images/ch04/ch04-f05.png){ width="760" }
/// caption
그림 4.5 — Claude Code 첫 실행 화면
///

로그인이 끝나면 입력창이 깜빡이는 대화 화면이 나타납니다. 앞으로 이 책의 실습은 대부분 이 화면에서 진행합니다. 간단한 요청부터 해 봅시다.

!!! tip "이렇게 물어보세요"
    > 안녕! 이 폴더에 hello.txt 파일을 만들고, 그 안에 "바이브코딩 시작!"이라고 써줘.

Claude Code가 파일을 만들어도 되는지 허락을 구하는 화면을 보여 줍니다. 이 화면은 4.6절에서 자세히 다룹니다. 허용을 선택하면 파일이 만들어지고, 탐색기로 폴더를 열어 보면 `hello.txt`가 생겨 있습니다. 코드를 한 줄도 입력하지 않고 파일을 만들었습니다.

이번에는 만들기가 아니라 물어보기를 시켜 봅시다.

!!! tip "이렇게 물어보세요"
    > 방금 무슨 일을 했는지, 그리고 이 폴더에 지금 어떤 파일이 있는지 정리해서 알려줘.

Claude Code가 폴더를 살펴보고 현재 상황을 요약해 줍니다. 이 사용법을 기억해 두세요. 앞으로 코드가 이해되지 않을 때마다 "이 코드가 무슨 뜻인지 설명해줘", "왜 이렇게 짰어?"라고 물어보는 것이 이 책의 학습 방식입니다. 1장에서 말한 "이해하려 노력하되 외우지 않는다"는 방침은 궁금할 때마다 바로 물어볼 수 있기 때문에 가능합니다. 설명 요청은 파일을 바꾸지 않으므로 권한 프롬프트도 뜨지 않습니다.

대화를 끝내고 싶으면 `/exit`를 입력하거나 Ctrl+C를 두 번 누르시면 됩니다. 다시 시작하고 싶으면 그 폴더에서 `claude`를 다시 실행하면 됩니다.

!!! tip "팁"
    입력창에 `/`를 입력하면 슬래시 명령어 목록이 열립니다. 지금 다 외울 필요는 없고, `/exit`(종료), `/clear`(대화 초기화), `/help`(도움말) 세 개만 기억해 두세요. 나머지는 필요할 때마다 책에서 하나씩 소개하겠습니다.

## 4.5 요청하는 법: 프롬프트의 4요소

설치는 끝났습니다. 이제 어떻게 요청해야 하는지 살펴봅시다.

Claude Code는 여러분이 말한 것만 알 수 있습니다. 같은 일을 시켜도 어떻게 말하느냐에 따라 결과가 크게 달라집니다. AI에게 보내는 이런 요청문을 프롬프트(prompt)라고 부릅니다. 좋은 프롬프트에는 네 가지가 들어갑니다. 맥락, 목표, 제약, 출력 형식입니다.

![프롬프트의 4요소](images/ch04/ch04-f06.png){ width="760" }
/// caption
그림 4.6 — 프롬프트의 4요소
///

하나씩 살펴봅시다. 예시는 전부 우리가 만들 지도 앱에서 가져왔으니 낯설지 않을 겁니다.

① 맥락(Context). 지금 어떤 상황인지 알려 줍니다. Claude Code는 폴더 안의 파일을 읽을 수 있지만, 여러분이 무엇을 하려는지까지 아는 것은 아닙니다. 프로젝트가 무엇이고 지금 어디까지 진행됐는지 한 줄이라도 적어 주면 결과가 달라집니다.

- 나쁜 예: "지도 띄워줘." 어떤 지도인지, 무슨 프로젝트인지 알 수가 없습니다.
- 좋은 예: "카카오지도 JS SDK를 쓰는 Vite 바닐라 JS 프로젝트야. 지금 빈 페이지 상태고, 여기에 지도를 띄우고 싶어."

② 목표(Goal). 원하는 결과를 구체적으로 적습니다. "잘 만들어줘"라고만 써서는 무엇을 만들지 정할 수는 없습니다. 완성된 화면이 어떤 모습인지 알 수 있게 적어야 합니다.

- 나쁜 예: "마커 기능 추가해줘."
- 좋은 예: "장소 데이터에 있는 맛집 5곳에 마커를 찍고, 마커를 클릭하면 가게 이름이 말풍선으로 뜨게 해줘."

③ 제약(Constraints). 하지 말아야 할 것과 지켜야 할 것을 적습니다. 네 요소 중에서 빠뜨리기 쉬운 항목일 겁니다. 범위를 정해 주지 않으면 AI가 파일을 여러 개 만들거나, 쓰지 않는 라이브러리를 설치하거나, 잘 동작하던 코드까지 고쳐 놓기도 합니다. 건드리지 말아야 할 범위를 적어 주세요.

- 예: "라이브러리는 새로 설치하지 말고, mapView.js 파일 하나만 수정해줘."
- 예: "지도 키는 코드에 직접 쓰지 말고 .env에서 읽어줘."

④ 출력 형식(Output). 결과를 어떤 형태로 받을지 적습니다. 코드만 받을지, 설명도 함께 받을지, 확인 방법까지 받을지 미리 알려 주면 다시 물을 일이 줄어듭니다.

- 예: "바뀐 부분만 보여주고, 왜 그렇게 했는지 한 줄씩 설명해줘."
- 예: "다 만들면 브라우저에서 확인하는 방법을 알려줘."

네 요소를 전부 합치면 이런 프롬프트가 됩니다.

!!! tip "이렇게 물어보세요"
    > 카카오지도 JS SDK를 쓰는 Vite 바닐라 JS 프로젝트야. (맥락)
    > 장소 데이터의 맛집 5곳에 마커를 찍고, 클릭하면 가게 이름 말풍선이 뜨게 해줘. (목표)
    > 새 라이브러리 설치는 하지 말고 mapView.js만 수정해. (제약)
    > 바뀐 부분만 보여주고 한 줄씩 설명해줘. (출력 형식)

`hello-claude` 폴더에서 4요소를 갖춘 프롬프트를 직접 실행해 봅시다.

!!! tip "이렇게 물어보세요"
    > 여기는 연습용 폴더야. (맥락)
    > 내가 좋아하는 장소 세 곳의 이름과 한 줄 소개를 담은 places.txt 파일을 만들어줘. (목표)
    > 파일은 하나만 만들고, 내용은 한국어로 써. (제약)
    > 다 만들면 파일 내용을 보여줘. (출력 형식)

비교를 위해 대화를 `/clear`로 초기화한 뒤, 이번에는 "장소 파일 만들어줘"라고만 시켜 보세요. 어떤 장소를 어떤 형식으로 만들지 AI가 알아서 정해 버릴 겁니다. 결과물의 품질이 낮다는 뜻이 아니라, 여러분이 원한 것과 다를 가능성이 높다는 뜻입니다. 프롬프트가 구체적일수록 AI가 추측하는 부분이 줄고, 그만큼 다시 시키는 횟수도 줄어듭니다.

매번 네 요소를 다 갖출 필요는 없습니다. "오타 고쳐줘" 같은 작은 요청은 한 줄이면 충분할 겁니다. 다만 결과물이 마음에 들지 않을 때 프롬프트를 다시 보면 네 요소 중 하나가 빠져 있는 경우가 많습니다. 그때 이 네 가지를 기준으로 점검하세요. 앞으로 이 책의 모든 "이렇게 물어보세요" 박스도 이 네 요소로 쓰여 있습니다. 박스를 읽을 때 맥락과 제약이 각각 어디인지 찾아보면 프롬프트를 쓰는 방법이 익숙해집니다.

!!! tip "팁"
    1장에서 말한 "작게 시키기"를 함께 지켜야 합니다. 네 요소를 갖췄더라도 "지도 앱 전부 다 만들어줘"처럼 목표가 크면 결과를 확인하고 되돌리기가 어려울 겁니다. 지도 띄우기, 그다음 마커, 그다음 말풍선처럼 한 번에 하나씩 시킵니다.

## 4.6 안전하게 쓰기: 권한 프롬프트 읽는 법

4.4절에서 파일 하나를 만드는 데도 Claude Code가 허락을 구했습니다. 이 권한 프롬프트가 Claude Code의 안전장치입니다.

Claude Code는 여러분의 컴퓨터에서 실제로 파일을 고치고 명령을 실행하는 도구입니다. 그만큼 잘못된 지시 한 번이 실제 피해로 이어질 수 있습니다. 그래서 Claude Code는 파일을 새로 만들거나 수정할 때, 그리고 명령어를 실행할 때 먼저 계획을 보여 주고 승인을 기다립니다.

![권한 프롬프트 화면](images/ch04/ch04-f07.png){ width="760" }
/// caption
그림 4.7 — 권한 프롬프트 화면
///

허용 여부를 판단하는 기준은 간단합니다.

- 파일 만들기·수정: 대상 파일이 내 프로젝트 폴더 안이고, 보여준 변경 내용이 내가 시킨 일과 맞으면 허용합니다.
- 명령 실행: 무슨 명령인지 읽어 봅니다. 패키지를 설치하는 `npm install`이나 개발 서버를 띄우는 `npm run dev`처럼 이 책에서 배운 명령이면 허용하셔도 괜찮습니다.
- 모르겠으면 물어보기: 승인하기 전에 "이 명령이 뭐 하는 건지 먼저 설명해줘"라고 입력하면 됩니다. Claude Code는 설명해 주고 다시 물어봅니다. 모르는 것을 승인하지 않는 습관 하나로 대부분의 위험을 막을 수 있습니다.

반대로 다음과 같은 경우에는 승인을 멈추고 확인해야 합니다. 시킨 적 없는 파일을 지우겠다고 할 때, 프로젝트 폴더 바깥의 경로를 건드리려 할 때, 처음 보는 프로그램을 설치하겠다고 할 때입니다. 이럴 때는 거절해도 됩니다. 거절하면 Claude Code가 다른 방법을 제안하거나 이유를 설명해 줄 겁니다. "그 파일은 지우지 말고 다른 방법을 찾아봐"처럼 거절 뒤에 방향을 덧붙이면, 4.5절에서 배운 제약을 추가하는 것과 같은 효과가 납니다.

매번 묻는 것이 번거로우면 "이번 세션 동안 같은 종류는 허용" 같은 선택지로 반복 승인을 줄일 수 있습니다. 다만 처음 얼마 동안은 하나하나 읽으면서 허용하기를 권합니다. 승인 화면을 읽으면 AI가 어떤 파일을 왜 고치는지 확인할 수 있습니다.

!!! warning "주의"
    권한 확인을 아예 꺼 버리는 옵션도 있지만, 이 책을 따라 하는 동안은 끄지 마세요. 확인 절차가 번거롭더라도 잘못된 수정을 실행 전에 막을 수 있는 지점은 여기뿐입니다. 3장에서 설치한 Git도 함께 쓰세요. 커밋해 둔 상태라면 AI가 파일을 어떻게 고쳐 놓아도 되돌릴 수 있습니다.

!!! info "꼭 Claude Code가 아니어도 됩니다"
    Pro 결제가 어렵다면 비슷한 터미널 AI 도구로 책을 따라올 수 있습니다. 프롬프트 4요소는 어느 도구에서나 똑같이 쓸 수 있습니다.

    - `opencode` — 오픈소스 터미널 코딩 에이전트. 여러 AI 모델을 골라 연결할 수 있고 무료 모델 조합도 가능합니다.
    - `codex` — OpenAI의 터미널 코딩 에이전트. ChatGPT 계정으로 사용합니다.
    - `antigravity` — 구글의 AI 코딩 도구. 구글 계정으로 무료 사용이 가능합니다.

    단, 이 책의 화면·명령어 설명은 Claude Code 기준이라 세부 조작은 조금씩 다를 수 있습니다.

## 4.7 마무리

!!! abstract "이 장의 핵심"
    - Claude Code는 터미널에서 파일을 직접 읽고 쓰고 실행하는 AI 코딩 에이전트로, 복사-붙여넣기 왕복이 없습니다.
    - 설치는 `npm install -g @anthropic-ai/claude-code` 한 줄, 확인은 `claude --version`입니다.
    - 프로젝트 폴더 안에서 `claude`를 실행하고, 브라우저 인증으로 Pro 계정과 연결합니다.
    - 좋은 프롬프트의 4요소는 맥락·목표·제약·출력 형식입니다.
    - 권한 프롬프트는 안전장치입니다. 내용을 읽고 허용하고, 모르겠으면 설명을 먼저 요청하세요.
