# 7장 카카오 개발자 계정과 앱 만들기

!!! note "이 장에서 배우는 것"
    - API 키가 무엇이고 왜 필요한지 이해합니다
    - developers.kakao.com에 개발자 계정을 만들고 애플리케이션(앱)을 생성합니다
    - REST API 키, JavaScript 키, 네이티브 앱 키 가운데 JavaScript 키가 어디에 쓰이는지 배웁니다
    - JavaScript 키의 JavaScript SDK 도메인에 `http://localhost:5173`을 등록합니다
    - 키를 공개하면 안 되는 이유와 "도메인 제한"의 의미를 배웁니다

---

1부에서 바이브코딩에 필요한 도구를 하나씩 설치했습니다. Node.js, Git, Claude Code, GitHub CLI, Orca까지 갖췄으니 이제 지도만 준비하면 되겠습니다.

우리가 만들 웹앱은 카카오지도를 바탕으로 합니다. 카카오가 제공하는 지도 API[^1]를 쓰면 카카오맵 앱에서 보던 지도를 우리 웹페이지 안에 넣을 수 있습니다. 다만 카카오는 아무 웹페이지에나 지도를 내주지 않고, 요청한 쪽이 누구인지 확인할 수 있는 인증 키를 요구합니다. 이번 장에서 그 키를 발급받겠습니다.

이번 장에서는 코드를 쓰지 않으므로 Claude Code에게 시킬 일도 없습니다. 웹사이트 가입과 설정은 사람 손이 빠르고 정확하니, 이 장은 직접 클릭해 가며 진행하시는 편이 낫습니다. 마우스 클릭 몇 번으로 끝나지만, 여기서 발급받는 키를 8장부터 26장까지 계속 씁니다. 이 장의 마지막 절에서 다루는 키 보안 원칙은 다른 API를 쓸 때도 그대로 통합니다.

## 7.1 API 키란 무엇인가

먼저 개념부터 짚어 봅시다. API 키란 무엇일까요?

우리 웹페이지는 카카오 서버에 요청을 보낼 때 API 키라는 문자열을 함께 보냅니다. 카카오 서버는 이 문자열을 보고 등록된 개발자의 요청인지 확인한 뒤 지도 데이터를 내어 줍니다. 키가 없거나 등록되지 않은 키를 보내면 요청이 거절됩니다.

키가 왜 필요한지는 카카오 입장에서 보면 쉽게 이해할 수 있습니다.

먼저 누가 얼마나 쓰는지 알아야 합니다. 지도 데이터를 서버에서 내려보내는 데는 비용이 듭니다. 키가 있으면 어떤 앱이 하루에 지도를 몇 번 불렀는지 셀 수 있고, 사용량이 지나치면 제한할 수 있습니다.

문제가 생겼을 때 연락할 수단도 있어야 합니다. 어떤 앱이 비정상적인 요청을 쏟아내면, 카카오는 키를 보고 어느 개발자의 앱인지 찾아 조치합니다.

개발자 쪽에서도 키를 보호 장치로 쓸 수 있습니다. 뒤에서 자세히 다루겠지만, 키가 특정 주소에서만 동작하도록 제한을 걸어 두면 남이 내 키를 가져다 쓰지 못하게 막을 수 있습니다.

카카오 개발자 사이트에서 계정을 만들고 애플리케이션을 하나 등록하면 카카오가 그 앱에 키를 발급해 줍니다. 이번 장에서 할 일은 여기까지라고 보시면 됩니다.

!!! tip "팁"
    여기서 말하는 "앱"은 스마트폰 앱을 만들어 스토어에 올린다는 뜻이 아닙니다. 카카오 개발자 사이트의 애플리케이션은 프로젝트를 등록해 두는 항목 하나를 가리킵니다. 이름만 정해서 등록하면 되고 1분이면 끝납니다.

## 7.2 카카오 개발자 사이트 가입하기

이제 실제로 해 봅시다. 브라우저를 열고 주소창에 아래 주소를 넣어 보세요.

```
https://developers.kakao.com
```

"카카오 디벨로퍼스(Kakao Developers)"라는 사이트가 열립니다. 카카오가 외부 개발자에게 지도, 로그인, 메시지 같은 기능을 제공하는 공식 사이트입니다. 첫 화면을 살펴보면 카카오톡 메시지 보내기, 카카오로 로그인하기처럼 다른 앱에서 보던 기능들을 여기서 모두 찾아볼 수 있습니다.

![카카오 디벨로퍼스 첫 화면](images/ch07/ch07-f01.jpg){ width="820" }
/// caption
그림 7.1 — 카카오 디벨로퍼스 첫 화면
///

화면 오른쪽 위의 로그인 버튼을 누르세요. 카카오 계정 로그인 화면이 나타납니다. 카카오톡을 쓰고 있다면 이미 카카오 계정이 있으므로, 카카오톡에 연결된 이메일과 비밀번호로 로그인하면 됩니다. 개발자 전용 회원가입 절차가 따로 있는 것은 아닙니다.

카카오 계정이 없거나 새로 만들고 싶다면 로그인 화면의 회원가입 링크를 눌러 이메일 인증을 거쳐 계정을 만들 수 있습니다. 몇 분이면 되니 오래 걸릴 일은 아닙니다.

처음 로그인하면 개발자 사이트 이용을 위한 동의 화면이 나올 수 있습니다. 약관을 읽고 동의하면 개발자 계정 등록이 끝납니다. 별도의 심사나 승인 절차는 없습니다.

!!! warning "주의"
    학교나 회사 컴퓨터처럼 여러 사람이 쓰는 PC라면, 실습이 끝난 뒤 꼭 로그아웃하세요. 개발자 계정에는 앞으로 발급받을 키가 들어 있어서, 남이 로그인된 화면을 보는 것만으로 키가 노출될 수 있습니다.

## 7.3 앱 생성하기

로그인이 됐으면 이제 개발자 콘솔로 들어갑니다. 첫 화면 상단 메뉴에서 콘솔을 찾아 누르시거나, 주소창에 아래 주소를 직접 넣으셔도 됩니다.

```
https://developers.kakao.com/console/app
```

전체 앱이라는 제목 아래에 앱 목록이 보일 겁니다. 방금 가입하셨다면 아직 만든 앱이 없으니 목록도 비어 있겠지요.

![개발자 콘솔의 전체 앱 목록과 "앱 생성" 버튼](images/ch07/ch07-f02.png){ width="520" }
/// caption
그림 7.2 — 개발자 콘솔의 전체 앱 목록과 "앱 생성" 버튼
///

화면 오른쪽 위의 앱 생성 버튼을 누르세요. 앱 정보를 입력하는 창이 열립니다. 입력할 것은 많지 않습니다.

- 앱 이름: 이 프로젝트의 이름입니다. 저는 `나만의지도`라고 지었습니다. 여러분은 `맛집지도`, `우리동네지도`처럼 마음에 드는 이름을 자유롭게 쓰세요. 나중에 언제든 바꿀 수 있습니다.
- 회사명(사업자명): 회사가 아니어도 괜찮습니다. 개인 개발자라면 자기 이름이나 닉네임을 적어 두셔도 좋습니다.
- 카테고리: 앱의 분류를 고르는 항목이 있다면 지도·위치와 관련된 것을 고르거나, 마땅한 게 없으면 기타를 골라도 실습에는 지장이 없습니다.

![앱 생성 창에 앱 이름 입력](images/ch07/ch07-f03.jpg){ width="760" }
/// caption
그림 7.3 — 앱 생성 창에 앱 이름 입력
///

입력을 마치고 저장(생성) 버튼을 누르면, 전체 앱 목록에 방금 만든 앱이 한 줄로 나타납니다. 목록에서 앱 이름을 클릭하면 그 앱의 관리 화면으로 들어갑니다. 왼쪽에 앱 설정, 대시보드, 앱, 유료 API, 제품 설정, 통계 메뉴가 세로로 늘어서 있는데, 이 책에서 쓰는 것은 앱 메뉴 하나입니다.

애플리케이션은 여러 개 만들 수 있습니다. 나중에 다른 프로젝트를 시작하면 그 프로젝트용 앱을 새로 만들면 됩니다. 프로젝트마다 앱을 따로 두면 키와 설정이 분리되어 관리하기 좋습니다. 실수로 만든 앱은 앱 관리 화면에서 삭제할 수 있습니다.

!!! tip "팁"
    앱 이름은 나중에 카카오 로그인 같은 기능을 붙일 때 사용자에게 보이기도 합니다. 지금은 본인만 보는 이름이지만, 욕설이나 다른 회사의 상표(예: "카카오맵")는 피하세요. 운영 정책 위반이 될 수 있습니다.

## 7.4 플랫폼 키 3종: 우리가 쓸 건 JavaScript 키

이제 키를 확인해 보겠습니다. 앱 관리 화면의 왼쪽 메뉴에서 앱을 펼치면 그 아래에 일반, 플랫폼 키, 어드민 키, 제품 링크 관리 같은 하위 메뉴를 보실 수 있습니다. 이 중 플랫폼 키를 클릭하세요. "플랫폼별(Android, iOS, 웹)로 API 요청을 인증하는 키를 생성하고 관리"한다는 설명과 함께 키가 세 묶음으로 나뉘어 표시됩니다.

![앱 > 플랫폼 키 화면의 키 3종 (JavaScript 키에 강조 표시)](images/ch07/ch07-f04.jpg){ width="760" }
/// caption
그림 7.4 — 앱 > 플랫폼 키 화면의 키 3종 (JavaScript 키에 강조 표시)
///

키가 세 종류인 이유는 카카오 기능을 어디에서 호출하느냐에 따라 쓰는 키가 달라지기 때문입니다. 표로 비교해 보면 차이가 분명해질 겁니다.

| 키 이름 | 어디서 쓰나 | 우리 책에서는 |
|---|---|---|
| REST API 키 | 서버에서 카카오 API를 부를 때 | 안 씁니다 |
| JavaScript 키 | 웹 브라우저에서 동작하는 웹페이지 | 이것만 씁니다 |
| 네이티브 앱 키 | 안드로이드·iOS 스마트폰 앱 | 안 씁니다 |

우리가 만드는 웹앱은 브라우저에서 동작하므로 JavaScript 키만 씁니다. 처음 앱을 만들면 각 묶음마다 기본 키가 하나씩 자동으로 만들어집니다. JavaScript 키 묶음에는 "Default JS Key" 같은 이름으로 표시됩니다. 키 값은 다음과 같은 32자리 문자열로 나옵니다.

```
0123abcd4567efgh8901ijkl2345mnop
```

위 값은 이 책에서 예로 든 가짜 키입니다. 여러분 화면에서는 각자의 키를 보실 수 있습니다. 키 옆의 복사 버튼을 누르면 클립보드로 복사됩니다. 지금 어딘가에 붙여 넣을 필요는 없습니다. 8장에서 프로젝트를 만들 때 이 화면으로 다시 돌아오므로, JavaScript 키가 어느 화면에 있는지 위치만 기억해 두면 됩니다. 각 묶음의 + JavaScript 키 추가 버튼으로 키를 여러 개 만들 수도 있지만, 이 책에서는 기본 키 하나만 씁니다.

키를 적어 두었다가 잃어버려도 문제되지 않습니다. 필요할 때마다 이 화면에 로그인해서 다시 확인하면 됩니다. 반대로 키가 유출된 것 같으면 키를 새로 만들어 바꾸고 이전 키를 삭제해 무효로 만들 수 있습니다.

!!! warning "주의"
    왼쪽 메뉴를 보면 플랫폼 키 아래에 어드민 키라는 별도 메뉴가 있습니다. 어드민 키는 웹페이지나 GitHub에 올리면 안 됩니다. 앱 설정 전체를 바꿀 수 있는 권한이 있어서, 유출되면 앱 설정을 다른 사람이 변경할 수 있습니다. 이 책에서는 어드민 키를 쓰지 않으므로 건드리지 마세요.

## 7.5 JavaScript SDK 도메인 등록: localhost:5173

키를 확인했지만 한 단계가 더 남았습니다. 이 단계를 빠뜨리는 경우가 많습니다. 9장에서 지도가 뜨지 않고 회색 화면만 보인다면 대부분 여기가 원인입니다.

카카오는 JavaScript 키를 발급하면서 이 키를 어느 주소의 웹사이트에서 쓸 것인지 함께 등록하게 합니다. 미리 등록된 주소에서 온 요청만 처리하겠다는 뜻입니다. 이 주소 목록은 별도의 메뉴가 아니라 JavaScript 키 자체에 붙어 있습니다. 키마다 그 키가 통하는 주소 목록을 따로 가지는 구조입니다.

방금 보던 플랫폼 키 화면에서 JavaScript 키 묶음의 기본 키를 클릭하세요. JavaScript 키 수정 화면이 열립니다. 위에서부터 ① 키 값, ② 키 이름, ③ JavaScript SDK 도메인, ④ 카카오 로그인 리다이렉트 URI 순으로 항목이 늘어서 있습니다. ④는 카카오 로그인에 쓰는 항목이라 이 책에서는 다루지 않고, 우리가 입력할 곳은 ③입니다. 화면의 설명문에는 "JavaScript 키를 사용할 웹사이트 도메인을 등록합니다. 등록한 도메인에서만 JavaScript 키로 Kakao SDK for JavaScript를 사용할 수 있습니다."라고 적혀 있습니다.

![JavaScript 키 수정 화면의 JavaScript SDK 도메인 항목](images/ch07/ch07-f05.jpg){ width="760" }
/// caption
그림 7.5 — JavaScript 키 수정 화면의 JavaScript SDK 도메인 항목
///

JavaScript SDK 도메인 입력란에 다음 주소를 정확히 입력하세요.

```
http://localhost:5173
```

여기서 규칙 하나를 알아 둡시다. 호스트와 포트는 등록한 값과 정확히 일치해야 합니다. 카카오 입장에서 `localhost:5173`과 `localhost:5174`는 서로 다른 주소입니다. 다만 프로토콜은 예외라서, `http`와 `https` 중 하나만 등록해도 양쪽 모두 인정됩니다. 우리는 개발 서버 주소 그대로 `http://localhost:5173`으로 적겠습니다. 입력했으면 옆의 + 버튼으로 목록에 추가하고, 화면 아래의 저장 버튼까지 눌러야 반영됩니다.

![JavaScript SDK 도메인에 http://localhost:5173 이 등록된 모습](images/ch07/ch07-f06.jpg){ width="760" }
/// caption
그림 7.6 — JavaScript SDK 도메인에 http://localhost:5173 이 등록된 모습
///

이 주소가 무엇을 뜻하는지 두 부분으로 나눠 봅시다.

- localhost는 내 컴퓨터 자신을 가리키는 특별한 주소입니다. 인터넷 어딘가의 서버가 아니라, 지금 여러분이 쓰고 계신 이 PC를 뜻합니다.
- 5173은 포트 번호[^2]입니다. 한 컴퓨터 안에서 여러 프로그램이 동시에 통신하기 때문에, 프로그램마다 다른 번호를 나눠 씁니다. 다음 장에서 설치할 개발 도구 Vite가 개발용 서버를 열 때 기본으로 사용하는 번호가 5173입니다.

그러므로 `http://localhost:5173`은 내 컴퓨터에서 Vite로 실행하는 개발 중인 웹페이지를 가리킵니다. 8장에서 프로젝트를 만들고 개발 서버를 켜면 브라우저 주소창에 이 주소가 뜹니다. 그 페이지에서 카카오지도를 불러야 하므로 카카오에 이 주소를 미리 등록해 둡니다.

25장에서 완성된 지도를 GitHub Pages로 공개할 때는 그 공개 주소를 여기에 추가로 등록합니다. 도메인은 여러 개 등록할 수 있습니다.

!!! tip "팁"
    JavaScript SDK 도메인은 기본적으로 최대 10개까지 등록할 수 있고, `*.example.com` 같은 와일드카드 서브도메인도 쓸 수 있습니다. 개발·스테이징·운영 주소를 여럿 추가하다 한도에 막히시면 이 숫자를 떠올려 보세요.

!!! tip "팁"
    나중에 지도가 뜨지 않으면서 브라우저 개발자도구 콘솔에 401이나 403 같은 숫자가 찍힌다면, 가장 먼저 이 JavaScript 키 수정 화면으로 돌아와 SDK 도메인이 정확히 등록됐는지 확인하세요. 대개 포트 번호를 5173이 아닌 5174로 적었거나, 호스트 철자가 틀렸거나, 주소 끝에 슬래시를 하나 더 붙였을 겁니다. 프로토콜은 하나만 등록해도 양쪽에서 인정되므로 원인이 아닙니다. 트러블슈팅 전체 목록은 부록 B에 정리되어 있습니다.

## 7.6 키를 공개하면 안 되는 이유, 그리고 도메인 제한의 의미

여기서 의문이 하나 생깁니다. JavaScript 키는 웹페이지에서 쓰는 키인데, 웹페이지의 코드는 브라우저에서 "페이지 소스 보기"만 눌러도 볼 수 있습니다. 그렇다면 키도 함께 공개되는 것 아닌가 하는 의문입니다.

맞습니다. JavaScript 키는 구조적으로 브라우저에 노출됩니다. 카카오도 이 점을 전제하고 있습니다. 그래서 함께 두는 안전장치가 방금 설정한 도메인 제한입니다.

!!! warning "키 보안: 도메인 제한이 지켜주는 것"
    카카오 서버는 지도 요청을 받을 때 키와 함께 요청이 출발한 웹페이지의 주소도 확인합니다. 키가 맞더라도 출발지 주소가 그 앱에 등록된 도메인 목록에 없으면 요청을 거절합니다.

    누군가 여러분의 JavaScript 키를 복사해서 자기 사이트 `evil-site.com`에 붙여 넣어도, `evil-site.com`은 여러분 앱의 등록 도메인이 아니므로 지도가 뜨지 않습니다. 도메인 제한이 이렇게 동작하기 때문에, 브라우저에 노출되는 키를 쓰면서도 무단 사용을 막을 수 있습니다.

그렇다고 도메인 제한이 있으니 키를 아무 데나 올려도 되는 것은 아닙니다.

먼저 모든 키가 도메인 제한의 보호를 받지는 않습니다. 도메인 제한은 JavaScript 키에만 적용됩니다. REST API 키나 어드민 키는 성격이 달라서 유출되면 실제 피해로 이어집니다. 키마다 위험한지 아닌지를 매번 따지기보다, 키는 공개하지 않는다는 기준을 일관되게 지키시는 편이 낫습니다.

그리고 앞으로 다루게 될 키 중에는 유출되면 곧바로 요금이 청구되는 것도 있습니다. 유료 AI API 키가 여기에 해당합니다. 첫 키부터 코드와 분리해 보관해 두면 그런 키를 다룰 때도 같은 방식으로 처리할 수 있습니다.

그래서 다음 장에서는 키를 코드에 직접 적지 않고 `.env`라는 파일에 넣은 뒤, 그 파일이 GitHub에 올라가지 않게 막는 방법을 배우겠습니다. 본문에서는 앞으로 키가 필요한 자리마다 `여러분의 JS 키`라고 쓰거나 `0123abcd...` 같은 가짜 키로 표기할 테니, 그 자리에 각자의 키를 넣으시면 됩니다.

!!! tip "이렇게 물어보세요"
    > 카카오 JavaScript 키는 어차피 브라우저에 노출된다는데, 그럼 .env에 숨기는 건 무슨 의미가 있어? 초보자한테 설명하듯 알려줘.

    개념이 헷갈릴 때는 Claude Code에게 물어보면 됩니다. 설치와 설정 단계에서도 궁금한 것을 그때그때 물어보는 습관을 들이세요. 위 질문의 답은 "노출 자체를 막는다기보다, 코드와 설정을 분리해서 관리하고 다른 키에도 같은 기준을 적용하기 위해서"입니다. 받은 답과 비교해 보세요.

## 7.7 마무리

이번 장에서는 코드를 쓰지 않고 카카오 개발자 계정을 만들고, 앱을 생성하고, 플랫폼 키 화면에서 JavaScript 키의 위치를 확인했으며, 그 키의 JavaScript SDK 도메인에 `http://localhost:5173`을 등록했습니다.

넘어가기 전에 세 가지를 점검하세요. 전체 앱 목록에 앱이 보이는지, 앱 > 플랫폼 키 화면에서 JavaScript 키를 찾을 수 있는지, JavaScript 키 수정 화면의 SDK 도메인에 `http://localhost:5173`이 오타 없이 등록되어 있는지 확인합니다. 세 가지가 모두 맞으면 다음 장으로 넘어가도 됩니다.

!!! abstract "이 장의 핵심"
    - API 키는 카카오 서버에 등록된 개발자의 요청임을 증명하는 문자열입니다.
    - developers.kakao.com은 카카오 계정만 있으면 바로 가입(로그인)할 수 있습니다.
    - developers.kakao.com/console/app 에서 전체 앱 → + 앱 생성으로 앱을 만들면 앱 > 플랫폼 키에 REST API·JavaScript·네이티브 앱 키가 준비됩니다.
    - 웹앱인 우리 프로젝트가 쓰는 키는 JavaScript 키 하나뿐입니다. 별도 메뉴의 어드민 키는 절대 노출하면 안 됩니다.
    - JavaScript 키를 클릭해 JavaScript SDK 도메인에 `http://localhost:5173`을 등록해야 개발 중인 페이지에서 지도를 부를 수 있습니다.
    - 도메인 제한이 있으므로 JS 키는 등록된 주소에서만 동작합니다. 그래도 키는 공개하지 않고 `.env`에 분리해 둡니다.
