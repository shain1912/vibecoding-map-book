# 0장 이 책에서 만드는 것

!!! note "이 장에서 배우는 것"
    - 이 책에서 완성할 「나만의 지도」 웹앱이 어떤 모습인지 미리 봅니다
    - "바이브코딩"이 무엇이고, 왜 코드를 몰라도 앱을 만들 수 있는지 이해합니다
    - 시작하기 전에 윈도우 PC, 카카오 계정, Claude Pro 구독을 준비합니다

## 0.1 완성된 모습

여러분이 좋아하는 장소만 모아 둔 지도를 하나 갖고 있다고 생각해 보세요. 지난주에 다녀온 국밥집, 노트북을 펴기 좋았던 카페, 언젠가 가 보려고 적어 둔 여행지 같은 곳을 카카오지도 위에 핀으로 꽂아 두고 언제든 다시 열어 볼 수 있다면 꽤 쓸모가 있을 겁니다. 이 책에서 만드는 「나만의 지도」가 그런 앱입니다.

이 장에는 설치도 설정도 코드도 없습니다. 무엇을 만들게 되는지부터 눈으로 보고 시작하겠습니다.

화면은 크게 둘로 나뉩니다. 왼쪽 사이드바에는 검색창과 카테고리 필터 버튼, 그리고 내가 저장해 둔 장소 목록이 위에서 아래로 놓이고, 오른쪽은 지도가 화면을 꽉 채웁니다. 지도에 꽂힌 핀은 카테고리마다 색이 달라서 🍜 맛집은 주황색, ☕ 카페는 갈색, 🏝 여행은 파란색, 💕 데이트는 분홍색으로 보입니다. 색만 훑어도 내가 어느 동네에 카페를 많이 저장해 두었는지 짐작이 가겠지요.

겉모습은 단순합니다. 그렇다고 안에 들어 있는 기능까지 간단한 것은 아닙니다. 하나씩 살펴봅시다.

### 마커를 누르면 말풍선이 뜹니다

지도 위의 핀을 눌러 보세요. 그 장소의 이름과 카테고리, 별점이 담긴 말풍선이 뜹니다. 카카오지도가 기본으로 주는 말풍선을 쓰지 않고 HTML과 CSS로 직접 만들어 붙인 것이라, 아래로 뾰족하게 뻗은 꼬리 모양까지 우리가 그린 것입니다.

### 버튼 하나로 원하는 것만 골라 봅니다

사이드바 위쪽의 필터 버튼을 눌러 보세요. "☕ 카페"를 고르면 지도에 카페만 보이고, "전체"로 돌아오면 다시 전부 나타납니다. 데이트 코스를 짜는 날에는 💕 버튼을, 점심 메뉴를 고르는 날에는 🍜 버튼을 누르면 그때 보고 싶은 장소만 눈에 들어오겠지요.

### 전국 어디든 검색해서 추가합니다

검색창에 "성수동 카페"라고 쳐 보면 카카오가 가진 장소 자료에서 실제 가게를 찾아 목록으로 정리해 줍니다. 결과를 누르면 지도가 그곳으로 옮겨 가고, ＋ 버튼을 누르면 내 지도에 저장됩니다. 검색으로 찾을 수 없는 곳이라면 지도의 빈 자리를 직접 눌러 추가하면 됩니다. "여기가 우리가 처음 만난 곳" 같은 장소는 아마 이렇게 넣게 될 겁니다.

### 별점과 메모까지, 나만의 기록이 쌓입니다

저장해 둔 장소를 누르면 상세 패널이 열립니다. 여기서 별점을 1점부터 5점까지 매기고 "웨이팅 김, 평일 오픈런 추천" 같은 메모를 적어 둘 수 있습니다. 다시 갈 일이 없어진 곳은 삭제 버튼으로 정리하면 되겠지요. 이렇게 쌓인 기록은 브라우저에 저장되어 내일 다시 열어도 그대로 있고, 파일로 내보내 두면 다른 컴퓨터로 옮길 수도 있습니다.

![별점과 메모를 편집하는 상세 패널](images/ch00/ch00-f05.jpg){ width="760" }

그림 0.5 — 별점과 메모를 편집하는 상세 패널

여기까지가 핵심 기능이고, 뒷부분에서는 기능을 더 붙입니다. 🧭 버튼을 누르면 내 현재 위치가 파란 점으로 표시되고, 🔗 버튼을 누르면 지금 보고 있는 지도 위치가 링크로 복사되니 친구에게 "여기서 보자"라고 보낼 수 있겠지요. 장소가 100개로 늘어나면 핀이 서로 겹쳐 보기 어려워질 텐데, 가까운 것끼리 자동으로 묶어 주는 기능도 함께 만듭니다. 스마트폰 화면에 맞추는 일까지 마치면 마지막으로 인터넷에 올립니다. 그러면 주소만 알려 줘도 누구나 열어 볼 수 있습니다.

!!! tip "팁"
    마커, 커스텀 오버레이, 필터, localStorage, 클러스터러 같은 이름을 지금 외울 필요는 없습니다. 기능마다 한 장씩 배정해 두었으니 그 장에서 다시 만나게 됩니다. 지금은 무엇을 만드는지만 보고 넘어가도 좋습니다.

## 0.2 그런데, 코드는 누가 짜나요?

"이걸 내가 만든다고요? 저는 코딩을 못하는데요."라는 생각이 드셨을지도 모릅니다.

이 책에서 코드를 쓰는 쪽은 AI입니다. 여러분은 무엇을 만들지 한국어로 알려 주면 됩니다. 이런 식으로 요청하게 됩니다.

!!! tip "이렇게 물어보세요"
    > 지도를 화면 전체에 꽉 차게 띄워줘. 카카오지도 JS SDK를 쓰고, 키는 .env에서 읽어줘.

이렇게 요청하면 Claude Code라는 AI 도구가 필요한 파일을 만들고 코드를 써서 실행까지 해 줍니다. 결과는 브라우저에서 확인하면 되고, 마음에 들지 않으면 다시 말로 고치면 됩니다. "말풍선이 너무 작아. 글자를 키우고 그림자를 넣어줘"처럼 요청을 이어 가다 보면 앱이 조금씩 모양을 갖춰 갑니다.

이런 방식의 개발을 바이브코딩(vibe coding)[^1]이라고 부릅니다. 코드를 한 줄씩 직접 치는 대신 만들고 싶은 것을 말로 설명하고, AI가 써 온 코드를 읽으며 다듬는 방식입니다. 그래서 이 책에는 코드를 복사해 붙여 넣는 실습이 없습니다. 대신 실습마다 "이렇게 시키세요" 프롬프트 박스가 나옵니다. 그 프롬프트를 참고해 AI에게 일을 시키고, 돌아온 코드를 책과 함께 한 줄씩 읽어 보시면 됩니다. 바이브코딩이 왜 지금 가능해졌는지는 1장에서 다루니, 여기서는 대략의 흐름만 보아도 좋습니다.

![바이브코딩의 흐름: 말하기 → AI가 코드 작성 → 함께 읽기 → 확인하기](images/ch00/ch00-f06.jpg){ width="760" }
/// caption
그림 0.6 — 바이브코딩의 흐름: 말하기 → AI가 코드 작성 → 함께 읽기 → 확인하기
///

그렇다고 코드를 아예 몰라도 되는 것은 아닙니다. 치는 일은 AI가 맡지만 읽는 일까지 넘길 수는 없습니다. 코드가 무슨 일을 하는지 대강이라도 알아야 어디가 잘못됐는지 짚을 수 있고, 원하는 쪽으로 고쳐 달라고 말할 수도 있기 때문입니다. 그래서 이 책의 코드 해설은 직접 쓸 수 있는 수준까지 가지 않습니다. 무엇을 하는 코드인지 알아보는 정도면 충분합니다. 외우지 않으셔도 됩니다.

이 책의 앱도 책이 안내하는 방식 그대로 저자가 Claude Code에게 시켜서 만들었습니다. 실린 코드 역시 AI가 쓰고 사람이 검토한 것을 그대로 옮겼습니다.

!!! warning "주의"
    바이브코딩이 아무것도 몰라도 된다는 뜻은 아닙니다. AI는 가끔 틀립니다. 엉뚱한 코드를 만들기도 하고, 시킨 것과 다른 일을 해 놓기도 합니다. 그래서 이 책에서는 작게 시키고, 결과를 확인하고, 잘못되면 되돌리는 습관을 처음부터 함께 익힙니다. 이 습관이 없으면 AI가 틀렸을 때 어디서부터 틀어졌는지 찾기 어려울 겁니다. 1장에서 자세히 다룹니다.

## 0.3 준비물 세 가지

준비물은 윈도우 PC, 카카오 계정, Claude Pro 구독입니다.

먼저 윈도우 PC가 필요합니다. 이 책의 화면 캡처와 설치 과정은 윈도우 10과 11을 기준으로 안내합니다. 사양이 높아야 하는 것은 아닙니다. 인터넷이 연결되고 크롬 브라우저가 돌아가면 충분합니다. 맥에서도 따라올 수 있지만 설치 화면이 책과 다르게 보일 겁니다.

다음은 카카오 계정입니다. 카카오톡을 쓰고 계신다면 이미 가지고 계실 겁니다. 이 책에서 띄우는 지도는 카카오가 제공하는 카카오지도 API[^2]를 쓰는데, 이 API를 쓰려면 카카오 개발자 사이트에서 키를 발급받아야 합니다. 발급은 무료이고, 이 책에서 쓰는 정도로는 요금이 나오지 않습니다. 발급 과정은 7장에서 화면을 따라가며 안내하겠습니다.

마지막은 Claude Pro 구독입니다. 코드를 대신 써 주는 Claude Code를 쓰려면 이 구독이 필요합니다. 월 20달러 수준이라 부담이 없지는 않겠지만, 이 책에서 가장 많이 쓰는 도구이니 한 달만이라도 구독해 따라오시기를 권합니다. 실습을 처음부터 끝까지 마치는 데는 한 달이면 넉넉한 편입니다. 구독이 어렵다면 opencode나 codex 같은 무료 도구로도 따라올 수 있습니다. 이 도구들은 4장에서 소개하겠습니다.

!!! tip "팁"
    당장 구독이 부담스럽다면 무료 도구를 써도 좋습니다. 4장에서 opencode처럼 무료로 쓸 수 있는 것들을 박스로 소개합니다. 프롬프트로 시키고 결과를 확인하는 흐름은 어느 도구나 비슷하니, 책의 내용은 그대로 따라올 수 있을 겁니다.

프로그래밍 경험은 없어도 됩니다. 변수가 무엇인지, 함수가 무엇인지 몰라도 시작할 수 있습니다. 필요한 개념은 필요해지는 순간에 필요한 만큼만 설명하겠습니다.

## 0.4 책의 구성: 5부 26장

이 책은 5부, 26개 장으로 구성되어 있습니다.

![이 책의 로드맵: 준비운동부터 세상에 공개하기까지](images/ch00/ch00-f07.png){ width="760" }
/// caption
그림 0.7 — 이 책의 로드맵: 준비운동부터 세상에 공개하기까지
///

1부 「바이브코딩 준비운동」(1~6장)에서는 도구를 갖춥니다. 바이브코딩이 왜 지금 배울 만한 방식인지 이야기한 뒤, Node.js, Git, Claude Code, GitHub CLI, 그리고 여러 AI 에이전트를 함께 다루는 Orca까지 저자가 매일 쓰는 도구를 순서대로 설치합니다. 설치 과정이 지루하게 느껴질 수도 있겠지만, 여기서 갖춘 도구를 책 끝까지 쓰게 됩니다.

2부 「카카오 지도 첫걸음」(7~10장)에서 지도를 띄웁니다. 카카오 개발자 계정을 만들어 API 키를 발급받고 Vite로 프로젝트를 시작하면, 브라우저 화면 가득 지도가 뜹니다. 이어서 지도를 움직이고 확대하는 기본 조작까지 익힙니다. 말로 요청해서 띄운 첫 지도를 9장에서 보시게 될 겁니다.

3부 「나만의 장소 지도 만들기」(11~19장)가 이 책에서 가장 깁니다. 마커를 찍고, 장소 데이터를 설계하고, 말풍선을 달고, 필터와 검색을 붙이고, 클릭으로 장소를 추가하고, 새로고침해도 사라지지 않게 저장하고, 목록과 상세 패널로 관리합니다. 3부를 마치면 그림 0.1의 화면이 여러분의 브라우저 안에 들어와 있을 겁니다.

4부 「한 단계 더」(20~23장)에서는 기능을 더 붙입니다. 내 위치 표시, 링크로 지도 공유, 마커가 100개여도 느려지지 않게 하는 클러스터러, 스마트폰 대응을 차례로 다룹니다.

5부 「세상에 공개하기」(24~26장)에서는 완성한 앱을 GitHub에 올리고 GitHub Pages로 배포해 인터넷 주소를 얻습니다. 여기까지 하면 친구에게 링크를 보내 직접 열어 보게 할 수 있겠지요.

부록도 두 개 있습니다. 부록 A에는 책에 나온 프롬프트를 상황별로 모아 두었습니다. 부록 B에는 "지도가 회색으로 나와요"처럼 자주 겪는 문제와 해결 방법을 표로 정리했습니다. 진행이 막히면 부록을 먼저 확인하세요.

!!! tip "팁"
    책은 순서대로 읽도록 구성했지만, 이미 갖춘 도구가 있다면 해당 장은 건너뛰어도 됩니다. 예를 들어 Node.js와 Git이 이미 설치되어 있다면 2~3장은 버전 확인만 하고 넘어가면 됩니다. 다만 7장(카카오 키 발급)과 8장(프로젝트 시작)은 건너뛸 수 없습니다.

## 0.5 마무리

!!! abstract "이 장의 핵심"
    - 카카오지도를 바탕으로 「나만의 지도」 웹앱을 완성해 인터넷에 배포합니다.
    - 완성 앱에는 마커·말풍선·카테고리 필터·검색·장소 추가·저장·상세 패널·위치·공유·클러스터·모바일 대응이 들어갑니다.
    - 코드는 Claude Code가 작성하고, 사용자는 말로 시킨 뒤 결과를 읽고 확인합니다. 이 방식을 바이브코딩이라고 부릅니다.
    - 준비물은 윈도우 PC, 카카오 계정, Claude Pro(또는 무료 대안 에이전트) 세 가지이며 프로그래밍 경험은 필요 없습니다.
    - 책은 5부 26장 구성입니다: 도구 준비 → 첫 지도 → 나만의 지도 → 업그레이드 → 세상에 공개.

> 다음 장으로. 1장에서는 이 책의 개발 방식인 바이브코딩을 자세히 다룹니다. 코드를 몰라도 앱을 만들 수 있게 된 이유를 살펴보고, 저자가 Claude Code와 Orca를 함께 쓰는 방식을 봅니다. AI에게 일을 시킬 때 지켜야 할 작게 시키기, 확인하기, 되돌리기도 여기서 배웁니다.

[^1]: 바이브코딩(vibe coding): AI에게 자연어로 요구사항을 말하고 AI가 작성한 코드로 소프트웨어를 만드는 개발 방식. 2025년 초 AI 연구자 안드레이 카파시(Andrej Karpathy)가 소셜 미디어에서 처음 사용한 표현으로 널리 알려졌습니다.
[^2]: API(Application Programming Interface): 다른 회사의 서비스(여기서는 카카오지도)를 내 프로그램에서 가져다 쓸 수 있게 열어 둔 창구. 카카오지도 API를 쓰면 카카오가 만든 지도를 우리 웹앱 안에 띄울 수 있습니다.
