# 1장 왜 바이브코딩인가

!!! note "이 장에서 배우는 것"
    - 바이브코딩이 무엇이고, 왜 지금 이 방식으로 배우면 유리한지 알아봅니다.
    - 저자가 실제로 쓰는 작업 흐름을 미리 살펴봅니다. Claude Code, Orca, Git, GitHub CLI를 함께 씁니다.
    - "이해하려 노력하되 외우지 않는다"는 이 책의 학습 철학을 익힙니다.
    - AI 에이전트에게 일을 시킬 때 지킬 것을 배웁니다. 작게 시키고, 확인하고, 잘못되면 되돌리는 세 가지면 충분할 겁니다.
    - 다음 장부터 설치할 도구 5종이 각각 어떤 역할을 하는지 정리합니다.

## 1.1 코드를 몰라도 만드는 시대

프로그래밍을 배우다 그만둔 이야기는 대체로 비슷합니다. "나만의 맛집 지도를 웹으로 만들어 보고 싶다"는 생각으로 검색을 시작하면, HTML을 배워야 하고 CSS를 배워야 하고 자바스크립트를 배워야 하고 API가 무엇인지도 알아야 한다는 글을 만납니다. 그러다 브라우저 탭을 닫았을 수도 있습니다. 만들고 싶은 것은 분명한데 배워야 할 것이 너무 많으니, 시작을 미루는 것도 이상한 일은 아닙니다.

바이브코딩(vibe coding)에서는 배우는 순서가 다릅니다. 문법을 모두 배운 뒤에 만드는 것이 아니라, 만들고 싶은 것을 말로 설명하면 AI가 코드를 대신 작성합니다. 여러분은 결과를 확인하고, 마음에 들지 않으면 다시 말로 고쳐 달라고 요청하면 됩니다. "지도를 화면에 꽉 차게 띄워줘", "마커를 클릭하면 말풍선이 뜨게 해줘"처럼 한국어 문장으로 요청하면 AI 코딩 도구가 실제로 동작하는 코드를 만들어 줍니다.

이 말은 2025년 초 AI 연구자 안드레이 카파시(Andrej Karpathy)[^1]가 "코드의 존재조차 잊고 분위기(vibe)에 몸을 맡긴 채 개발한다"라고 표현한 뒤로 널리 퍼졌습니다. 처음에는 반쯤 농담이었을 것입니다. 지금은 많은 개발자와 비개발자가 이 방식으로 소프트웨어를 만듭니다. 이 책의 원고와 예제 앱도 상당 부분 바이브코딩으로 만들었습니다.

![전통적 코딩과 바이브코딩의 순서 비교](images/ch01/ch01-f01.png){ width="760" }

///

여기서 흔한 오해 하나를 짚고 넘어가겠습니다. 바이브코딩에서 배우는 순서와 방법은 다를 뿐입니다. 예전에는 문법을 모두 익힌 뒤에야 무언가를 만들 수 있었지만, 이제는 만들면서 필요한 만큼 이해하면 됩니다. 다만 AI가 만든 코드가 무엇을 하는지, 화면에 나타나는 경고가 무슨 뜻인지는 읽을 수 있어야 합니다. 그래야 결과가 이상할 때 어디를 고쳐 달라고 요청할지 알 수 있습니다. 이 책에서는 기능을 만들면서 그 읽는 법도 함께 익힙니다.

이 책에는 코드를 복사하여 붙여 넣는 실습이 없습니다. 긴 코드를 책에서 보고 한 글자씩 따라 적는 실습도 포함하지 않았습니다. 실습은 이 순서로 진행합니다. 첫째, AI에게 보낼 프롬프트를 먼저 제시합니다. 둘째, AI가 만들어 온 코드를 함께 읽습니다. 셋째, 그 코드가 왜 그렇게 동작하는지 설명합니다. 넷째, 브라우저에서 결과를 확인합니다. 코드를 입력하는 일은 AI에게 맡깁니다. 결과가 올바른지는 여러분이 판단합니다.

!!! tip "팁"
바이브코딩이라는 이름 때문에 대충 감으로 진행한다고 오해하기 쉽습니다. 그러나 잘하는 사람일수록 요청을 명확하게 작성하고 결과를 꼼꼼히 확인합니다. 분위기에 맡기는 것은 타이핑이며, 판단까지 맡긴다는 뜻은 아닙니다.

## 1.2 저자의 실제 작업 흐름

시중의 많은 입문서는 교육용으로 정제된 방법을 가르칩니다. 이 책은 다릅니다. 저자가 실제 프로젝트에서 매일 사용하는 작업 흐름을 거의 그대로 따릅니다. 사용하는 도구는 네 가지로 나눌 수 있습니다.

먼저 Claude Code를 사용합니다. 터미널에서 실행하는 AI 코딩 에이전트이며, 이 책에서 가장 많이 다루는 도구입니다. 코드 조각을 제시하는 수준을 넘어섭니다. 프로젝트 폴더 안에서 파일을 만들고 수정하며, 명령어를 실행하고, 에러를 읽어 스스로 수정하기도 합니다. "검색 기능을 붙여줘"라고 요청하면 어떤 파일을 어떻게 변경할지 계획을 세운 뒤 실제로 변경합니다.

Git은 코드의 변경 이력을 기록하고 이전 시점으로 되돌리는 기능을 제공합니다. AI가 코드를 대신 작성하는 작업에서 이 도구는 특히 중요합니다. AI가 수정한 결과가 적절하지 않으면 마지막으로 정상 동작하던 시점으로 돌아가야 합니다. 이력이 없으면 되돌릴 수 없습니다. 이 내용은 3장에서 자세히 다루겠습니다.

GitHub CLI는 작성한 코드를 인터넷 저장소인 GitHub에 올리고 관리하는 도구입니다. 터미널에서 gh 명령으로 실행합니다. 브라우저에서 버튼을 찾아 클릭하는 대신 명령어 한 줄로 저장소를 만들 수 있으므로 AI 에이전트에게 명령하기에도 적합합니다.

Orca는 여러 AI 에이전트를 한 화면에 표시하고 함께 관리하는 데스크톱 앱입니다. 한 에이전트에게 기능 A를 수행하도록 하고, 대기 시간 동안 다른 에이전트에게 기능 B를 요청할 수 있습니다. 초기에는 없어도 되지만, 익숙해지면 대기 시간을 줄일 수 있습니다.

![저자의 바이브코딩 워크플로 한눈에 보기](images/ch01/ch01-f02.png){ width="760" }

네 도구를 함께 사용하는 하루는 다음과 같이 진행합니다. 아침에 Orca를 실행하고 Claude Code에게 "어제 만든 지도에 카테고리 필터를 추가해줘"라고 요청합니다. 에이전트가 코드를 수정하는 동안 다른 일을 진행한 뒤 돌아와 브라우저로 결과를 확인합니다. 결과가 적절하면 Git으로 커밋하고 GitHub에 올립니다. 적절하지 않으면 "버튼 색이 너무 강하도록 변경해줘"라고 다시 요청하거나, 이전 상태로 복원한 뒤 요청 내용을 수정할 수 있습니다. 코드를 직접 입력하지 않는 날도 많지만, 그렇다고 사람의 역할이 사라지는 것은 아닙니다. 무엇을 만들지 결정하고 결과의 정확성을 판단하는 일은 여전히 사람이 수행합니다.

이 책의 1부(2~6장)에서는 이 작업 흐름을 여러분의 윈도우 PC에 그대로 설정합니다.

## 1.3 이해하려 노력하되, 외우지 않는다

AI가 코드를 모두 작성해 준다면 우리는 무엇을 배워야 할까요? 이 책에서는 이해하려 노력하되 외우지는 않는 방향으로 진행합니다.

먼저 외우지 않아도 되는 것을 말씀드리겠습니다. 함수 이름의 정확한 철자, 괄호와 세미콜론의 위치, API 옵션의 나열 순서가 그렇습니다. 예전에는 프로그래밍을 배울 때 이 부분에 가장 많은 시간을 들였지만, 이제는 AI가 사람보다 훨씬 정확하게 기억합니다. 카카오지도에서 마커를 만드는 클래스 이름이 Marker인지 MapMarker인지 헷갈려도 괜찮습니다. AI에게 물어보면 됩니다.

반대로 구조와 흐름은 이해해야 합니다. 예를 들어 "내 앱은 장소 데이터를 어디에 저장하고 있지?", "지도에 마커가 표시되기까지 코드가 어떤 순서로 실행되지?", "API 키는 왜 코드에 직접 작성하면 안 되지?"와 같은 질문에 대략적으로 답할 수 있으면 AI가 작성한 코드가 부적절할 때 알아챌 수 있습니다. 무엇을 고쳐 달라고 요청할지도 정확히 말할 수 있습니다.

여러분은 무엇을 만들지 결정하고 결과가 올바른지 확인합니다. 코드를 직접 작성할 줄은 몰라도 되지만, 파일이 몇 개이고 데이터가 어디에 저장되며 어떤 순서로 실행되는지는 읽을 수 있어야 합니다. 그래야 AI가 요청한 기능을 빠뜨리거나 엉뚱하게 구현했을 때 알아챌 수 있습니다. 그래서 이 책에는 코드 해설을 적절히 포함하였습니다. 코드는 전체 구조를 파악하며 읽습니다.

그래서 이 책의 실습에는 코드에 대한 설명을 요청하는 프롬프트가 자주 등장합니다. AI에게 작업을 요청한 뒤 다음과 같이 추가로 질문하는 습관을 들이면 좋습니다.

!!! tip "이렇게 물어보세요"
    > 방금 만든 코드를 프로그래밍을 처음 배우는 사람에게 설명하듯이, 위에서 아래로 실행 순서를 따라가며 설명해줘. 처음 나오는 용어는 짧게 풀어서 알려줘.

AI는 코드를 작성할 뿐 아니라 그 코드를 설명하기도 합니다. 같은 질문을 반복해도 괜찮습니다. 모르는 내용을 모른다고 편하게 말할 수 있는 점은 혼자 학습할 때 특히 도움이 될 것입니다.

## 1.4 에이전트에게 일 시키는 세 가지 원칙: 작게, 확인, 되돌리기

AI 에이전트는 유능하지만 실수도 합니다. 틀린 코드를 자신 있게 제시하거나, 요청하지 않은 부분까지 변경하기도 합니다. 그래서 에이전트를 활용할 때 몇 가지 요령을 알아 두면 효과적입니다. 이 책 전체에서 준수할 세 가지 원칙을 정리하였습니다.

요청은 작게 분할합니다. "맛집 지도 앱을 전부 만들어줘"라고 요청하면 AI가 결과를 제시하지만, 한 번에 너무 많은 코드가 작성되어 어디에서 문제가 발생했는지 파악하기 어렵습니다. 대신 "지도만 표시해줘", "마커 하나만 추가해줘", "마커를 클릭하면 말풍선이 나타나게 해줘"처럼 단계별로 요청하면 즉시 결과를 확인할 수 있고, 문제가 발생한 경우 원인을 찾을 범위도 좁아집니다. 이 책의 26개 장도 같은 순서로 구성하였습니다.

작업 결과를 확인합니다. AI가 완료했다고 알려주어도 실제로 동작하는 것은 아닙니다. 요청 하나를 처리할 때마다 브라우저를 새로고침하여 화면을 확인하고, 개발자 도구의 콘솔에 오류 메시지가 없는지 검토합니다. 확인 절차를 생략한 채 다음 요청을 진행하면, 이후 문제가 발생하였을 때 어느 시점에서 잘못되었는지 파악하기 어렵습니다. 요청마다 확인하는 습관을 유지합니다.

결과가 예상과 다르면 되돌립니다. 새로운 수정 요청을 추가하기보다, 이전 상태로 복원한 뒤 요청 내용을 다시 작성하는 것이 더 빠를 수 있습니다. Git을 사용하여 정상 동작하는 시점을 저장해 두면 명령어 한 줄로 이전 상태로 돌아갈 수 있습니다. 되돌릴 수 있는 환경에서는 다양한 시도를 자유롭게 테스트할 수 있습니다.

!!! warning "주의"
AI가 작성한 코드를 검토 없이 누적하여 적용하면 문제가 발생하기 쉽습니다. 특히 "알아서 모두 구현해줘"와 같이 범위가 넓은 요청은 반드시 동작을 검증하고, 정상적으로 작동하는 시점을 Git에 커밋하여 저장해 둡니다. 이전 상태가 저장되지 않으면 문제 발생 시 복원할 지점이 사라집니다.

이 세 가지 원칙은 4장에서 설명할 프롬프트의 네 가지 요소와 함께 이 책 전체에서 지속적으로 활용합니다. 프롬프트의 네 가지 요소는 맥락, 목표, 제약 조건, 출력 형식을 의미합니다. 사용하는 도구는 변경될 수 있지만, AI 에이전트에 작업을 요청하는 방식은 어떤 도구를 사용하더라도 크게 달라지지 않을 것입니다.

첫째, Node.js(2장). 자바스크립트를 브라우저 외부에서 실행하는 환경입니다. 이 책에서 사용할 개발 서버 Vite와 Claude Code가 모두 Node.js 기반으로 동작하므로 가장 먼저 설치합니다. 다른 도구를 사용하려면 Node.js가 필수적으로 필요합니다.

둘째, Git(3장). 앞에서 설명한 상태 복원용 도구입니다. 프로젝트의 상태를 시점별로 저장(커밋)하여 언제든 해당 시점으로 복원할 수 있습니다. 지도 기능을 구현하기 전에 먼저 설치합니다.

셋째, Claude Code(4장). 이 책에서 가장 많이 활용할 AI 코딩 에이전트입니다. 터미널에서 실행하며, 한국어로 요청하면 파일을 생성하고 수정하며 실행까지 수행합니다. Claude Pro 유료 구독이 필요하지만, 4장에서 무료로 사용할 수 있는 대안 도구도 함께 제시합니다.

넷째, GitHub CLI(5장). 작성한 코드를 인터넷 저장소인 GitHub에 업로드하고 관리하는 명령줄 도구입니다. 25장에서 지도 앱을 GitHub Pages로 공개할 때 사용합니다.

다섯째, Orca(6장). 여러 AI 에이전트를 동시에 관리할 수 있는 데스크톱 앱입니다. 이 도구만은 설치하지 않아도 책의 내용을 따라가는 데 문제가 없습니다. 다만 설치하면 실제 개발 환경에서의 작업 방식을 그대로 경험할 수 있습니다.

도구는 아니지만 추가로 준비할 것이 있습니다. 카카오지도 API 키(7장)입니다. 카카오에서 제공하는 지도 데이터를 앱에서 활용하려면 이 인증 키가 필요하며, 무료로 발급받을 수 있습니다. 다섯 가지 도구를 설치하고 API 키를 발급받으면 8장부터 지도를 구현하기 시작합니다.

!!! tip "팁"
설치 단계(2~6장)에서 도구의 버전이 책의 화면과 약간 달라도 괜찮습니다. 도구의 버전은 변경될 수 있지만 설치 순서는 동일합니다. 화면 구성이 많이 다르면 해당 화면을 캡처하여 AI에게 "이 화면에서 어떤 항목을 선택해야 하나요?"라고 질문하면 됩니다.

!!! abstract "이 장의 핵심"
    - 바이브코딩은 말로 요청하고 AI가 코드를 쓰는 개발 방식입니다. 타이핑은 AI가 맡지만, 판단까지 넘길 수는 없습니다.
