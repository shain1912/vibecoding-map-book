[1] 1장에서는 코드는 AI에게 작성하게 하고 그 결과는 사람이 판단하는 원칙에 대해 설명하였습니다. 이 방식으로 작업하려면 먼저 개발 환경을 갖추어야 합니다. 이번 장부터 6장까지 필요한 도구를 차례로 설치할 것이며, 가장 먼저 Node.js를 설치하겠습니다.
[2] Node.js는 웹 브라우저 외부에서 자바스크립트를 실행하는 프로그램입니다.
[3] 과거 자바스크립트는 웹 페이지 내에서만 사용할 수 있었으며, 크롬이나 엣지와 같은 브라우저가 연 페이지에서만 동작하였습니다. 2009년 Node.js가 출시되면서 이러한 제약이 사라졌습니다. 이제 브라우저 없이 컴퓨터의 터미널에서도 자바스크립트를 직접 실행할 수 있게 되었습니다. 이후로는 자바스크립트를 활용하여 서버, 개발 도구, 명령줄 프로그램 등 다양한 소프트웨어를 제작하기 시작하였습니다.
[4] 지도 웹앱을 개발하는 데에 왜 브라우저 외부에서 자바스크립트를 실행하는 프로그램이 필요한지 의아할 수 있습니다. 이 책에서 사용하는 도구들이 Node.js 환경에서 동작하기 때문입니다.
[5] 8장에서 다룰 Vite도 그 중 하나입니다. Vite는 지도 앱 개발 중 개발 서버를 실행하고, 코드를 수정할 때마다 브라우저 화면을 자동으로 갱신해 줍니다. Vite 자체가 Node.js로 제작되었으므로, Node.js가 없으면 정상적으로 작동하지 않습니다.
[6] 4장에서 설치할 Claude Code도 마찬가지입니다. 코드를 작성해 주는 이 AI 에이전트 역시 Node.js로 개발된 명령줄 프로그램이며, 설치 시 Node.js에 포함되는 npm을 사용합니다.
[7] 완성된 지도 앱을 이용하는 사용자에게는 Node.js가 보이지 않습니다. 사용자는 브라우저에 표시되는 지도만 보게 될 뿐입니다. 그렇다고 하여 Node.js가 불필요한 것은 아닙니다. 앱을 개발하는 전 과정에서 Vite와 Claude Code가 계속해서 Node.js 위에서 구동되기 때문입니다.
[8] 이 책에서 여러분이 Node.js로 직접 프로그램을 작성할 일은 없을 것입니다. 관련 작업은 Vite와 Claude Code가 대신 처리합니다. 설치에는 대략 10분 정도면 충분합니다.
[9] Node.js에서 【2】는 JavaScript를 줄여 표기한 이름입니다. 앞으로 파일 이름 끝에 붙는 【1】 확장자를 자주 접하게 될 것인데, 이는 모두 자바스크립트 파일을 의미합니다.

[19] 해당 프로그램을 찾을 수 없다는 의미이므로, 이제부터 설치를 진행하면 됩니다.

[21] 그림 2.1 — 설치 전 【9】 실행 결과
[22] 이제 공식 홈페이지에서 설치 파일을 내려받겠습니다. 웹 브라우저를 실행한 뒤 주소창에 안내된 주소를 입력하십시오.
[23] 첫 화면에 큰 크기의 다운로드 버튼이 보입니다. 버튼에는 버전 번호와 함께 LTS라는 문구가 표시되어 있을 것입니다.
[24] 여기서 LTS의 의미에 대해 알아보겠습니다. LTS는 Long Term Support의 약자로, 장기 지원 버전을 의미합니다. Node.js는 새로운 기능을 우선적으로 적용하는 Current 버전과, 안정성이 검증되어 장기간 지원하는 LTS 버전으로 구분됩니다. Current 버전에는 아직 검증되지 않은 문제점이 포함되어 있을 수 있습니다. LTS 버전은 다수의 사용자가 테스트하고 문제점을 수정한 뒤 공개되는 버전으로, 최신 기능보다 안정성이 중요한 경우 LTS 버전을 선택하는 것이 유리합니다. 참고로 Node.js는 짝수 번호의 버전만 LTS로 지정되며, 20, 22, 24와 같은 버전은 시간이 지나면 LTS로 승격됩니다. 반면 21, 23과 같은 홀수 번호 버전은 실험용으로 제작되어 지원 기간이 짧습니다. 이 책의 집필 시점 기준 LTS 버전은 v22 계열이지만, 실제 화면에는 더 높은 버전 번호가 표시될 수 있습니다. 버전 번호와 상관없이 LTS라고 표시된 버전을 내려받으면 됩니다.
[25] 다운로드 페이지에서 운영체제는 Windows로, 설치 방식은 Installer(.msi)로 선택되었는지 확인한 뒤 초록색 다운로드 버튼을 누르십시오. 대부분의 경우 윈도우용 설치 파일이 기본으로 선택되어 있을 것입니다. 다운로드가 완료되면 다운로드 폴더에 【10】와 같은 이름의 파일이 생성됩니다.

[45] 이제 컴퓨터에서 자바스크립트를 실행할 준비가 되었습니다. 간단한 코드 한 줄로 정상 동작 여부를 확인하여 보겠습니다. 터미널에 아래의 명령어를 입력하십시오.
[46] 실행 결과로 【28】가 표시됩니다. 【29】 옵션은 따옴표 안에 작성한 자바스크립트 코드를 즉시 실행하라는 의미이며, 【30】는 실행 결과를 화면에 출력하라는 명령어입니다. 이로써 웹 브라우저 없이도 자바스크립트를 실행할 수 있음을 확인하였습니다. Node.js는 바로 이러한 역할을 수행하는 프로그램입니다. 이 명령어의 동작 원리를 완전히 이해하지 못하더라도 이후 학습에 지장은 없으니 걱정하지 마십시오. 터미널 환경에서 자바스크립트가 정상적으로 실행된다는 점만 확인하면 충분합니다.
[47] 터미널을 새로 실행하였음에도 불구하고 계속해서 【31】 오류가 발생하는 경우, 대부분 시스템 경로인 PATH에 등록되지 않은 것이 원인입니다. 이 문제는 비교적 자주 발생하므로 원인과 해결 방법을 자세히 설명하겠습니다.
[48] 터미널에 【32】라고 입력하면 윈도우는 컴퓨터 전체를 검색하는 것이 아니라, PATH 환경 변수에 등록된 폴더들을 순서대로 검색하여 【33】 프로그램을 찾습니다. 만약 PATH 목록에 【34】 경로가 포함되어 있다면, 어떤 폴더에서든 【35】 명령어만 입력하여도 프로그램이 실행되지만, 등록되지 않은 경우 프로그램 파일이 존재하더라도 찾을 수 없다는 오류가 발생합니다.
[49] 따라서 이 오류는 프로그램 자체가 설치되지 않아서 발생하는 것이 아니라, 프로그램이 설치된 폴더 경로가 PATH 목록에 등록되지 않아서 발생하는 것입니다. 해당 경로를 PATH에 직접 등록하면 문제가 해결됩니다.
[50] 설치 마법사의 Add to PATH 옵션이 자동으로 이 과정을 처리하여 주지만, 간혹 정상적으로 등록되지 않는 경우가 있습니다. 아래의 순서대로 점검하고 조치하여 보십시오.
[51] 1단계. 컴퓨터 재시작. 가장 간단한 해결 방법이지만 의외로 많은 경우 문제가 해결됩니다. 컴퓨터를 재시작하면 시스템이 변경된 PATH 정보를 다시 읽어오게 됩니다. 재시작 이후 새 터미널에서 【36】 명령어를 다시 입력하여 보십시오.
[52] 2단계. 설치 파일 존재 여부 확인. 파일 탐색기를 열어 【37】 폴더에 실제로 파일이 존재하는지 확인하십시오. 해당 폴더에 【38】 파일이 보인다면 설치 자체는 정상적으로 완료된 것이며, PATH에만 경로가 등록되지 않은 상태입니다. 만약 해당 폴더 자체가 존재하지 않는다면 설치 과정에 문제가 발생한 것이므로, 2.3절의 설치 과정을 다시 진행하시기 바랍니다.
[53] 3단계. PATH에 경로 직접 등록. 설치 파일은 존재하지만 명령어가 인식되지 않는 경우, PATH 환경 변수에 직접 경로를 등록하면 해결됩니다.
[54] 그림 2.8 — 환경 변수 편집 창에서 Path에 nodejs 경로 확인
[55] 4단계. 재설치. 위의 모든 조치를 취하여도 문제가 해결되지 않는 경우, 제어판(설정 → 앱 → 설치된 앱)에서 Node.js를 제거한 뒤 2.3절의 내용부터 다시 설치하시기 바랍니다. 이번 설치 시에는 구성 요소 선택 단계에서 Add to PATH 항목이 정상적으로 체크되었는지 반드시 확인하십시오.
[56] PATH는 Node.js에만 적용되는 개념이 아닙니다. 3장에서 설치할 Git, 5장에서 설치할 GitHub CLI 역시 PATH에 경로를 등록해야 터미널에서 각각 【39】, 【40】 명령어로 호출할 수 있습니다. 앞으로 어떤 도구를 설치하여도 터미널이 명령어를 인식하지 못하는 경우, 이번 장에서 설명한 순서에 따라 ①터미널을 새로 실행 ②컴퓨터 재시작 ③PATH 경로 확인을 차례로 진행하여 보십시오.
[57] 2.5절에서 【41】 명령어를 통하여 npm의 버전도 함께 확인하였습니다. npm은 별도로 설치하지 않았음에도 Node.js를 설치하면 자동으로 함께 설치됩니다. 이제 npm이 무엇인지 설명하겠습니다.
[58] npm은 Node Package Manager의 약자입니다. npm을 이용하면 개발에 필요한 코드 묶음, 즉 패키지를 인터넷으로부터 내려받아 프로젝트에 쉽게 설치할 수 있습니다. 필요한 패키지 이름을 입력하고 명령어를 실행하면, npm이 자동으로 패키지를 내려받아 프로젝트에 적용하여 줍니다. 전 세계 개발자들이 공유한 수많은 패키지를 활용할 수 있으며, 그 수가 수백만 개에 이릅니다.
[59] 이 책에서 npm을 사용하는 경우는 크게 두 가지입니다.
[60] 앞으로 여러분이 npm 명령어를 직접 입력할 경우는 많지 않을 것입니다. 8장 이후부터는 Claude Code에게 기능 구현을 요청하면, 필요한 패키지가 있을 경우 에이전트가 스스로 【42】 명령어를 실행하겠다고 제안할 것입니다. 여러분은 그 제안 내용을 확인한 뒤 승인만 하면 됩니다. 다만 npm이 어떤 역할을 하는지 정도는 알고 있어야, 에이전트가 【43】라고 요청하여 왔을 때 어떤 내용을 승인하는지 이해하고 결정할 수 있습니다.
[61] 지금 당장 명령어를 암기할 필요는 없습니다. npm은 개발용 도구를 설치하는 프로그램이며, Node.js를 설치하면 기본으로 함께 제공된다는 점만 기억하여 두면 충분합니다.
[62] 【44】의 버전 번호와 【45】의 버전 번호는 서로 다릅니다. 예를 들어 Node.js의 버전이 v22이고 npm의 버전이 10이라 하여도 오류가 아닙니다. 두 프로그램은 별개로 개발되므로 각자 독립적인 버전 번호를 사용하기 때문입니다.
