[24] 여기서 LTS가 무엇인지 짚고 갑시다. LTS는 Long Term Support의 약자로, 우리말로는 장기 지원 버전이라고 합니다. Node.js는 새 기능을 먼저 넣는 Current 버전과, 안정성을 검증해 오래 지원하는 LTS 버전으로 나뉩니다. Current에는 아직 걸러 내지 못한 문제가 섞여 있을 수 있습니다. LTS는 여러 사람이 오래 써 보며 문제를 고친 뒤에 내놓습니다. 최신 기능보다 안정성이 중요하다면 LTS 쪽이 낫습니다. 참고로 Node.js는 짝수 번호 버전만 LTS가 됩니다. 20, 22, 24처럼 짝수 버전은 시간이 지나면 LTS로 승격됩니다. 21, 23 같은 홀수 버전은 실험용이라 얼마 지나지 않아 지원이 끝납니다. 이 책을 쓰는 시점의 LTS는 v22 계열이지만, 여러분이 보는 화면에는 더 높은 숫자가 적혀 있을 수 있습니다. 숫자가 몇이든 LTS라고 적힌 쪽을 받으면 됩니다.

[52] 2단계. 파일이 실제로 있는지 확인. 파일 탐색기로 【37】 폴더를 열어 봅니다. 폴더 안에 【38】가 보이면 설치는 끝났습니다. PATH 등록만 빠졌다는 뜻입니다. 폴더 자체가 없다면 설치가 실패했으니 2.4절의 설치를 처음부터 다시 진행하세요.

[53] 3단계. PATH에 직접 등록. 파일은 있는데 명령만 안 된다면 PATH에 직접 등록합니다.

[54] 그림 2.8 — 환경 변수 편집 창에서 Path에 nodejs 경로 확인

[55] 4단계. 그래도 안 되면 재설치. 제어판(설정 → 앱 → 설치된 앱)에서 Node.js를 제거한 뒤, 2.3절부터 다시 설치합니다. 이번에는 Custom Setup 화면에서 Add to PATH가 빠지지 않았는지 반드시 확인하세요.

[56] PATH가 Node.js에만 해당하는 개념은 아닙니다. 3장의 Git, 5장의 GitHub CLI도 PATH에 등록해야 터미널에서 【39】, 【40】로 부를 수 있습니다. 앞으로 어떤 도구든 설치했는데 터미널이 명령을 못 찾으면, 이번 장의 순서 그대로 ①터미널 새로 열기 → ②재부팅 → ③PATH 확인을 차례로 해 보세요.

[57] 2.5절에서 【41】도 함께 확인했습니다. npm은 따로 설치한 적이 없는데도 Node.js를 깔면 함께 들어옵니다. npm이 무엇인지 여기서 짚고 넘어가겠습니다.

[58] npm은 Node Package Manager를 줄인 이름입니다. npm으로 개발에 필요한 코드 꾸러미를 인터넷에서 내려받아 설치할 수 있습니다. 이 코드 꾸러미를 패키지라고 부릅니다. 필요한 패키지 이름을 적어 명령 한 줄을 실행하면 npm이 내려받아 프로젝트에 넣어 줍니다. 전 세계 개발자가 올린 패키지가 수백만 개에 이릅니다.

[59] 이 책에서는 npm을 앞으로 두 곳에서 씁니다.

[60] 앞으로 npm 명령을 여러분이 직접 입력할 일은 많지 않을 겁니다. 8장 이후로는 Claude Code에게 기능을 만들어 달라고 요청합니다. 그러면 필요한 패키지가 있을 때 에이전트가 【42】 명령을 실행하겠다고 제안합니다. 여러분은 그 제안을 보고 승인하면 됩니다. 그래도 npm이 무엇인지는 알아 두어야 합니다. 에이전트가 【43】라고 물어 왔을 때 무엇을 승인하는지 알고 답해야 하기 때문입니다.

[61] 지금 명령을 외울 필요는 없습니다. npm은 도구를 설치해 주는 프로그램이고, Node.js를 깔면 함께 들어온다는 사실만 기억해 두면 충분할 겁니다.

[62] 【44】의 버전과 【45】의 버전은 서로 다른 숫자입니다. Node.js가 v22인데 npm이 10이어도 잘못된 것은 아닙니다. 둘은 별개의 프로그램이라 각자 버전 번호를 따로 매기기 때문입니다.
