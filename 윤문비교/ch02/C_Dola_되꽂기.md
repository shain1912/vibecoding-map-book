# 2장 Node.js 설치

!!! note "이 장에서 배우는 것"
    - Node.js가 무엇이고, 왜 이 책의 모든 도구가 Node.js 위에서 도는지 이해합니다
    - 내 컴퓨터에 Node.js가 이미 있는지 `node -v`로 확인합니다
    - nodejs.org에서 LTS 버전을 내려받아 윈도우에 설치합니다
    - "명령을 찾을 수 없습니다"라는 PATH 오류를 스스로 해결합니다
    - npm이 무엇인지, 앞으로 어디에 쓰는지 감을 잡습니다

## 2.1 Node.js가 왜 필요한가요

1장에서 코드는 AI에게 작성을 맡기고 결과는 사람이 판단한다는 원칙을 설명하였습니다. 이 방식으로 작업하려면 개발 환경을 먼저 준비하여야 합니다. 이번 장부터 6장까지 필요한 도구를 하나씩 설치하며, 가장 먼저 Node.js를 설치합니다.

Node.js는 웹 브라우저 외부에서 자바스크립트를 실행하는 환경입니다.

과거 자바스크립트는 웹 페이지 내에서만 사용할 수 있었습니다. 크롬이나 엣지 같은 브라우저가 연 페이지 안에서만 동작하였습니다. 2009년 Node.js가 등장하면서 이 제약이 사라졌습니다. 브라우저 없이 컴퓨터의 터미널에서 자바스크립트를 직접 실행할 수 있게 되었습니다. 이후로 자바스크립트를 활용하여 서버, 개발 도구, 명령줄 프로그램 등을 제작하기 시작하였습니다.

지도 웹앱을 제작하는 데 브라우저 외부에서 자바스크립트를 실행하는 환경이 필요한 이유는 이 책에서 사용하는 도구들이 Node.js 기반으로 동작하기 때문입니다.

8장에서 다룰 Vite도 그중 하나입니다. Vite는 지도 앱 개발 시 개발 서버를 실행하고, 코드를 수정할 때마다 브라우저 화면을 자동으로 갱신합니다. Vite 자체가 Node.js로 제작되었으므로 Node.js가 없으면 동작하지 않습니다.

4장에서 설치할 Claude Code도 마찬가지입니다. 코드를 대신 작성하는 이 AI 에이전트 역시 Node.js로 제작된 명령줄 프로그램입니다. 설치 시에도 Node.js에 포함된 npm을 사용합니다.

완성된 지도 앱을 사용하는 사용자에게는 Node.js가 보이지 않습니다. 사용자는 브라우저에 표시되는 지도만 보게 될 뿐입니다. 그러나 앱을 제작하는 동안에는 Vite와 Claude Code가 Node.js 위에서 동작하므로 Node.js가 반드시 필요합니다.

이 책에서 Node.js를 사용하여 직접 프로그램을 작성하는 경우는 없을 것입니다. Vite와 Claude Code가 관련 작업을 처리합니다. 설치에 소요되는 시간은 약 10분 내외입니다.

!!! tip "팁"
Node.js에서 "js"는 JavaScript의 약자입니다. 앞으로 파일 이름 끝에 붙는 .js 확장자가 자주 보일 것인데, 이는 자바스크립트 파일을 의미합니다.

## 2.2 먼저 확인부터: 이미 설치되어 있을 수도 있습니다

어떤 프로그램이든 설치하기 전에 확인하는 습관을 가지는 것이 좋습니다. 다른 프로그램을 설치하는 과정에서 Node.js가 함께 설치되었을 수도 있으므로, 터미널에서 먼저 확인하여 봅니다.

터미널에서는 마우스로 아이콘을 클릭하는 대신 키보드로 명령어를 입력하여 컴퓨터를 조작합니다. 이 책 전체에서 터미널을 지속적으로 사용하므로 여는 방법을 미리 익혀 두는 것이 좋습니다.

윈도우에서 터미널을 여는 가장 간단한 방법은 다음과 같습니다.

1. 키보드에서 윈도우 키를 누릅니다.
2. 검색창에 terminal 또는 터미널이라고 입력합니다.
3. 터미널(Windows Terminal) 앱이 보이면 클릭해서 엽니다.

검은색 또는 흰색 창이 나타나고 PS C:\Users\사용자이름>과 같은 문구가 표시되면 정상적으로 열린 것입니다. 이 문구를 프롬프트라고 부르며, 명령을 입력할 수 있는 상태임을 의미합니다.

!!! tip "팁"
윈도우 10 일부 버전에는 Windows Terminal이 포함되지 않을 수 있습니다. 그 경우 검색창에 PowerShell이라고 입력하여 표시되는 파란색 아이콘을 실행하면 됩니다. 어느 쪽을 사용하더라도 이 책의 작업 내용은 동일하게 진행할 수 있습니다.

이제 프롬프트에 다음 명령을 입력하고 Enter 키를 누릅니다.

```
node -v
```

node는 Node.js를 호출하는 명령이며, -v는 버전 정보를 확인하라는 옵션입니다. 실행 결과는 두 가지 경우 중 하나로 나타납니다.

경우 1. 버전 번호가 표시되는 경우. v22.19.0처럼 v로 시작하는 숫자가 나타나면 Node.js가 이미 설치된 상태입니다. 다만 버전이 낮은 경우(예: v16 이하) 이 책의 도구가 정상적으로 동작하지 않을 수 있습니다. 버전의 첫 번째 숫자가 20 이상이면 그대로 사용하여도 좋고, 그보다 낮으면 이번 장의 내용에 따라 최신 LTS 버전으로 다시 설치합니다. 새 버전을 설치하면 기존 버전은 자동으로 교체됩니다.

경우 2. 오류가 발생하는 경우. 다음과 유사한 오류 메시지가 표시되면 컴퓨터에 Node.js가 아직 설치되지 않은 것입니다.

```
node : 'node' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는
프로그램 이름으로 인식되지 않습니다.
```

해당 프로그램을 찾을 수 없다는 의미이므로, 이제부터 설치를 진행하면 됩니다.

터미널 사용 시 알아 두면 편리한 조작법 두 가지를 숙지합니다. 위쪽 화살표(↑) 키를 누르면 직전에 입력한 명령어가 다시 표시되므로, 동일한 명령을 반복 실행할 때 매번 입력할 필요가 없습니다. 붙여넣기는 마우스 오른쪽 클릭 또는 Ctrl+V로 수행합니다. 책에 제시된 명령어를 직접 입력하면 오타가 발생하기 쉬우므로, 전자책으로 보고 있는 경우 복사하여 붙여넣는 것이 좋습니다. 다만 명령어의 의미를 파악한 뒤 실행하는 습관을 가지는 것이 좋습니다. 코드를 외울 필요는 없지만, 어떤 작업을 수행하는지 이해하는 것이 중요합니다.

## 2.3 nodejs.org에서 LTS 내려받기

이제 공식 홈페이지에서 설치 파일을 내려받습니다. 브라우저를 열고 주소창에 해당 주소를 입력합니다.

```
https://nodejs.org
```

첫 화면에 큰 다운로드 버튼이 표시됩니다. 버튼에는 버전 번호와 함께 LTS라는 문구가 표시될 것입니다.

LTS의 의미를 설명하면 다음과 같습니다. LTS는 Long Term Support의 약자로 장기 지원 버전을 의미합니다. Node.js는 새로운 기능을 우선 적용하는 Current 버전과, 안정성이 검증되어 장기간 지원하는 LTS 버전으로 구분됩니다. Current 버전에는 아직 검증되지 않은 문제점이 포함되어 있을 수 있습니다. LTS 버전은 다수의 사용자가 검증한 뒤 출시되므로 안정성이 높습니다. 최신 기능보다 안정성이 중요한 경우 LTS 버전을 사용하는 것이 좋습니다. 참고로 Node.js는 짝수 번호 버전이 LTS 버전으로 지정됩니다. 20, 22, 24와 같은 짝수 버전은 시간이 지나면 LTS로 승격되며, 21, 23과 같은 홀수 버전은 실험용으로 지원 기간이 짧습니다. 이 책 집필 시점의 LTS는 v22 계열이지만, 실제 화면에는 더 높은 버전 번호가 표시될 수 있습니다. 표시되는 LTS 버전을 내려받으면 됩니다.

다운로드 페이지에서 운영체제는 Windows, 설치 방식은 Installer(.msi)로 선택되었는지 확인한 뒤 다운로드 버튼을 클릭합니다. 대부분 윈도우용이 기본으로 선택되어 있을 것입니다. 다운로드가 완료되면 다운로드 폴더에 node-v22.19.0-x64.msi와 같은 이름의 파일이 생성됩니다.

!!! tip "Mac 사용자라면"
macOS의 경우 동일한 페이지에서 macOS Installer 항목의 .pkg 파일을 내려받아 실행합니다. 화면의 안내에 따라 계속 버튼을 클릭하면 설치가 완료됩니다. 설치 후 node -v와 npm -v로 확인하는 방식은 윈도우와 동일합니다. 터미널은 Spotlight에서 터미널을 검색하여 실행하면 되며, Spotlight는 ++cmd+space++ 단축키로 열 수 있습니다. 이후 장에서 사용하는 명령어도 윈도우와 거의 동일하므로 그대로 따라하면 됩니다.

!!! tip "팁"
터미널 사용에 익숙한 경우 홈페이지에 접속하지 않고도 설치할 수 있습니다. 윈도우에 기본 포함된 패키지 관리자 winget으로 winget install OpenJS.NodeJS.LTS 명령 한 줄로 설치를 완료할 수 있습니다. 다만 처음 접하는 경우 이번 장에서 설명하는 설치 마법사 방식을 권장합니다. 설치 과정에서 어떤 항목을 선택하는지 직접 확인하면 이후 다른 도구를 설치할 때 도움이 될 것입니다.

## 2.5 설치 확인

새 터미널을 열고 다음 두 가지 명령을 차례로 실행합니다.

```
node -v
npm -v
```

첫 번째 명령에서는 v22.19.0과 같이 v로 시작하는 버전 번호가 표시되고, 두 번째 명령에서는 10.9.3과 같은 버전 번호가 표시되면 정상적으로 설치된 것입니다. 표시되는 버전 번호는 책의 내용과 약간 다를 수 있으며, 이는 LTS 버전이 지속적으로 갱신되기 때문이므로 오류가 아닙니다. 오류 없이 버전 번호가 표시되는지만 확인하면 됩니다.

![`node -v`와 `npm -v` 버전 확인 결과 (출력 예시)](images/ch02/ch02-f07.png){ width="760" }

이제 컴퓨터에서 자바스크립트를 실행할 수 있는 환경이 준비되었습니다. 간단한 명령으로 확인하여 봅니다. 터미널에 다음과 같이 입력합니다.

```
node -e "console.log(1 + 1)"
```

실행 결과로 2가 표시됩니다. -e 옵션은 따옴표 안의 자바스크립트 코드를 직접 실행하라는 의미이며, console.log는 실행 결과를 화면에 출력하는 기능입니다. 브라우저 없이 자바스크립트가 실행된 것을 확인할 수 있습니다. 이 코드의 의미를 완전히 이해하지 못하여도 이후 진행에 문제가 없으므로, 터미널에서 자바스크립트가 정상 실행된다는 점만 확인하면 됩니다.

## 2.6 "명령을 찾을 수 없습니다": PATH 문제 해결

새 터미널에서도 여전히 해당 명령어가 인식되지 않는다는 오류가 발생하는 경우, 환경 변수 등록이 정상적으로 이루어지지 않았을 가능성이 높습니다. 이 문제의 원인과 해결 방법을 설명합니다.

터미널에서 node라고 입력하면 윈도우는 시스템 전체를 검색하는 것이 아니라, 환경 변수 PATH에 등록된 폴더를 순서대로 확인하며 node.exe 파일을 찾습니다. 만약 C:\Program Files\nodejs\ 경로가 등록되어 있다면 어느 위치에서든 node 명령어로 프로그램을 실행할 수 있으며, 등록되지 않은 경우 파일이 존재하여도 찾을 수 없습니다.

따라서 이 오류는 프로그램이 설치되지 않아서 발생하는 것이 아니라, 설치된 경로가 환경 변수에 등록되지 않아서 발생하는 것입니다. 해당 경로를 환경 변수에 추가하면 해결됩니다.

설치 마법사의 Add to PATH 옵션이 자동으로 이 작업을 수행하지만, 간혹 누락되는 경우가 있습니다. 다음 순서로 확인하고 조치합니다.

1단계. 컴퓨터 재시작. 가장 간단한 방법으로 의외로 효과가 좋습니다. 시스템을 재시작하면 모든 프로그램이 갱신된 환경 변수를 다시 불러오게 됩니다. 재시작 후 새 터미널에서 node -v 명령을 다시 실행하여 확인합니다.

2단계. 설치 파일 존재 확인. 파일 탐색기에서 C:\Program Files\nodejs 폴더를 확인합니다. 폴더 내에 node.exe 파일이 존재한다면 설치는 정상적으로 완료된 것이며, 환경 변수 등록만 누락된 상태입니다. 해당 폴더 자체가 존재하지 않는 경우 설치 과정에 문제가 있었으므로 2.3절의 설치 단계를 다시 진행합니다.

3단계. 환경 변수에 직접 등록. 설치 파일은 존재하지만 명령어가 실행되지 않는 경우 환경 변수 PATH에 직접 경로를 추가합니다.

1. 윈도우 키를 누르고 환경 변수라고 검색한 뒤 시스템 환경 변수 편집을 엽니다.
2. 창 아래쪽의 환경 변수(N)... 버튼을 누릅니다.
3. 아래쪽 시스템 변수 목록에서 Path를 찾아 선택하고 편집(I)...을 누릅니다.
4. 목록에 `C:\Program Files\nodejs\`가 있는지 확인합니다. 없으면 새로 만들기(N)를 눌러 `C:\Program Files\nodejs\`를 입력합니다.
5. 확인을 세 번 눌러 모든 창을 닫습니다.
6. 터미널을 새로 열고 `node -v`를 다시 실행합니다.

![환경 변수 편집 창에서 Path에 nodejs 경로 확인](images/ch02/ch02-f08.png){ width="680" }
/// caption
그림 2.8 — 환경 변수 편집 창에서 Path에 nodejs 경로 확인
///

4단계. 재설치. 위 단계로 해결되지 않는 경우 제어판에서 Node.js를 제거한 뒤 2.3절부터 다시 설치합니다. 이때 구성 요소 선택 화면에서 Add to PATH 항목이 정상적으로 체크되었는지 반드시 확인합니다.

!!! tip "팁"
환경 변수 PATH는 Node.js에만 해당하는 개념이 아닙니다. 3장의 Git, 5장의 GitHub CLI도 환경 변수에 등록해야 터미널에서 git, gh 명령어로 호출할 수 있습니다. 앞으로 어떤 도구를 설치하여도 명령어를 인식하지 못하는 경우, ①터미널을 새로 열고 ②컴퓨터를 재시작한 뒤 ③환경 변수를 확인하는 순서로 점검하면 됩니다.

## 2.7 함께 설치된 npm

2.5절에서 npm -v 명령으로 npm의 버전도 함께 확인하였습니다. npm은 별도로 설치하지 않아도 Node.js 설치 시 함께 포함되어 제공됩니다. npm의 역할에 대하여 설명합니다.

npm은 Node Package Manager의 약자입니다. npm을 사용하여 개발에 필요한 코드 묶음을 인터넷에서 내려받아 사용할 수 있으며, 이러한 코드 묶음을 패키지라고 부릅니다. 필요한 패키지 이름을 지정하고 명령어를 실행하면 npm이 자동으로 내려받아 프로젝트에 적용합니다. 전 세계 개발자가 공유하는 수많은 패키지를 활용할 수 있습니다.

이 책에서는 npm을 두 가지 상황에서 사용하게 될 것입니다.

- 4장에서 `npm install -g @anthropic-ai/claude-code`로 Claude Code를 설치합니다
- 8장에서 `npm create vite@latest`로 지도 앱 프로젝트를 만듭니다

이후로 npm 명령어를 직접 입력할 일은 많지 않을 것입니다. 8장 이후로는 Claude Code에 기능 구현을 요청하게 되며, 필요한 패키지가 있는 경우 에이전트가 자동으로 설치 명령어를 제안합니다. 해당 제안을 확인하고 승인하면 됩니다. 그래도 npm의 역할을 이해하는 것이 중요한데, 에이전트가 패키지 설치를 제안할 때 어떤 내용을 승인하는지 알고 있어야 하기 때문입니다.

지금 당장 명령어를 외울 필요는 없으며, npm은 패키지 관리 도구이고 Node.js에 기본 포함된다는 점만 기억하면 충분합니다.

!!! tip "팁"
node -v로 표시되는 버전과 npm -v로 표시되는 버전은 서로 다릅니다. Node.js의 버전이 v22라 하여 npm의 버전이 동일하지는 않으며, 두 프로그램은 별개로 관리되므로 버전 번호가 다릅니다.
