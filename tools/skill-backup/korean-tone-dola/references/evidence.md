『바이브코딩으로 배우는 인공지능 윤리』 29장을 Dola로 윤문하면서,
윤문 전후를 문단 단위로 짝지어 전수 비교했다.

- 짝 지은 문단 1,439개
- 원문 217,780자 / 5,575문장 → Dola 281,344자 / 5,674문장
- 문단 평균 150자 → 195자
- 문장 평균 37자 → 48자
- 문단당 문장 수 3.9개 → 3.9개 (변화 없음)

문단 수가 그대로인데 글자가 29% 늘었다. 문장을 더 쪼갠 것이 아니라
한 문장을 길게 쓰고, 생략했던 주어·목적어를 되살린 결과다.

## 실제 문장 짝

**구어 축약과 청유를 걷어낸다**

```
원문: 이 책에서 Node.js를 직접 프로그래밍할 일은 없을 겁니다. Vite와 Claude
      Code가 알아서 씁니다. 설치는 10분이면 넉넉할 겁니다.
Dola: 이 책에서 여러분이 Node.js로 직접 프로그램을 작성할 일은 없을 것입니다.
      관련 작업은 Vite와 Claude Code가 대신 처리합니다. 설치에는 대략 10분
      정도면 충분합니다.
```

**명령을 권유로 바꾸고 결과를 명시한다**

```
원문: 저장하고 디바이스 모드 화면을 보세요. 지도가 화면 전체에 깔리고,
      사이드바가 그 위에 그림자를 드리우며 떠 있으면 제대로 적용됐다고
      보셔도 좋습니다.
Dola: 코드를 저장한 뒤 디바이스 모드에서 화면을 확인하여 보시기 바랍니다.
      지도가 화면 전체에 걸쳐 표시되고, 사이드바가 그 위에 그림자를 가지고
      떠 있는 형태로 나타난다면 정상적으로 적용된 것입니다.
```

**지시어를 '해당'으로, 동사를 한자어로**

```
원문: 결과가 좋지 않으면 카드를 지웁니다. 워크트리를 지워도 원본 폴더는
      그대로 남습니다.
Dola: 반면 작업 결과가 만족스럽지 않으면 해당 카드를 삭제합니다. 워크트리를
      삭제하여도 원본 폴더의 내용물은 전혀 변경되지 않습니다.
```

**말장난 제목을 평서형으로**

```
원문: 그림 16.1 — 입구는 둘, 문은 하나: 장소 추가의 전체 흐름
Dola: 그림 16.1 — 경로는 두 가지, 처리 방식은 하나: 장소 추가의 전체 흐름

원문: 그림 26.4 — 자랑하기 3단계 코스
Dola: 그림 26.4 — 공유하기 3단계 과정

원문: 그림 20.1 — 브라우저가 위치를 알아내는 세 가지 단서
Dola: 그림 20.1 — 브라우저의 위치 파악에 사용되는 세 가지 정보
```

**짧은 문장 둘을 하나로**

```
원문: 2장에서 만난 PATH가 여기서 다시 나옵니다. git 명령을 어디서 쓸 수
      있게 할지 정하는 화면이고, 선택지가 셋입니다.
Dola: 2장에서 언급한 바 있는 환경 변수 PATH에 관한 설정이 이번 단계에서 다시
      등장합니다. 이 설정은 git 명령어를 어느 위치에서나 사용할 수 있도록
      허용할 것인지 결정하는 내용이며, 총 세 가지의 선택지가 제시됩니다.
```
