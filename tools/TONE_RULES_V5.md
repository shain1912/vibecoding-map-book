# 문체 점검 기준 v5 — 저자가 반복해서 지적한 것

빈도 검사기로는 안 잡힌다. 읽어야 보인다. 아래 형태가 보이면 **그냥 단정해서 서술**한다.

## 1. 불필요한 부정 대조 — "A가 아니라 B"

저자 지적: *"우리가 컴퓨터로 그렸다고 하면 되지 뭘 그렇게 '아니고 했다' 투를 씀?"*

독자가 생각도 하지 않은 것을 굳이 끌어와 부정하고 시작하는 버릇.

- ✗ 「카카오지도가 기본으로 주는 말풍선이 아니라 HTML과 CSS로 직접 만든 말풍선입니다」
- ✓ 「이 말풍선은 HTML과 CSS로 직접 만들었습니다」

**다만 전부 지우면 안 된다.** 대조 자체가 정보일 때는 남긴다.

- ✓ 남김: 「5173이 아니라 5174처럼 다른 번호로 뜬다면」 (문제 상황 구분이 정보)
- ✓ 남김: 「`.env`가 src 안이 아니라 프로젝트 루트에 있는지」 (위치를 바로잡는 말)
- ✓ 남김: 「인터넷 어딘가의 서버가 아니라 지금 쓰고 있는 이 PC를 뜻합니다」 (용어 정의)

판단 기준: **부정되는 대상이 이미 독자 머릿속에 있는가?** 있으면 남기고, 없으면 지운다.

## 2. 이중 명사화 — "~것이라, …것입니다"

- ✗ 「직접 만들어 붙인 것이라, 꼬리 모양까지 우리가 그린 것입니다」
- ✓ 「직접 만든 말풍선입니다. 꼬리도 우리가 그렸습니다」 (두 문장으로 끊는다)

## 3. "~게 되는지 / ~게 됩니다"

- ✗ 「무엇을 만들게 되는지부터 눈으로 보고 시작하겠습니다」
- ✓ 「무엇을 만들지부터 살펴봅시다」

## 4. 사실인데 추측처럼 — "~으로 보입니다"

- ✗ 「분홍색으로 보입니다」  ✓ 「분홍색입니다」

## 5. "남습니다" 종결 — 쓰지 않는다

- ✗ 「네 가지가 남습니다」  ✓ 「네 가지를 얻을 수 있습니다」

물리적으로 remain 이라는 뜻이어도 다른 표현으로 바꾼다.

## 6. 불필요한 부사 — "눈으로 / 손으로"

- ✗ 「눈으로 확인해 보세요」  ✓ 「확인해 보세요」

## 7. 억지 유보 — "~라고 볼 수 있습니다 / ~보시면 됩니다"

단정해도 되는 자리에 붙인 완충은 뺀다.

## 어체

합니다체. 「살펴봅시다」, 「보세요」, 「~수 있습니다」, 「~것은 아닙니다」.
해요체는 쓰지 않는다 (교수님 원고에 없다).
