# 윤문 규칙 — "점프 투 파이썬처럼 담백하게"

저자가 대학 교수에게 "AI 말투가 심하다"고 지적받았다. 특히 두 가지다.

1. 굳이 붙이는 예고·과시 — "완성된 모습부터 보여드립니다", "~하는 시간입니다"
2. 있어 보이려고 멋 부린 재정의(중2병) — "그렇게 보면 ~는 유효한 ~가 아닙니다"

## 절대 원칙: 내용은 바꾸지 않는다

문체만 고친다. 기술적 사실·설명 순서·예시·수치는 그대로 둔다.
**코드 블록 / 헤딩 / 이미지 참조 / 링크 / `/// caption` 블록 / 인라인 코드는 절대 수정 금지.**
문장을 삭제해 분량을 줄이지 말 것 (산문 12% 이상 감소하면 검사 실패).

## 고치는 법 — ch21 실제 사례 (이 톤을 따를 것)

**예고성 메타 발화**
- 「주머니를 찾았으니 무엇을 담을지 정할 차례입니다.」 → 「이제 무엇을 담을지 정합니다.」
- 「설계가 끝났으니 만들 차례입니다.」 → 「이제 만듭니다.」
- 「완성된 모습부터 보여드립니다」 → 무엇을 만드는지 바로 서술
- 「~을 살펴봅니다 / 알아보겠습니다 / 돌아보겠습니다」 → 바로 본론

**중2병 재정의**
- 「~는 지도 앱만의 것이 아닙니다.」 → 「~는 지도 앱 말고도 널리 쓰입니다.」
- 「좌표 세 개, "카메라의 위치"일 뿐 "지도 위의 내용물"이 아닙니다.」
  → 「좌표 세 개뿐입니다. 카메라가 어디를 보고 있는지는 담기지만, 지도 위에 무엇이 놓여 있는지는 담기지 않습니다.」
- 「X는 Y이지 Z가 아닙니다」 형태는 전부 평범한 서술로 푼다.

**극적 지시**
- 「비밀은 간단합니다. **지도의 상태를 URL 안에 새겨 넣는 것**입니다.」
  → 「지도의 상태를 URL 안에 새겨 넣었기 때문입니다.」
- 「`toFixed(5)`가 바로 그 일을 합니다.」 → 「`toFixed(5)`가 ~해 줍니다.」
- 「~인 셈입니다 / 셈이죠」 → 「~입니다」
- 「바로 그」, 「핵심은」, 「비밀은」, 「정체는」 → 평서문으로

**독자 반응 대행 · 예고 후 본론**
- 「~의 가치를 짚고 넘어가야 합니다」 → 「~이 왜 필요한지 봅시다」
- 「기능이 잘 돌아가니 기분이 좋지만, 솔직하게 한계도 짚고 넘어가야 합니다.」 → 「이 기능에는 한계가 하나 있습니다.」
- 「~가 궁금해집니다」, 「주의할 점이 하나 있습니다」 → 넘겨짚지 말고 바로 서술

**교훈조 마무리**
- 「한계를 아는 것은 부끄러운 일이 아닙니다. 오히려 ~야말로 ~증거입니다.」
  → 「어디까지 되고 어디부터 다른 기술이 필요한지 알아 두면 다음 설계가 쉬워집니다.」
- 훈계·감동으로 끝내지 말고 사실로 끝낸다.
