# 19장 상세 패널

!!! note "이 장에서 배우는 것"
    - 장소 하나를 자세히 보고 편집하는 상세 패널 UI를 만듭니다
    - 별점 버튼(1~5)으로 평점을 매기고, 클릭 즉시 화면에 반영합니다
    - 메모를 입력하고 저장하는 흐름과 `store.update`의 쓰임새를 익힙니다
    - 삭제 전에 `confirm`으로 한 번 더 물어보는 이유를 배웁니다
    - XSS 공격이 무엇인지 직접 실험해 보고, `escapeHtml`로 막는 법을 배웁니다

---

16장에서 장소를 추가했고, 17장에서 localStorage에 저장했고, 18장에서 사이드바 목록으로 확인할 수 있게 만들었습니다. 아직 못 하는 일이 남아 있습니다. 저장해 둔 장소의 별점과 메모를 고치지 못하고, 더 이상 필요 없는 장소를 지울 수는 없습니다. 데이터를 다루는 기본 동작을 CRUD라고 부릅니다. Create로 만들고 Read로 읽고 Update로 고치고 Delete로 지우는 네 동작의 머리글자를 딴 이름입니다. 지금까지 C와 R을 만들었고, 이번 장에서 U와 D를 만들겠습니다.

이 두 기능을 담을 상세 패널을 만듭니다. 마커나 목록에서 장소를 고르면 지도 오른쪽 위에 카드가 나타나 그 장소의 이름·카테고리·별점·메모를 보여 주고, 그 자리에서 바로 편집까지 할 수 있게 합니다. 카카오맵에서 가게를 눌렀을 때 옆에 뜨는 상세 화면을 작게 줄여 놓은 것이라고 생각하셔도 좋습니다. 그리고 이 장의 끝에서는 15장에서 19장으로 미뤄 뒀던 `escapeHtml`을 다루겠습니다. XSS라는 웹 보안 문제를 직접 실험으로 확인하고 막는 방법까지 만들어 봅니다.

## 19.1 상세 패널 설계: 어디에, 무엇을

코드를 시키기 전에 늘 하던 대로 그림부터 그려 봅시다. 상세 패널에 들어갈 내용을 네 덩어리로 나눴습니다.

1. 머리글: 카테고리 이모지 + 장소 이름, 그리고 닫기(×) 버튼
2. 별점 줄: ★ 버튼 다섯 개. 현재 별점만큼 노랗게 칠해져 있고, 누르면 그 값으로 바뀝니다
3. 메모 칸: 여러 줄 입력이 되는 `textarea`
4. 동작 버튼: 저장, 그리고 빨간 글씨의 삭제

자리는 지도 오른쪽 위가 좋습니다. 왼쪽은 사이드바가 차지하고 있으니, 반대편에 띄우면 목록과 상세를 나란히 놓고 볼 수 있습니다. 13장의 말풍선처럼 지도 위에 겹쳐 뜨는 요소이므로 `position: absolute`를 쓰고, 평소에는 `hidden` 속성으로 숨겨 둡니다. 15장의 검색 결과 목록과 똑같은 방식입니다. 화면 요소는 상태에 따라 나타나고 사라집니다.

그전에 한 가지 정할 것이 있습니다. 패널 안의 내용을 HTML에 미리 써 둘지, 아니면 열 때마다 자바스크립트로 만들어 넣을지 골라야 합니다. 검색 결과 목록은 열 때마다 만들어 넣었고, 상세 패널도 같은 방식으로 만듭니다. 어떤 장소가 클릭될지, 별점이 몇 개일지, 메모에 무엇이 적혀 있을지는 클릭되는 시점 전까지 알 수는 없습니다. 그래서 HTML에는 빈 요소만 두고, 열 때마다 내용을 새로 그려 넣습니다. Claude Code에게 HTML 구조와 스타일부터 요청합시다.

!!! tip "이렇게 물어보세요"
    > index.html의 지도 영역 안에 상세 패널 그릇을 추가해줘. `<section id="detail-panel" hidden></section>` 하나면 되고 내용은 자바스크립트로 채울 거야. style.css에는 지도 오른쪽 위(right/top 12px)에 뜨는 폭 280px 흰색 카드로 스타일을 잡아줘. 둥근 모서리와 그림자로 말풍선·다이얼로그와 톤을 맞춰줘.

Claude Code가 `index.html`에 넣은 것은 아래 한 줄뿐입니다.

```html
<section id="detail-panel" hidden></section>
```

`style.css`에 추가된 스타일은 이렇습니다.

```css
#detail-panel {
  position: absolute; right: 12px; top: 12px; z-index: 25;
  width: 280px; background: #fff; border-radius: 14px;
  box-shadow: 0 6px 24px rgb(0 0 0 / 0.18); padding: 16px;
}
.detail-stars .star {
  border: none; background: none; font-size: 24px; cursor: pointer; color: #d1d5db;
}
.detail-stars .star.on { color: #f59e0b; }
#detail-memo {
  width: 100%; margin: 10px 0; padding: 8px; border: 1px solid var(--line);
  border-radius: 8px; font-family: inherit; font-size: 13px; resize: vertical;
}
button.primary { background: var(--brand); border-color: var(--brand); color: #fff; }
button.danger { color: #dc2626; border-color: #fecaca; }
```

별점 부분을 눈여겨보세요. `.star`는 평소 `#d1d5db`의 회색이고, `on` 클래스가 붙은 것만 `#f59e0b`의 노란색이 됩니다. 14장 필터 버튼의 `active` 토글과 똑같은 방식입니다. 모양은 CSS가, 켜고 끄기는 클래스가 담당합니다. 삭제 버튼에는 `danger`라는 클래스로 빨간 계열을 입혔습니다. 되돌릴 수 없는 버튼을 빨갛게 표시하는 관례는 웹 어디에서나 볼 수 있습니다.

## 19.2 openDetail: 패널을 그리는 함수

이제 동작하는 코드를 만듭니다. 지금까지의 규칙대로 상세 패널도 파일 하나에 담고, 이름은 `src/detail.js`로 하겠습니다. 요구사항을 정리해서 한 번에 시켜 봅시다.

!!! tip "이렇게 물어보세요"
    > src/detail.js를 새로 만들어줘. openDetail(id)과 closeDetail을 export하고, openDetail은 store.get(id)으로 장소를 찾아 #detail-panel 안에 카테고리 이모지+이름 머리글(닫기 × 버튼 포함), 별 버튼 5개(현재 별점만큼 on 클래스), 메모 textarea, 저장/삭제 버튼을 그려줘. 별을 누르면 store.update로 rating을 바꾸고, 저장은 memo를 update하고 toast를 띄우고, 삭제는 confirm으로 물어본 뒤 store.remove 해줘. 이름과 메모는 mapView.js의 escapeHtml로 감싸줘. 그리고 main.js에서 마커 클릭과 사이드바 목록 클릭이 openDetail을 부르게 연결해줘.

Claude Code가 만들어 준 `src/detail.js`를 세 토막으로 나눠 읽겠습니다. 먼저 패널을 그리는 앞부분을 봅니다.

```js
// src/detail.js — 상세 패널: 별점·메모 편집, 삭제
import { store } from './store.js';
import { categoryOf } from './categories.js';
import { escapeHtml } from './mapView.js';
import { toast } from './sidebar.js';

let currentId = null;

export function openDetail(id) {
  const place = store.get(id);
  if (!place) return;
  currentId = id;
  const panel = document.getElementById('detail-panel');
  const cat = categoryOf(place.category);
  panel.hidden = false;
  panel.innerHTML = `
    <header>
      <h2>${cat.emoji} ${escapeHtml(place.name)}</h2>
      <button id="detail-close" title="닫기">×</button>
    </header>
    <p class="detail-cat" style="color:${cat.color}">${cat.label}</p>
    <div class="detail-stars" id="detail-stars">
      ${[1, 2, 3, 4, 5]
        .map((n) => `<button class="star ${n <= (place.rating || 0) ? 'on' : ''}" data-n="${n}">★</button>`)
        .join('')}
    </div>
    <textarea id="detail-memo" rows="4" placeholder="메모를 남겨 보세요">${escapeHtml(place.memo || '')}</textarea>
    <div class="detail-actions">
      <button id="detail-save" class="primary">저장</button>
      <button id="detail-delete" class="danger">삭제</button>
    </div>`;
```

첫 줄부터 봅시다. `store.get(id)`으로 장소 객체를 찾고, 없으면 조용히 반환합니다. 15장에서 배운 문지기 검사를 그대로 씁니다. 이미 삭제된 장소의 id가 어디선가 들어와도 앱이 깨지는 일은 막을 수 있습니다. 그다음 `panel.hidden = false`로 패널을 드러내고, `innerHTML`에 템플릿 문자열로 내용 전체를 한 번에 그려 넣습니다. 새로운 방식은 아닙니다. 12장 이후 계속 써 온 데이터를 HTML 문자열로 바꾸는 방식 그대로입니다.

별점을 그리는 줄을 자세히 보겠습니다.

```js
[1, 2, 3, 4, 5].map((n) => `<button class="star ${n <= (place.rating || 0) ? 'on' : ''}" ...>★</button>`)
```

`<button class="star">★</button>`를 다섯 번 복사해 붙이는 대신, `[1, 2, 3, 4, 5]` 배열을 `map`으로 돌려 다섯 개를 만듭니다. 각 버튼은 자기 번호 `n`을 가지고 있고, `n <= place.rating`을 만족해 자기 번호가 현재 별점 이하이면 `on` 클래스가 붙습니다. 별점이 3이면 1·2·3번 별에만 `on`이 붙어 노란색으로 표시됩니다. `place.rating || 0`은 `rating`이 `undefined`인 장소를 0점으로 처리합니다. 삼항 연산자[^1] `조건 ? 참일때 : 거짓일때`는 이렇게 클래스 이름을 고를 때 요긴하게 쓸 수 있습니다.

`data-n="${n}"`도 눈에 익을 겁니다. 15장 검색 결과의 `data-i`와 같이 번호를 달아 두는 코드이고, 잠시 뒤 클릭된 별이 몇 번째인지 알아내는 데 씁니다. 그리고 이름과 메모에 씌워진 `escapeHtml`은 아직 외부 문자열에 씌우는 함수라는 정도로만 알고 넘어가세요. 19.5절에서 이 함수를 빼면 무슨 일이 벌어지는지 눈으로 확인할 수 있습니다.

## 19.3 별점 버튼: 클릭하면 다시 그린다

`innerHTML`로 그리기가 끝나면, 이어서 방금 만든 버튼들에 동작을 붙입니다. `openDetail`의 뒷부분을 봅니다.

```js
  panel.querySelector('#detail-close').addEventListener('click', closeDetail);
  panel.querySelectorAll('.star').forEach((btn) => {
    btn.addEventListener('click', () => {
      const n = Number(btn.dataset.n);
      // 다시 그리기 전에 쓰던 메모를 잃지 않게 보관한다
      const draft = panel.querySelector('#detail-memo').value;
      store.update(id, { rating: n });
      openDetail(id); // 다시 그려서 별 반영
      panel.querySelector('#detail-memo').value = draft;
    });
  });
```

별 버튼 다섯 개를 `querySelectorAll`로 모아 하나씩 클릭 리스너를 붙입니다. 클릭되면 `btn.dataset.n`을 읽어 몇 번째 별인지 알아냅니다. `dataset` 값은 항상 문자열이므로 15장에서와 같이 `Number()`로 변환합니다. 그다음 `store.update(id, { rating: n })`로 저장소에 새 별점을 기록합니다. 17장에서 만든 `update`는 그 장소 객체에 변경된 값만 덮어쓰고 `save()`를 호출하므로, localStorage 저장까지 이 한 줄로 끝낼 수 있습니다.

그런데 뒤쪽의 `openDetail(id)`를 보면 지금 실행 중인 함수를 자기가 다시 부릅니다. 별점은 방금 3에서 5로 바뀌었는데 화면의 별들은 여전히 3개만 노랗기 때문입니다. 노란 별을 두 개 더 칠하는 코드를 따로 짤 수도 있습니다. 그래도 패널을 통째로 다시 그리는 쪽이 훨씬 단순합니다. `openDetail`은 어차피 현재 데이터를 읽어 패널을 그리는 함수이니, 데이터를 바꾼 뒤 한 번 더 부르면 바뀐 별점이 반영된 새 패널을 얻을 수 있습니다. 화면을 부분부분 손보지 않고 상태를 바꾼 다음 다시 그립니다. 14장 필터에서 익힌 단방향 흐름을 여기서도 그대로 씁니다. React 같은 프레임워크도 같은 방식으로 동작하며, 우리는 그것을 바닐라 자바스크립트로 직접 만들어 보고 있습니다.

그리고 `openDetail(id)`를 앞뒤로 감싼 두 줄은 이 방식의 부작용을 처리합니다. `draft`에 값을 보관했다가 되돌려 놓는 코드입니다. 패널을 전부 다시 그리면 textarea도 새로 만들어집니다. 메모 칸에 아직 저장하지 않은 글을 쓰던 중에 별을 누르면, 새 textarea에는 저장된 이전 메모가 들어가면서 쓰던 글이 사라질 수 있습니다. 그래서 다시 그리기 전에 textarea의 현재 값을 `draft` 변수에 담아 두고, 다시 그린 뒤에 그 값을 새 textarea에 넣습니다. 전체를 다시 그리는 단순한 구조는 유지하면서 이 부작용만 두 줄로 막았습니다.

한 가지 더 좋은 일이 공짜로 따라옵니다. `store.update`가 `save()`를 부르면, 18장에서 심어 둔 구독 패턴이 발동합니다. `main.js`의 `store.subscribe(rerender)` 덕분에 지도의 마커와 말풍선도 자동으로 다시 그려집니다. 말풍선에는 별점이 ★★★☆☆처럼 표시되고 있었는데(13장), 상세 패널에서 별을 바꾸는 순간 말풍선의 별도 함께 바뀝니다. 우리가 이번 장에서 그 연동 코드를 한 줄도 안 썼는데도요. 데이터의 길목 한 곳(`save`)에 방송국을 세워 둔 설계가 이렇게 계속 이자를 쳐서 돌아옵니다.

## 19.4 메모 저장, 그리고 confirm으로 묻는 삭제

이제 남은 두 버튼을 봅니다. 먼저 저장 버튼입니다.

```js
  panel.querySelector('#detail-save').addEventListener('click', () => {
    store.update(id, { memo: panel.querySelector('#detail-memo').value });
    toast('저장했습니다.');
  });
```

textarea의 현재 값을 읽어 `store.update`로 memo에 덮어쓰고, `toast`로 "저장했습니다."를 잠깐 띄웁니다. 이 토스트 한 줄을 우습게 보면 안 됩니다. 저장은 눈에 보이는 변화가 없는 동작이라, 알림이 없으면 사용자는 눌린 것인지 몰라 같은 버튼을 여러 번 누를지도 모릅니다. 겉으로 표시가 나지 않는 동작에는 알림을 붙여 두시는 편이 낫습니다.

다음으로 삭제 버튼을 봅니다. 여기엔 처음 보는 함수가 나옵니다.

```js
  panel.querySelector('#detail-delete').addEventListener('click', () => {
    if (confirm(`'${place.name}'을(를) 삭제할까요?`)) {
      store.remove(id);
      closeDetail();
      toast('삭제했습니다.');
    }
  });
```

`confirm`은 브라우저가 기본으로 제공하는 확인 다이얼로그를 띄웁니다. 호출하면 메시지와 [확인]·[취소] 버튼이 있는 작은 창이 뜨고, 사용자가 답할 때까지 코드 실행이 멈춥니다. 확인을 누르면 `true`, 취소를 누르면 `false`가 돌아옵니다. 그래서 `if (confirm(...))` 안에 삭제 코드를 넣으면, 취소를 누른 경우엔 아무 일도 일어나지 않습니다.

확인 창을 두는 이유가 있습니다. 별점 변경은 다시 누르면 되고 메모도 다시 쓰면 되지만, 한번 삭제한 장소를 되살릴 수는 없습니다. `store.remove`가 실행되고 `save()`가 localStorage를 덮어쓰면 그 장소 데이터는 남지 않습니다. 이 앱에는 실행 취소 기능도 없습니다. 그래서 되돌릴 수 없는 동작 앞에서는 한 번 더 물어보는 편이 좋습니다. 파일을 지울 때나 회원 탈퇴를 할 때 나오는 확인 창이 하는 일도 이와 같습니다. 메시지에 `place.name`을 넣은 것도 일부러 그렇게 했습니다. "삭제할까요?"보다 "'성수동 국밥집'을(를) 삭제할까요?"가 무엇을 지우는지 확인할 수 있어 실수를 줄여 줍니다.

확인을 눌렀다면 세 줄이 차례로 실행됩니다. `store.remove(id)`로 데이터에서 지우면 구독 패턴이 마커와 목록도 함께 치워 줍니다. 그다음 `closeDetail()`로 패널을 닫고, 토스트로 결과를 알립니다. `closeDetail`은 파일 끝에 있는 짧은 함수입니다.

```js
export function closeDetail() {
  const panel = document.getElementById('detail-panel');
  panel.hidden = true;
  currentId = null;
}
```

`hidden`을 되돌리고, "지금 열려 있는 장소" 기억(`currentId`)을 비웁니다. 열 때 `currentId = id`로 적어 두고 닫을 때 지우는 이 변수는, 나중에 다른 모듈이 지금 상세 패널에 어떤 장소가 떠 있는지 물어볼 때 쓸 수 있습니다.

마지막으로 연결합니다. Claude Code가 `main.js`에서 두 곳을 `openDetail`로 이어 붙였습니다.

```js
import { openDetail } from './detail.js';
// ...
setMarkerClickHandler((id) => openDetail(id));   // 마커 클릭 → 상세
initSidebar({
  onSelectPlace: (id) => {
    const p = store.get(id);
    if (p) {
      focusPlace(p);      // 지도 이동 + 말풍선 (18장)
      openDetail(id);     // 상세 패널도 함께
    }
  },
  // ...
});
```

마커를 클릭해도, 사이드바 목록을 클릭해도 같은 상세 패널이 열립니다. 입구는 여러 개입니다. 그렇다고 함수까지 여러 개인 것은 아닙니다. 16장에서 추가 다이얼로그를 재사용했던 것과 같은 방식입니다.

## 19.5 XSS: 입력값이 HTML로 해석될 때

이제 미뤄 둔 숙제를 풉니다. 15장부터 코드 곳곳에 등장한 `escapeHtml`, 도대체 왜 씌우는 걸까요? 백문이 불여일견, 직접 공격을 해 보면서 배웁시다.

우리 앱에서 사용자가 입력한 문자열이 `innerHTML`로 들어가는 곳은 장소 이름과 메모입니다. 16장의 추가 다이얼로그에서 이름을 아무거나 적을 수 있었습니다. 그럼 이름에 글자 대신 HTML 태그를 적으면 어떻게 될까요? 지도를 클릭해 추가 다이얼로그를 열고, 이름 칸에 이렇게 넣어 보세요.

```
<b>굵은 국밥집</b>
```

저장한 뒤 상세 패널을 열어 봅니다. 우리 앱에서는 `<b>굵은 국밥집</b>`이라는 글자가 꺾쇠까지 그대로 보입니다. `escapeHtml`이 동작했기 때문입니다. 이 처리가 없었다면 `innerHTML`이 문자열 속 `<b>`를 글자가 아니라 태그로 해석해서, 패널에 굵은 글씨로 표시됐을 겁니다. 사용자가 입력한 문자열이 앱의 HTML 구조에 들어간 것입니다.

"글씨 좀 굵어지는 게 뭐 어때서?"라고 생각할 수 있습니다. 문제는 그다음에 있습니다. 태그로 할 수 있는 일이 굵은 글씨 정도인 것은 아닙니다. 이런 이름은 어떨까요.

```
<img src=x onerror="alert('해킹!')">
```

깨진 이미지 태그입니다. 브라우저는 `x`라는 이미지를 못 찾으니 `onerror`에 적힌 자바스크립트를 실행합니다. `escapeHtml`이 없는 앱이라면 이런 이름의 장소를 여는 순간 경고창이 뜨는 것을 볼 수 있습니다. 장소 이름을 그렸을 뿐인데 남이 쓴 코드가 내 브라우저에서 돌아간 것입니다. 이런 공격을 XSS라고 부르고, 우리말로는 교차 사이트 스크립팅[^2]이라고 옮깁니다. 웹에서 가장 오래되고 가장 흔한 공격에 속합니다.

![XSS 공격의 원리: 입력이 코드가 되는 순간](images/ch19/ch19-f05.png){ width="760" }
/// caption
그림 19.5 — XSS 공격의 원리: 입력이 코드가 되는 순간
///

내 지도에 내가 이상한 이름을 넣어 봤자 피해자는 나뿐이라고 생각할 수 있습니다. 지금 우리 앱은 데이터가 내 브라우저 안에만 있으니, 틀린 말은 아닙니다. 하지만 함께 생각해 볼 점이 있습니다. 먼저 17장에서 만든 가져오기 기능으로 다른 사람이 만든 JSON 파일을 불러올 수 있고, 그 파일 속 장소 이름에 공격 코드가 들어 있을 수 있습니다. 15장의 검색 결과도 외부에서 온 데이터이므로 함께 검증해야 합니다. 그리고 나중에 이 앱에 서버를 붙여 여러 사람이 장소를 공유하게 되면, 한 사람이 넣은 공격 코드가 모든 방문자의 브라우저에서 실행될 수 있습니다. 실제 XSS 사고는 대부분 이렇게 발생합니다. 방명록, 댓글, 닉네임에 들어간 스크립트가 그 페이지를 여는 모든 사람에게 실행되는 것입니다.

참고로 우리 앱이 이스케이프 하나로만 방어하는 것은 아닙니다. 17장에서 store에 만든 `normalize` 함수가 한 겹 더 막아 줍니다. 가져오기 파일이 들어오면 이름과 좌표만이 아니라 `id`까지 검사해서, 영문·숫자·밑줄·하이픈으로만 된 id가 아니면 새 id로 교체합니다. id는 화면에 보이지 않는 값이라 놓치기 쉽지만, `data-id="${p.id}"`처럼 HTML 속성에 넣는 코드가 있으면 공격 통로가 될 수 있습니다. 데이터가 들어올 때 `normalize`로 검증하고, 화면에 출력할 때 `escapeHtml`로 이스케이프하는 두 단계를 모두 둡니다. 한쪽에서 놓친 값을 다른 쪽에서 걸러 낼 수 있기 때문입니다.

그래서 원칙은 이렇게 외웁니다. 사용자(또는 외부)가 만든 문자열을 innerHTML에 넣을 때는 반드시 이스케이프한다. `escapeHtml`은 `mapView.js`에 있는 여섯 줄짜리 함수입니다.

```js
// src/mapView.js — HTML 특수문자를 무해한 표기로 바꾼다
export function escapeHtml(s = '') {
  return s.replace(/[&<>"']/g, (c) => ({
    '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;',
  })[c]);
}
```

정규식 `/[&<>"']/g`로 HTML에서 특별한 의미를 갖는 다섯 글자를 전부(`g`) 찾아, 각각을 HTML 엔티티라는 표기로 바꿉니다. `<`는 `&lt;`로, `>`는 `&gt;`로 바뀝니다. 브라우저는 `&lt;`를 만나면 태그의 시작이 아니라 `<`라는 글자로 표시합니다. 태그로 해석될 여지를 없애 줍니다.

| 원래 글자 | 바뀐 표기 | HTML에서의 원래 의미 |
|---|---|---|
| `&` | `&amp;` | 엔티티의 시작 |
| `<` | `&lt;` | 태그 열기 |
| `>` | `&gt;` | 태그 닫기 |
| `"` | `&quot;` | 속성값 따옴표 |
| `'` | `&#39;` | 속성값 따옴표 |

이제 15장에서 미뤄 둔 이야기를 마무리할 수 있습니다. 검색 결과의 `place_name`, 상세 패널의 `place.name`과 `place.memo`, 13장 말풍선의 이름까지, 외부에서 온 문자열이 `innerHTML`을 통과하는 모든 길목에 우리 앱은 이미 이 함수를 세워 뒀습니다. 앞에서 `<b>굵은 국밥집</b>`을 넣었을 때 태그가 글자 그대로 보인 것도 그래서입니다.

![escapeHtml 덕분에 태그가 글자 그대로 표시된 상세 패널](images/ch19/ch19-f06.jpg){ width="760" }
/// caption
그림 19.6 — escapeHtml 덕분에 태그가 글자 그대로 표시된 상세 패널
///

!!! warning "주의"
    `textarea` 안에 값을 넣을 때도 이스케이프가 필요합니다. "textarea는 입력칸이니까 괜찮겠지"라고 생각하기 쉽지만, 입력칸 안이라고 해서 안전한 것은 아닙니다. 메모에 `</textarea>`라는 문자열이 들어 있으면 브라우저가 입력칸을 거기서 닫아 버리고 나머지를 HTML로 해석합니다. 우리 코드가 `${escapeHtml(place.memo || '')}`로 감싼 이유가 여기에 있습니다. innerHTML로 들어가는 외부 문자열은 예외 없이 전부 이스케이프합니다.

!!! tip "팁"
    이스케이프 말고 근본적으로 안전한 길도 있습니다. `el.textContent = place.name`처럼 textContent에 넣으면 브라우저가 처음부터 순수한 글자로만 취급하므로 XSS가 원천 차단됩니다. 다만 우리처럼 템플릿 문자열로 HTML 구조를 통째로 조립할 때는 쓸 수 없어서, 구조는 innerHTML로 만들되 끼워 넣는 값마다 escapeHtml을 씌우는 쪽을 택했습니다. 규모가 커지면 React 같은 프레임워크가 이 문제를 자동으로 처리해 줍니다. AI가 짜 준 코드를 검토할 때 사용자 입력이 innerHTML에 그대로 들어가는 곳이 없는지 물어보는 습관을 들이세요. 바이브코딩으로 만든 코드라고 해서 보안 검토까지 AI에게 맡길 수는 없습니다.

## 19.6 실행 확인

전체 흐름을 점검해 봅시다. 브라우저를 새로고침하고 순서대로 해 보세요.

1. 마커를 클릭: 말풍선과 함께 오른쪽 위에 상세 패널이 열립니다.
2. 별 다섯 번째를 클릭: 별 5개가 노래지고, 말풍선의 별도 함께 바뀝니다.
3. 메모를 적고 저장: "저장했습니다." 토스트가 뜹니다. 새로고침해도 메모가 남아 있는지 꼭 확인하세요. 17장의 localStorage가 동작하고 있다는 뜻입니다.
4. 사이드바 목록에서 다른 장소 클릭: 지도가 이동하며 패널 내용이 그 장소로 바뀝니다.
5. 삭제 버튼 → 취소: 아무 일도 없습니다. 다시 삭제 → 확인을 누르면 패널이 닫히고 마커와 목록에서도 사라집니다.
6. 지도를 클릭해 이름이 `<b>테스트</b>`인 장소를 추가: 상세 패널과 말풍선에 태그가 글자 그대로 보이면 이스케이프가 제대로 동작하고 있습니다.

여기까지 하면 추가·저장·목록·상세·삭제가 모두 갖춰져 CRUD가 완성됩니다. PLAN의 마일스톤 M5까지 왔습니다. 이제 이 지도를 매일 열어 쓸 수 있습니다.
