# 9장 첫 지도 띄우기

!!! note "이 장에서 배우는 것"
    - `script` 태그로 외부 SDK를 불러오는 원리와, 동적 로드가 필요한 이유를 이해합니다
    - `autoload=false`와 `kakao.maps.load()`가 왜 필요한지 배웁니다
    - Claude Code에게 시켜 SDK 로더 모듈(`loader.js`)을 만들고 함께 읽습니다

7장에서 JavaScript 키를 발급받았고, 8장에서 Vite 프로젝트를 만들고 키를 `.env`에 넣어 두었습니다. 이번 장이 끝나면 브라우저 화면 가득 카카오지도가 뜹니다. 마우스로 끌면 지도가 움직이고 휠을 굴리면 골목까지 확대됩니다. 카카오맵 앱에서 보던 지도가 여러분의 웹페이지 안에서 동작합니다.

지금까지는 설치하고 가입하고 설정하는 준비 과정이었고, 이번 장부터 만듭니다. 코드는 Claude Code가 작성하고 우리는 시키고, 읽고, 확인합니다. 이번 장의 코드는 몇 줄 안 되지만 그 안에서 외부 스크립트 로드, 비동기 대기, 좌표계를 함께 다룹니다.

## 9.1 SDK: 카카오가 미리 만들어 둔 지도 기능 모음

지도를 직접 만들려면 전 세계 도로 데이터를 구하고, 확대 단계마다 타일 이미지를 준비하고, 마우스 드래그를 계산해야 합니다. 개인이 할 수 있는 일이 아닙니다. 카카오는 이 모든 것을 SDK[^1]라는 이름의 자바스크립트 파일 하나로 제공합니다.

카카오지도 JavaScript SDK 파일에 지도 기능이 모여 있습니다. 이 파일 하나만 불러오면 됩니다. 이 파일을 우리 페이지에 불러오면 `kakao.maps` 아래에서 지도를 만드는 `Map`, 좌표를 다루는 `LatLng`, 마커를 찍는 `Marker` 등을 쓸 수 있습니다. 우리는 이 기능들을 불러 쓰기만 하면 됩니다.

그럼 이 파일을 어떻게 불러올까요? 웹페이지가 외부 자바스크립트를 불러오는 표준 방법은 HTML의 `script` 태그입니다. 카카오 공식 문서에도 처음에는 이런 방법이 나옵니다.

```html
<!-- 방법 1: index.html에 직접 적기 (우리는 이 방법을 안 씁니다) -->
<script src="https://dapi.kakao.com/v2/maps/sdk.js?appkey=0123abcd4567efgh8901ijkl2345mnop"></script>
```

주소 뒤에 `?appkey=...`가 붙어 있습니다. 7장에서 배운 대로 카카오 서버는 요청마다 키를 확인합니다. `script` 태그로 SDK를 요청할 때는 주소의 물음표 뒷부분에 키를 적어 함께 보냅니다. 이 부분을 쿼리 문자열이라고 부릅니다.

간단해 보이지만 이 방법은 쓰지 않습니다. 위 코드를 보면 키가 HTML에 그대로 적혀 있기 때문입니다. 8장에서 키를 `.env` 파일에 넣고 `.gitignore`로 GitHub에 올라가지 않게 막았는데, HTML에 키를 직접 적으면 그 조치가 무의미해집니다. `index.html`은 GitHub에 올라가는 파일입니다.

HTML에서도 `.env`를 읽으면 되지 않느냐고 생각할 수 있지만, HTML은 변수를 읽지 못합니다. `import.meta.env.VITE_KAKAO_JS_KEY`는 자바스크립트 안에서만 동작합니다.

그래서 두 번째 방법인 동적 로드를 씁니다. HTML에 `script` 태그를 미리 적어 두는 대신, 자바스크립트 코드가 실행되는 시점에 `script` 태그를 코드로 만들어 페이지에 넣습니다. 자바스크립트 안에서는 `.env`의 키를 읽어 주소에 끼워 넣을 수 있습니다. 두 방법을 비교하면 아래와 같습니다.

| | 방법 1: HTML에 직접 | 방법 2: 동적 로드 (우리의 선택) |
|---|---|---|
| 적는 곳 | `index.html` | 자바스크립트 파일 |
| 키 처리 | HTML에 그대로 노출 | `.env`에서 읽어서 끼움 |
| 코드 관리 | GitHub에 키가 올라감 | 키 없는 코드만 올라감 |

## 9.2 autoload=false: 다운로드 완료와 사용 준비 완료는 다르다

동적 로드에는 주의할 점이 하나 있습니다. SDK 파일 다운로드가 끝났다고 해서 지도를 만들 준비까지 끝난 것은 아니라는 점입니다.

파일이 도착한 뒤에도 SDK가 지도 모듈을 준비하는 초기화 작업이 한 단계 더 남습니다. 이 준비가 끝나기 전에 `new kakao.maps.Map(...)`으로 지도를 만들려 하면 에러가 납니다. 그런데 이 에러는 날 때도 있고 안 날 때도 있습니다. 네트워크가 빠르면 초기화가 먼저 끝나서 잘 동작하고, 느리면 실패합니다. 이렇게 실행 시점의 속도에 따라 결과가 달라지는 코드는 원인을 찾기 어렵습니다.

카카오는 이 문제를 위한 옵션을 제공합니다. SDK 주소 뒤에 `autoload=false`를 붙이는 것입니다. 파일이 도착해도 자동으로 초기화하지 말라는 뜻입니다. 그 대신 우리가 원하는 시점에 `kakao.maps.load(콜백)`을 부르면 SDK가 초기화를 시작하고, 초기화가 끝난 순간 우리가 넘긴 콜백 함수[^2]를 실행합니다. 순서를 그림으로 그리면 이렇습니다.

SDK를 불러오는 순서는 이렇습니다. 자바스크립트로 `script` 태그를 만들어 페이지에 넣습니다. 주소에는 `.env`에서 읽은 키와 `autoload=false`를 붙입니다. 그리고 `kakao.maps.load()`의 콜백 안에서만 지도를 만듭니다. 이제 코드로 옮깁니다.

## 9.3 Claude Code에게 로더 만들게 하기

프로젝트 폴더에서 `claude`를 실행해 Claude Code를 열고 다음과 같이 요청합니다. 4장에서 배운 프롬프트 4요소(맥락·목표·제약·출력)를 담았습니다.

!!! tip "이렇게 물어보세요"
    > 카카오지도 JS SDK를 동적으로 불러오는 모듈을 src/loader.js로 만들어줘. 키는 .env의 VITE_KAKAO_JS_KEY에서 읽고, autoload=false로 받아서 kakao.maps.load()가 끝나면 resolve되는 Promise를 반환해줘. 키가 없거나 로드에 실패하면 이유를 알 수 있는 에러로 reject해줘.

잠시 후 Claude Code가 파일을 만들고 결과를 보여 줍니다. 아래는 이 장 시점의 `src/loader.js` 전문입니다. 이 파일은 앞으로 두 번 더 바뀝니다. 검색을 만드는 15장에서 `services`를 추가하고, 마커를 묶는 22장에서 `clusterer`를 추가하면 최종 형태가 됩니다.

```javascript
// 카카오 지도 SDK를 동적으로 불러오는 모듈
// autoload=false로 받아서 kakao.maps.load() 콜백 안에서 지도를 만든다.
export function loadKakaoSdk() {
  return new Promise((resolve, reject) => {
    const key = import.meta.env.VITE_KAKAO_JS_KEY;
    if (!key) {
      reject(new Error('VITE_KAKAO_JS_KEY가 .env에 없습니다.'));
      return;
    }
    const script = document.createElement('script');
    script.src =
      `https://dapi.kakao.com/v2/maps/sdk.js?appkey=${key}` +
      `&autoload=false`;
    script.onload = () => kakao.maps.load(() => resolve(kakao));
    script.onerror = () => reject(new Error('카카오 SDK 로드 실패 — 키/도메인 확인'));
    document.head.appendChild(script);
  });
}
```

코드는 열여덟 줄입니다. 위에서부터 읽어 봅시다.

`export function loadKakaoSdk()`에서 이 파일이 밖으로 공개하는 함수를 선언합니다. `export`를 붙였으므로 다른 파일에서 `import`해서 쓸 수 있습니다. SDK 불러오기만 담당하는 파일로 분리해 두면, 나중에 지도 코드가 커져도 로드 관련 문제는 이 파일만 확인하면 됩니다.

`return new Promise((resolve, reject) => {...})`가 Promise를 만들어 반환합니다. Promise는 지금 끝나지 않은 일의 결과를 나중에 알려 줍니다. SDK 다운로드는 네트워크를 거치므로 얼마나 걸릴지 미리 알 수 없습니다. 그래서 함수가 결과 대신 Promise를 반환하고, 일이 끝나면 `resolve`를, 실패하면 `reject`를 호출합니다. 이 Promise를 받는 쪽에서 `await loadKakaoSdk()`라고 쓰면 결과가 나올 때까지 기다렸다가 다음 줄로 넘어갑니다. 다음 절에서 실제로 그렇게 씁니다.

`const key = import.meta.env.VITE_KAKAO_JS_KEY;`는 8장에서 다룬 코드입니다. Vite가 `.env` 파일에서 읽어 둔 키를 꺼냅니다. 바로 아래 `if (!key)`에서 키가 비어 있는 경우를 처리합니다. 키가 없으면 지도는 어차피 뜨지 않는데, 카카오 서버가 보내는 에러 대신 "VITE_KAKAO_JS_KEY가 .env에 없습니다"라는 문장이 표시되므로 원인을 바로 알 수 있습니다.

`document.createElement('script')`부터 `document.head.appendChild(script)`까지가 9.1절에서 설명한 동적 로드를 실제로 수행합니다. `script` 태그를 코드로 만들고, `src` 주소에 키를 끼워 넣고, 마지막 줄에서 페이지의 `<head>`에 넣습니다. 넣는 순간 브라우저가 다운로드를 시작합니다.

`&autoload=false`는 9.2절에서 배운 대로 자동 초기화를 막습니다. 지금 주소에는 키와 이 옵션만 붙어 있지만, 앞으로 두 번 더 늘어납니다. 장소 검색을 만드는 15장에서 `services`를, 마커를 묶는 22장에서 `clusterer`를 `&libraries=` 옵션으로 추가합니다. 필요한 시점에 필요한 라이브러리만 불러오는 방식으로 씁니다.

`script.onload = () => kakao.maps.load(() => resolve(kakao));`가 이 파일에서 가장 중요한 줄입니다. 괄호가 겹쳐 있어 읽기 어렵다면 시간 순서로 풀어 보세요. `onload`로 파일 다운로드가 끝난 것을 확인하고, `kakao.maps.load`로 SDK 초기화를 시작하고, 초기화까지 끝나면 `resolve`를 호출합니다. 다운로드와 초기화를 모두 기다린 뒤에 Promise가 완료되므로, 이 함수를 `await`한 다음 줄에서는 지도를 만들어도 됩니다.

`script.onerror = () => reject(...)`는 다운로드 자체가 실패했을 때 Promise를 실패로 처리합니다. 인터넷이 끊겼거나 키가 잘못된 경우가 여기에 해당하며, "키/도메인 확인"이라는 안내를 함께 남깁니다. 이 문구는 9.7절 트러블슈팅에서 씁니다.

!!! warning "주의"
    `onerror`는 모든 실패를 잡아내지 못합니다. 파일 다운로드가 네트워크 수준에서 실패했을 때만 호출됩니다. 광고 차단 확장 프로그램이나 CSP 보안 정책이 스크립트를 막는 경우, 또는 `kakao.maps.load()`의 콜백이 호출되지 않는 경우에는 에러 없이 Promise가 계속 대기 상태로 남습니다. 그러면 앱이 멈춘 것처럼 보입니다. 지도가 뜨지도 않고 에러도 없으면 콘솔과 함께 Network 탭에서 `dapi.kakao.com` 요청이 성공했는지 확인하세요. 심화 과제로 "일정 시간 안에 로드가 안 끝나면 실패로 처리하는 타임아웃과, 두 번 호출해도 스크립트가 중복 삽입되지 않는 장치를 넣어줘"라고 Claude Code에게 시켜 보세요.

!!! tip "팁"
    Claude Code가 만들어 준 코드가 책과 똑같을 필요는 없습니다. 변수 이름이나 에러 메시지 문구가 달라도, Promise 반환, `.env`에서 키 읽기, `autoload=false`, `load` 콜백에서 `resolve` 이 네 가지가 들어 있으면 같은 동작을 합니다. 다르게 나온 부분이 궁금하면 "왜 이렇게 짰어?"라고 물어보세요.

## 9.4 지도가 들어갈 자리: index.html의 #map

SDK를 불러올 준비가 됐으니 이제 지도를 어디에 그릴지 정합니다. 카카오 SDK는 지도를 그릴 HTML 요소 하나를 지정받아야 하고, 보통 `id="map"`을 붙인 `div`를 씁니다. 이 장 시점의 `index.html`은 다음과 같습니다.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>나만의 지도</title>
  </head>
  <body>
    <div id="app">
      <div id="map"></div>
    </div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

`<div id="map"></div>`가 지도를 그릴 자리를 잡아 둡니다. 지금은 비어 있지만 잠시 후 자바스크립트가 이 안을 지도 타일로 채웁니다. 앞으로 장이 진행되면서 이 HTML에 사이드바, 검색창, 상세 패널이 하나씩 늘어나지만 기본 구조는 지금 만드는 형태를 그대로 유지합니다.

여기서 자주 겪는 문제를 미리 짚고 넘어갑시다. 빈 `div`의 높이는 0입니다. HTML의 `div`는 내용물 높이만큼만 커지는데, 내용이 없으므로 높이도 0이 됩니다. 높이가 0인 요소에 지도를 그리면 지도 객체는 정상적으로 만들어지지만 화면에는 아무것도 보이지 않습니다. 에러도 나지 않고 하얀 화면만 나옵니다. 그래서 CSS로 요소의 크기를 지정해야 합니다. `src/style.css`에 들어갈 규칙입니다.

```css
html, body, #app, #map {
  height: 100%;
  margin: 0;
}
```

화면 전체 높이를 `html`부터 `#map`까지 차례로 물려준다는 뜻입니다. `#map`에만 `height: 100%`를 주면 되지 않느냐고 생각할 수 있지만, 그렇게 하면 동작하지 않습니다. CSS의 `100%`는 부모 요소 높이의 100%를 의미하므로, 부모(`#app`), 그 부모(`body`), 그 부모(`html`)까지 모두 100%여야 화면 전체 높이가 됩니다. 중간에 하나라도 빠지면 높이가 다시 0이 됩니다. 이 문제는 9.7절에서 다시 다룹니다.

## 9.5 지도 생성 3요소: 컨테이너, center, level

이제 지도를 실제로 만드는 코드를 작성합니다. Claude Code에게 이어서 시킵니다.

!!! tip "이렇게 물어보세요"
    > src/main.js를 앱 진입점으로 만들어줘. loader.js의 loadKakaoSdk를 await로 기다렸다가, 성공하면 #map에 서울시청 중심(레벨 7)의 지도를 만들어줘. SDK 로드에 실패하면 #map 안에 실패 이유를 보여줘.

Claude Code가 만들어 준 `src/main.js`입니다. 아래는 이 장 진도에 맞춘 모습입니다. 장이 진행되면 이 파일에 사이드바와 검색 관련 코드가 늘어나지만, SDK를 기다렸다가 지도를 만드는 구조는 끝까지 그대로입니다.

```javascript
// 앱 진입점 — SDK를 기다렸다가 지도를 만든다
import './style.css';
import { loadKakaoSdk } from './loader.js';

async function main() {
  try {
    await loadKakaoSdk();
  } catch (e) {
    document.getElementById('map').innerHTML =
      `<p class="sdk-error">지도를 불러오지 못했습니다.<br>${e.message}</p>`;
    return;
  }

  const map = new kakao.maps.Map(
    document.getElementById('map'),          // ① 컨테이너: 어디에
    {
      center: new kakao.maps.LatLng(37.5665, 126.978), // ② 어디를 중심으로
      level: 7,                                        // ③ 얼마나 확대해서
    }
  );
}

main();
```

`async function main()`과 `await loadKakaoSdk()`에서 9.3절에서 만든 Promise를 받습니다. `await`는 async 함수 안에서만 쓸 수 있어서 `main`에 `async`를 붙였습니다. 이 한 줄이 SDK 초기화 완료까지 기다리므로, 그 아래에서는 `kakao.maps`를 바로 쓸 수 있습니다.

`try { ... } catch (e) { ... }`는 Promise가 `reject`로 실패했을 때를 처리합니다. 에러를 그냥 넘기지 않고, 지도 자리에 "지도를 불러오지 못했습니다"와 실패 이유를 표시합니다. 사용자는 무엇이 잘못됐는지 알 수 있고, 개발자는 `e.message`에 담긴 내용으로 원인을 좁힐 수 있습니다. 키가 없는 경우와 로드가 실패한 경우가 구분되어 들어옵니다.

그다음이 `new kakao.maps.Map(컨테이너, 옵션)`입니다. 지도 하나를 만들려면 아래 항목을 지정해야 합니다.

컨테이너에는 지도를 그릴 HTML 요소를 넣습니다. `document.getElementById('map')`으로 9.4절에서 만든 빈 요소를 찾아 건넵니다.

center에는 지도가 처음 열릴 때 화면 한가운데에 올 지점을 넣습니다. 좌표는 `kakao.maps.LatLng(위도, 경도)`로 만듭니다. LatLng라는 이름은 위도를 뜻하는 Latitude와 경도를 뜻하는 Longitude를 합친 것이고, 지구 위의 한 점을 숫자 두 개로 나타냅니다. 위도는 적도를 0으로 두고 남북 방향 위치를 나타내며 북쪽으로 갈수록 커집니다. 경도는 영국 그리니치를 0으로 두고 동서 방향 위치를 나타냅니다. 서울시청의 좌표는 위도 37.5665, 경도 126.978입니다. 대한민국 안이라면 위도는 대략 33~38, 경도는 124~132 사이에 들어갑니다. 각자의 동네 좌표를 얻는 방법은 12장에서 다루므로 여기서는 서울시청을 씁니다.

    `LatLng`는 이름 그대로 위도가 먼저, 경도가 나중입니다. 순서를 바꿔 `LatLng(126.978, 37.5665)`라고 쓰면 에러 없이 지도가 뜨지만 중심이 서울이 아니라 바다 위가 됩니다. 지도가 떴는데 화면이 온통 파란색이면 위도와 경도의 순서를 확인하세요.

level에는 확대 단계를 넣습니다. 숫자가 작을수록 확대되어 1에서는 건물 하나가 크게 보이고, 숫자가 클수록 축소되어 14에서는 한반도 전체가 보입니다. 숫자가 커질수록 더 넓은 범위가 화면에 담깁니다. 레벨 7로 두면 도시의 여러 동네가 한 화면에 들어옵니다. 레벨은 다음 장에서 직접 바꿔 보며 익힙니다.

## 9.7 트러블슈팅: 지도가 안 뜰 때 확인하는 순서

첫 지도는 확인할 것이 많아서 문제가 자주 생깁니다. 카카오 콘솔의 설정, `.env`의 키, CSS 높이, SDK 타이밍 중 하나만 어긋나도 지도가 뜨지 않습니다. 증상별로 원인이 거의 정해져 있으니 위에서부터 순서대로 확인하세요.

증상 1. 화면이 하얗게 비어 있고 에러도 나오지 않습니다. 대부분 9.4절에서 다룬 대로 `#map`의 높이가 0입니다. 개발자 도구의 Elements 탭에서 `#map`을 클릭해 보세요. 요소는 있는데 크기가 `너비×0`으로 나오면 이 경우에 해당합니다. `html, body, #app, #map`에 `height: 100%`가 빠진 곳이 없는지 `style.css`를 점검하세요. 지도를 만든 뒤에 높이가 생긴 경우라면 새로고침으로 해결됩니다.

증상 2. 콘솔이나 Network 탭에 `401`이 찍힙니다. 가장 흔한 원인은 카카오 서버가 키를 인정하지 않은 경우입니다. 점검 순서는 이렇습니다. ① `.env`의 변수 이름이 정확히 `VITE_KAKAO_JS_KEY`인지 확인합니다. `VITE_` 접두사가 없으면 Vite가 읽지 않습니다. ② 값이 JavaScript 키가 맞는지 확인합니다. REST API 키를 붙여 넣는 경우가 많으니 7장의 플랫폼 키 화면에서 다시 확인하세요. ③ 키 앞뒤에 따옴표나 공백이 붙지 않았는지 봅니다. ④ `.env`를 고쳤으면 개발 서버를 껐다 켰는지 확인합니다. Vite는 `.env`를 서버 시작 시점에 한 번만 읽습니다. 터미널에서 `Ctrl+C`로 끄고 `npm run dev`로 다시 켜세요.

증상 3. 콘솔이나 Network 탭에 `403`이 찍힙니다. 가장 흔한 원인은 키는 맞지만 요청이 출발한 주소가 등록되어 있지 않은 경우입니다. 7장에서 배운 도메인 제한이 동작한 것입니다. 참고로 401을 키 문제, 403을 도메인 문제로 나누는 것은 공식 분류가 아니라 가장 흔한 원인을 정리한 것입니다. 어느 쪽이든 Network 탭에서 실패한 요청을 클릭해 실제 요청 URL과 응답을 확인하고 시작하세요. developers.kakao.com에서 전체 앱 → 내 앱 → 앱 > 플랫폼 키 → JavaScript 키로 들어가, JavaScript SDK 도메인에 `http://localhost:5173`이 있는지 확인하세요. 있는데도 403이 나오면 오타를 확인해야 합니다. 프로토콜은 `http`와 `https` 중 하나만 등록해도 양쪽에서 인정되지만, 호스트와 포트는 정확히 일치해야 합니다. 포트가 `5173`이 아닌 경우가 가장 많습니다. 8장에서 다룬 대로 5173이 사용 중이면 Vite가 5174를 쓰므로, 그때는 5174도 등록해야 합니다. 호스트 철자가 다르거나 주소 끝에 `/`가 더 붙은 경우도 있습니다.

증상 4: "지도를 불러오지 못했습니다: VITE_KAKAO_JS_KEY가 .env에 없습니다." loader.js에 넣어 둔 확인 코드가 동작한 것입니다. `.env` 파일이 프로젝트 최상위 폴더(package.json 옆)에 있는지, 파일 이름이 `.env.txt`처럼 되어 있지는 않은지 확인하고 서버를 다시 시작하세요.

증상 5: 회색 바탕만 있고 지도 타일이 안 나온다. 지도 객체는 만들어졌는데 타일을 받지 못했거나, 크기가 0인 요소에 지도를 그린 뒤 나중에 요소가 커진 경우입니다. 먼저 Network 탭에서 실패한 요청이 있으면 증상 2와 3의 방법을 따르세요. 통신에 문제가 없는데 회색이라면 요소 크기가 나중에 바뀐 경우이니 새로고침해 보고, 그래도 반복되면 지도 컨테이너 크기가 바뀐 뒤 `relayout`을 호출해야 하는 경우입니다. 사이드바를 접었다 펴는 23장에서 다룹니다.

위의 방법으로 해결되지 않으면 에러를 Claude Code에게 그대로 보여 주는 방법이 있습니다.

!!! tip "이렇게 물어보세요"
    > 지도가 안 떠. 브라우저 콘솔에 이런 에러가 나와. 원인을 찾아서 고쳐줘. 카카오 콘솔 설정 문제라면 뭘 확인해야 하는지 알려줘. 에러 내용은 이거야: 콘솔의 빨간 에러 메시지를 그대로 붙여 넣습니다

    디버깅할 때는 에러 메시지를 요약하지 말고 그대로 붙여 넣으세요. "지도가 안 떠"라는 설명보다 에러 원문 한 줄에 훨씬 많은 정보가 들어 있습니다. 코드 문제라면 Claude Code가 직접 고치고, 카카오 콘솔 설정 문제라면 확인할 화면을 알려 줍니다.

!!! warning "주의"
    401이나 403을 해결하는 과정에서 키를 채팅창이나 커뮤니티에 그대로 붙여 넣지 않도록 주의하세요. 에러 메시지에는 키가 들어 있지 않지만, `.env` 내용이나 SDK 요청 URL 전체를 복사하면 키가 함께 들어갑니다. 질문할 때는 키 부분을 `0123abcd...`처럼 가리세요.

## 9.8 마무리

이번 장에서 첫 기능을 만들었습니다. Claude Code에게 시켜 SDK를 동적으로 불러오는 `loader.js`를 만들었고, `autoload=false`와 `kakao.maps.load()`로 초기화 타이밍 문제를 해결했으며, 컨테이너·center·level 세 가지로 지도를 띄웠습니다. 그리고 지도가 뜨지 않는 다섯 가지 상황의 확인 방법도 정리했습니다.

아직 마커가 없는 지도이지만, 앞으로 이 위에 장소가 표시되고 말풍선이 열리고 필터와 검색이 붙습니다. 이번 장에서 만든 `loader.js`와 `main.js`가 그 바탕이 됩니다.

!!! abstract "이 장의 핵심"
    - SDK는 카카오가 만들어 둔 지도 기능 모음이며, `kakao.maps` 아래의 기능을 불러 지도를 만듭니다.
    - HTML에 `script` 태그를 직접 적으면 키가 노출되므로, 자바스크립트에서 `.env`의 키를 읽어 `script` 태그를 만들어 넣는 동적 로드를 씁니다.
    - 파일 다운로드가 끝나도 사용 준비가 끝난 것은 아닙니다. `autoload=false`로 자동 초기화를 막고, `kakao.maps.load()` 콜백 안에서만 지도를 만듭니다.
    - `loader.js`는 이 과정을 Promise로 감싸므로, `await loadKakaoSdk()` 한 줄로 준비 완료까지 기다릴 수 있습니다.
    - 지도를 만들 때 컨테이너, center, level을 지정합니다. 컨테이너로 쓰는 `#map` div에는 CSS 높이를 반드시 지정하고, center에는 `LatLng(위도, 경도)` 순서로 좌표를 넣고, level은 숫자가 작을수록 확대됩니다.
    - 화면이 비어 있으면 `#map` 높이가 0인지 봅니다. 401이면 `VITE_` 접두사와 JS 키를 확인하고 서버를 다시 시작합니다. 403이면 JavaScript 키의 SDK 도메인에 `http://localhost:5173`이 등록됐는지 확인합니다. 이 구분은 가장 흔한 원인을 정리한 것이므로 Network 탭의 실패 요청도 함께 봅니다.

!!! info "더 찾아보기"
    - `async/await` — Promise를 기다리는 문법의 나머지 이야기. `Promise.all`로 여러 약속을 동시에 기다리는 법도 있습니다.
    - `쿼리 문자열(query string)` — URL의 `?key=value&key2=value2` 부분. SDK 주소의 `appkey`·`autoload`(그리고 15장부터 추가할 `libraries`)가 모두 이 형식입니다.
    - `WGS84` — 우리가 쓴 위경도 좌표의 공식 이름(세계 측지계). GPS와 대부분의 지도 서비스가 이 좌표계를 씁니다.
    - `HTTP 상태 코드` — 401·403 말고도 404, 500 등 서버의 대답 코드 체계. 앞으로 계속 만나게 됩니다.

> 다음 장으로. 10장에서는 코드로 지도를 조작하는 방법을 배웁니다. 중심을 바로 옮기는 `setCenter`와 이동 애니메이션이 있는 `panTo`의 차이, 확대 레벨 조절, 지도 위에 확대·축소 버튼 붙이기, 그리고 지도를 클릭한 곳의 좌표를 얻는 이벤트를 다룹니다. 16장에서 클릭으로 장소를 추가할 때 이 기능들을 씁니다.

[^1]: SDK(Software Development Kit) — 소프트웨어 개발 키트. 어떤 서비스를 내 프로그램에서 쓸 수 있도록 필요한 코드와 도구를 묶어 제공하는 것을 말합니다. 카카오지도 JS SDK는 자바스크립트 파일 형태로 제공됩니다.
[^2]: 콜백(callback) 함수 — "이 일이 끝나면 이 함수를 불러줘(call back)"라며 다른 코드에 맡겨 두는 함수. `kakao.maps.load(콜백)`은 SDK 초기화가 끝난 시점에 우리가 맡긴 함수를 대신 실행해 줍니다.
