# 2장 Node.js 설치

!!! note "이 장에서 배우는 것"
    - Node.js가 무엇이고, 왜 이 책의 모든 도구가 Node.js 위에서 도는지 이해합니다
    - 내 컴퓨터에 Node.js가 이미 있는지 `node -v`로 확인합니다
    - nodejs.org에서 LTS 버전을 내려받아 윈도우에 설치합니다
    - "명령을 찾을 수 없습니다"라는 PATH 오류를 스스로 해결합니다
    - npm이 무엇인지, 앞으로 어디에 쓰는지 감을 잡습니다

## 2.1 Node.js가 왜 필요한가요

1장에서 코드는 AI에게 시키고 결과는 사람이 판단한다는 원칙을 다뤘습니다. 그렇게 작업하려면 개발 환경을 먼저 갖춰야 합니다. 이번 장부터 6장까지 개발 환경을 하나씩 설치하며, Node.js부터 시작합니다.

Node.js는 웹 브라우저 바깥에서 자바스크립트를 실행합니다.

원래 자바스크립트는 웹 페이지 안에서만 쓸 수 있었습니다. 크롬이나 엣지 같은 브라우저가 열어 준 페이지 안에서만 동작했습니다. 2009년에 Node.js가 등장하면서 이 제약이 사라졌습니다. 브라우저 없이 내 컴퓨터의 터미널에서 곧바로 자바스크립트를 실행할 수 있게 되었습니다. 그 뒤로 자바스크립트로 서버를 만들고, 개발 도구를 만들고, 명령줄 프로그램도 만들게 되었습니다.

지도 웹앱을 만드는데 브라우저 바깥에서 실행되는 프로그램이 왜 필요한지 궁금할 수 있습니다. 이 책에서 쓰는 도구가 Node.js 위에서 동작하기 때문입니다.

8장에서 다루는 Vite도 그중 하나에 해당합니다. Vite는 지도 앱을 개발하는 동안 개발 서버를 띄워 주고, 코드를 고칠 때마다 브라우저 화면을 자동으로 새로고침합니다. 이 Vite 자체가 Node.js로 만들어졌으므로 Node.js가 없으면 실행되지 않습니다.

4장에서 설치하는 Claude Code도 그렇습니다. 코드를 대신 작성하는 이 AI 에이전트 역시 Node.js로 만들어진 명령줄 프로그램입니다. 설치할 때도 Node.js에 딸려 오는 npm을 씁니다.

완성된 지도 앱을 여는 사용자에게는 Node.js가 보이지 않습니다. 사용자는 브라우저에 뜬 지도만 봅니다. 하지만 그 앱을 만드는 동안에는 Vite와 Claude Code가 계속 Node.js 위에서 실행됩니다.

이 책에서 Node.js를 직접 프로그래밍할 일은 없습니다. Vite와 Claude Code가 알아서 Node.js를 씁니다. 설치는 10분이면 끝납니다.

!!! tip "팁"
    Node.js에서 "js"는 JavaScript를 줄여 붙인 이름입니다. 앞으로 파일 이름 끝에 붙는 `.js` 확장자를 자주 보게 되는데, 모두 자바스크립트 파일을 가리킵니다.

## 2.2 먼저 확인부터: 이미 설치되어 있을 수도 있습니다

무엇이든 설치하기 전에 확인하는 습관을 들입시다. 예전에 다른 프로그램을 설치하면서 Node.js가 함께 깔렸을 수도 있습니다. 터미널에서 확인합니다.

터미널에서는 마우스로 아이콘을 클릭하는 대신 키보드로 명령어를 입력합니다. 이 책에서는 터미널을 계속 쓰므로 여는 방법부터 익혀 둡시다.

윈도우에서 터미널을 여는 가장 쉬운 방법은 이렇습니다.

1. 키보드에서 윈도우 키를 누릅니다.
2. 검색창에 terminal 또는 터미널이라고 입력합니다.
3. 터미널(Windows Terminal) 앱이 보이면 클릭해서 엽니다.

검은색이나 흰색 창이 뜨고 `PS C:\Users\사용자이름>` 같은 글자가 보이면 열린 것입니다. 이 글자를 프롬프트라고 부르며, 명령을 입력할 수 있는 상태임을 나타냅니다.

!!! tip "팁"
    윈도우 10 일부 버전에는 Windows Terminal이 기본 설치되어 있지 않을 수 있습니다. 그럴 때는 검색창에 PowerShell(파워셸)이라고 입력해서 나오는 파란 아이콘을 열면 됩니다. 이 책에서 하는 작업은 둘 중 무엇을 써도 똑같이 됩니다.

이제 프롬프트에 아래 명령을 입력하고 Enter 키를 눌러 봅시다.

```
node -v
```

`node`는 Node.js를 부르는 명령이고, `-v`는 "버전(version)을 알려 줘"라는 옵션입니다. 결과는 둘 중 하나로 나옵니다.

경우 1. 버전 번호가 나온다. `v22.19.0`처럼 `v`로 시작하는 숫자가 출력되면 이미 Node.js가 설치되어 있는 것입니다. 다만 버전이 너무 낮으면(예: v16 이하) 이 책의 도구들이 제대로 돌지 않을 수 있습니다. 앞자리 숫자가 20 이상이면 그대로 써도 좋고, 그보다 낮으면 이번 장을 따라 최신 LTS로 다시 설치해 주세요. 새로 설치하면 기존 버전 위에 덮어써집니다.

경우 2. 오류가 나온다. 아래와 비슷한 빨간 글씨가 나오면 아직 Node.js가 없는 것입니다.

```
node : 'node' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는
프로그램 이름으로 인식되지 않습니다.
```

"그런 프로그램을 찾지 못했다"는 뜻입니다. 지금부터 설치하면 됩니다.

터미널을 쓸 때 알아 두면 편한 조작을 익혀 둡시다. 위쪽 화살표(↑) 키를 누르면 방금 입력했던 명령이 다시 나타납니다. 같은 명령을 여러 번 실행할 때 다시 입력하지 않아도 됩니다. 붙여넣기는 마우스 오른쪽 클릭이나 `Ctrl+V`로 합니다. 책에 나오는 명령을 보고 한 자씩 옮겨 적으면 오타가 나기 쉬우니, 전자책으로 보고 있다면 복사해서 붙여 넣으세요. 다만 명령이 무슨 뜻인지는 한 번씩 확인하고 실행하세요. 코드를 외울 필요는 없지만, 무엇을 실행하는지는 알아야 합니다.

## 2.3 nodejs.org에서 LTS 내려받기

이제 공식 홈페이지에서 설치 파일을 받겠습니다. 브라우저를 열고 주소창에 아래 주소를 입력합니다.

```
https://nodejs.org
```

첫 화면에 커다란 다운로드 버튼이 보입니다. 버튼에는 버전 번호와 함께 LTS라는 글자가 붙어 있습니다.

여기서 LTS가 무엇인지 짚고 갑시다. LTS는 Long Term Support를 줄인 것이고, 우리말로는 장기 지원 버전이라고 합니다. Node.js는 새 기능을 먼저 넣는 Current 버전과, 안정성이 검증되어 오래 지원되는 LTS 버전으로 나뉘어 배포됩니다. Current에는 아직 걸러지지 않은 문제가 남아 있을 수 있습니다. LTS는 여러 사람이 오래 써 보며 문제를 고친 뒤에 배포됩니다. 최신 기능보다 안정성이 중요하면 LTS를 고릅니다. 참고로 Node.js는 짝수 번호 버전만 LTS가 됩니다. 20, 22, 24처럼 짝수 버전은 시간이 지나면 LTS로 승격되고, 21, 23 같은 홀수 버전은 실험용으로 쓰이다 사라집니다. 이 책을 쓰는 시점의 LTS는 v22 계열이지만, 여러분이 보는 화면에는 더 높은 숫자가 적혀 있을 수 있습니다. 숫자가 몇이든 LTS라고 적힌 쪽을 받으면 됩니다.

다운로드 페이지에서 운영체제가 Windows로, 설치 방식이 Installer(.msi)로 선택되어 있는지 확인하고 초록색 다운로드 버튼을 누릅니다. 대부분은 자동으로 윈도우용이 선택되어 있습니다. `node-v22.19.0-x64.msi` 같은 이름의 파일이 다운로드 폴더에 저장됩니다.

![nodejs.org 다운로드 페이지](images/ch02/ch02-f02.jpg){ width="760" }
/// caption
그림 2.2 — nodejs.org 다운로드 페이지

!!! tip "Mac 사용자라면"
    같은 페이지에서 macOS Installer 항목의 `.pkg` 파일을 내려받아 더블클릭하고, 안내에 따라 "계속"만 몇 번 누르면 설치가 끝납니다. 설치한 뒤 `node -v`와 `npm -v`로 확인하는 방법은 윈도우와 완전히 같습니다. 터미널은 Spotlight에서 "터미널"을 검색해 엽니다. Spotlight는 ++cmd+space++로 엽니다. 이후 장에서도 명령어는 윈도우와 거의 동일하니, 이 책의 터미널 명령을 그대로 따라 하시면 됩니다.

!!! tip "팁"
    터미널에 익숙한 분이라면 홈페이지에 가지 않고도 설치할 수 있습니다. 윈도우에 내장된 패키지 관리자 winget으로 `winget install OpenJS.NodeJS.LTS` 한 줄이면 끝납니다. 다만 처음이라면 이번 장의 설치 마법사 방식을 권합니다. 어떤 화면에서 무엇을 묻는지 확인해 두면 다음 도구를 설치할 때 도움이 됩니다.

## 2.5 설치 확인

터미널을 새로 열고, 이번에는 두 가지 명령을 차례로 입력해 봅시다.

```
node -v
npm -v
```

첫 줄에 `v22.19.0`처럼 v로 시작하는 버전이 나오고, 다음 줄에 `10.9.3`처럼 숫자로 된 버전이 나오면 설치된 것입니다. 숫자가 책과 조금 달라도 괜찮습니다. LTS는 계속 업데이트되기 때문입니다. 오류 없이 버전이 출력되는지만 확인하세요.

![`node -v`와 `npm -v` 버전 확인 결과 (출력 예시)](images/ch02/ch02-f07.png){ width="760" }

이제 여러분의 컴퓨터에서 자바스크립트를 실행할 수 있습니다. 짧은 코드 한 줄로 확인해 봅시다. 터미널에 아래를 입력합니다.

node -e "console.log(1 + 1)"

`2`가 출력됩니다. `-e` 옵션을 붙이면 따옴표 안의 자바스크립트 코드를 곧바로 실행합니다. `console.log`는 결과를 화면에 출력합니다. 방금 브라우저 없이 자바스크립트를 실행했고, Node.js가 하는 일이 이것입니다. 이 한 줄을 이해하지 못해도 다음 장으로 넘어가는 데는 지장이 없습니다. 터미널에서도 자바스크립트가 실행된다는 것만 확인하세요.

## 2.6 "명령을 찾을 수 없습니다": PATH 문제 해결

새 터미널에서도 여전히 `'node' 용어가 인식되지 않습니다` 오류가 난다면 대부분 PATH 문제입니다. 여기서 막히는 분이 많으니 원리부터 설명하겠습니다.

터미널에 `node`라고 입력하면, 윈도우는 컴퓨터 전체를 뒤지지 않고 PATH라는 목록에 적힌 폴더들만 순서대로 열어 보며 `node.exe`라는 파일을 찾습니다. 목록에 `C:\Program Files\nodejs\`가 등록되어 있으면 어느 폴더에서든 `node`라고만 입력해도 실행되고, 등록되어 있지 않으면 파일이 그대로 있어도 찾지 못했다는 답이 돌아옵니다.

그러므로 지금 겪는 오류는 프로그램이 없어서 생긴 것이 아닙니다. 프로그램이 있는 폴더가 PATH 목록에 적혀 있지 않아서 생깁니다. 그 폴더를 목록에 등록하면 해결됩니다.

설치 마법사의 Add to PATH 항목이 이 등록을 대신해 주는데, 드물게 등록이 누락되는 경우가 있습니다. 아래 순서로 점검해 봅시다.

1단계. 재부팅. 가장 간단하고 의외로 잘 듣는 방법입니다. 컴퓨터를 다시 시작하면 PATH 변경 사항이 모든 프로그램에 확실히 반영됩니다. 재부팅 후 새 터미널에서 `node -v`를 다시 실행해 보세요.

2단계. 파일이 실제로 있는지 확인. 파일 탐색기로 `C:\Program Files\nodejs` 폴더를 열어 봅니다. 폴더 안에 `node.exe`가 보이면 설치 자체는 된 것이고 PATH 등록만 문제라는 뜻입니다. 폴더 자체가 없다면 설치가 실패한 것이니 2.4절의 설치를 처음부터 다시 진행하세요.

3단계. PATH에 직접 등록. 파일은 있는데 명령만 안 된다면 PATH에 손으로 등록합니다.

1. 윈도우 키를 누르고 환경 변수라고 검색한 뒤 시스템 환경 변수 편집을 엽니다.
2. 창 아래쪽의 환경 변수(N)... 버튼을 누릅니다.
3. 아래쪽 시스템 변수 목록에서 Path를 찾아 선택하고 편집(I)...을 누릅니다.
4. 목록에 `C:\Program Files\nodejs\`가 있는지 확인합니다. 없으면 새로 만들기(N)를 눌러 `C:\Program Files\nodejs\`를 입력합니다.
5. 확인을 세 번 눌러 모든 창을 닫습니다.
6. 터미널을 새로 열고 `node -v`를 다시 실행합니다.

4단계. 그래도 안 되면 재설치. 제어판(설정 → 앱 → 설치된 앱)에서 Node.js를 제거한 뒤, 2.3절부터 다시 설치합니다. 이번에는 Custom Setup 화면에서 Add to PATH가 선택되어 있는지 반드시 확인하세요.

!!! tip "팁"
    PATH는 Node.js에만 해당하는 개념이 아닙니다. 3장의 Git, 5장의 GitHub CLI도 PATH에 등록되어야 터미널에서 `git`, `gh`로 부를 수 있습니다. 앞으로 어떤 도구든 설치했는데 명령이 인식되지 않으면, 이번 장의 순서 그대로 ①터미널 새로 열기 → ②재부팅 → ③PATH 확인을 차례로 해 보세요.

## 2.7 함께 설치된 npm

2.5절에서 `npm -v`도 함께 확인했습니다. npm은 따로 설치한 적이 없는데도 Node.js를 설치할 때 함께 들어옵니다. npm이 무엇인지 짚고 넘어갑시다.

npm은 Node Package Manager를 줄인 이름입니다. 개발에 필요한 코드 꾸러미를 인터넷에서 내려받아 설치합니다. 이 코드 꾸러미를 패키지라고 부릅니다. 필요한 패키지 이름을 적어 명령 한 줄을 실행하면 npm이 내려받아 프로젝트에 넣어 줍니다. 전 세계 개발자가 올린 패키지가 수백만 개 등록되어 있습니다.

이 책에서 npm은 앞으로 두 곳에서 쓰입니다.

- 4장에서 `npm install -g @anthropic-ai/claude-code`로 Claude Code를 설치합니다
- 8장에서 `npm create vite@latest`로 지도 앱 프로젝트를 만듭니다

앞으로 npm 명령을 여러분이 손으로 입력하는 일은 많지 않습니다. 8장 이후로는 Claude Code에게 기능을 만들어 달라고 요청하면, 필요한 패키지가 있을 때 에이전트가 `npm install` 명령을 실행하겠다고 제안합니다. 여러분은 그 제안을 보고 승인하면 됩니다. 그래도 npm이 무엇인지 알아 두는 이유는, 에이전트가 "이 패키지를 설치하겠습니다"라고 물어 왔을 때 무엇을 승인하는지 알고 답하기 위해서입니다.

지금 명령을 외울 필요는 없습니다. npm은 도구를 설치해 주는 프로그램이고 Node.js를 설치하면 함께 들어온다는 것만 기억하면 이번 장의 목표는 달성입니다.

!!! tip "팁"
    `node -v`의 버전과 `npm -v`의 버전은 서로 다른 숫자입니다. Node.js가 v22인데 npm이 10이어도 잘못된 것이 아닙니다. 둘은 별개의 프로그램이라 각자의 버전 번호를 가집니다.

## 2.8 마무리

이번 장에서는 Node.js를 설치했습니다. 터미널을 여는 법, 버전을 확인하는 법, 문제가 생겼을 때 PATH를 점검하는 법까지 함께 익혔습니다. 다음 장에서는 Git을 설치합니다.

!!! abstract "이 장의 핵심"
    - Node.js는 브라우저 밖에서 자바스크립트를 실행해 주는 프로그램으로, 이 책의 Vite와 Claude Code가 모두 그 위에서 동작합니다
    - 설치 전 터미널에서 `node -v`로 이미 설치되어 있는지 먼저 확인합니다
    - nodejs.org에서는 항상 LTS(장기 지원 버전)를 내려받고, 설치 마법사는 기본값 그대로 진행합니다
    - 설치 후에는 터미널을 새로 열어 `node -v`와 `npm -v`로 확인합니다
    - "명령을 찾을 수 없습니다" 오류는 PATH 문제: ①새 터미널 ②재부팅 ③환경 변수의 Path 확인 순서로 해결합니다
    - npm은 Node.js에 딸려 오는 패키지 관리자로, 4장(Claude Code 설치)과 8장(Vite 프로젝트 생성)에서 사용합니다
