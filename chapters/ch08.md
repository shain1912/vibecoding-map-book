# 8장 Vite로 프로젝트 시작

!!! note "이 장에서 배우는 것"
    - Vite가 무엇인지(개발 서버 + 빌드 도구) 이해합니다
    - Claude Code에게 시켜 `npm create vite`로 프로젝트 기본 구조를 만듭니다
    - 생성된 폴더 구조와 `package.json`을 살펴보며 각 파일의 역할을 파악합니다
    - `npm run dev`로 개발 서버를 켜고 `http://localhost:5173`에 접속합니다
    - 7장에서 발급받은 JavaScript 키를 `.env` 파일에 숨기고, `.gitignore`로 보호합니다
    - `import.meta.env`로 코드가 키를 읽어 오는 원리를 배웁니다

---

7장에서 카카오지도의 JavaScript 키를 발급받고, 그 키를 쓸 주소로 `http://localhost:5173`을 등록했습니다. 그런데 그 주소에는 아직 아무것도 없습니다. 브라우저에 `http://localhost:5173`을 입력하면 "사이트에 연결할 수 없음"이 나옵니다. 그 주소로 응답할 서버를 아직 만들지 않았기 때문입니다.

이번 장에서 프로젝트의 기본 구조를 만듭니다. 프로젝트의 기본 폴더와 설정 파일을 미리 갖춰진 틀로 만들어 내는 것을 스캐폴드[^1]라고 부릅니다. 이 틀을 만들어 주는 도구가 Vite(비트)입니다.

이 작업도 바이브코딩으로 합니다. 명령어를 외워서 직접 입력하는 대신, Claude Code에게 프로젝트를 만들어 달라고 시키고 AI가 무엇을 했는지 함께 읽으며 확인합니다.

## 8.1 Vite란 무엇인가: 개발 서버와 빌드 도구

먼저 이름부터 보겠습니다. Vite는 프랑스어로 "빠르다"라는 뜻이고, "비트"라고 읽습니다. 이름 그대로 서버를 빠르게 시작하고 수정도 빠르게 반영합니다.

여기서 한 가지 의문이 생길 수 있습니다. 웹페이지는 HTML 파일이므로, 메모장으로 `index.html`을 만들어 더블클릭하면 브라우저에 열립니다. 그런데 왜 별도의 도구가 필요할까요?

작은 페이지라면 그렇게 해도 됩니다. 하지만 우리가 만들 지도 앱은 파일이 열 개가 넘고, 파일끼리 서로를 불러다 쓰고, `.env`에 넣어 둔 키도 읽어야 합니다. HTML 파일을 더블클릭해서 열면 주소창이 `file:///...`로 시작하는데, 이 방식에서는 이런 동작이 제대로 되지 않습니다. 브라우저가 보안 때문에 여러 기능을 막기 때문입니다. 그리고 7장에서 카카오에 등록한 주소는 `file:///...`이 아니라 `http://localhost:5173`이었습니다. 지도를 불러오려면 페이지가 웹 서버를 통해 열려야 합니다.

Vite는 크게 두 가지 일을 해 줍니다.

먼저 개발 서버 역할을 합니다. 내 컴퓨터 안에 작은 웹 서버를 띄워서, 만들고 있는 페이지를 `http://localhost:5173`이라는 주소로 열어 줍니다. 코드를 고치고 저장하는 순간 브라우저 화면이 자동으로 갱신되므로, 고치고 저장하고 결과를 확인하는 과정이 1초 안에 끝납니다.

그리고 빌드 도구 역할도 합니다. 개발이 끝나면 여기저기 흩어진 코드 파일들을 압축하고 정리해서 인터넷에 올릴 수 있는 파일 묶음으로 만들어야 합니다. 결과물은 `dist` 폴더에 담기고, 이 과정을 빌드[^2]라고 합니다. 25장에서 GitHub Pages에 배포할 때 이 기능을 씁니다. 지금은 개발할 때 개발 서버를 쓰고 공개할 때 빌드를 쓴다는 것만 알아 두면 됩니다.

!!! tip "팁"
    2장에서 설치한 Node.js를 여기서 씁니다. Vite는 Node.js 위에서 동작하는 프로그램이라서, Node가 없으면 실행되지 않습니다. 우리가 쓰는 Vite 7 버전은 Node 20 이상을 요구하는데, 2장에서 LTS 버전을 설치했다면 조건을 이미 만족합니다. 혹시 오래된 Node가 깔려 있다면 터미널에서 `node -v`로 버전부터 확인하세요.

## 8.2 Claude Code에게 프로젝트를 만들게 하기

프로젝트를 담을 폴더를 정하고 그 위치에서 Claude Code를 실행하세요. 저자는 문서 폴더 아래에 작업 폴더를 만들었습니다. 4장에서 배운 대로 터미널에 `claude`를 입력하면 실행됩니다. 그리고 다음과 같이 요청합니다.

!!! tip "이렇게 물어보세요"
    > Vite로 새 프로젝트를 만들어줘. 프로젝트 이름은 my-map, 템플릿은 vanilla(순수 자바스크립트)로. 만든 다음 의존성 설치까지 해줘.

프롬프트의 4요소를 점검해 봅시다. 맥락은 Vite로 만드는 새 프로젝트, 목표는 프로젝트 생성, 제약은 이름 my-map과 템플릿 vanilla, 출력은 의존성 설치까지 완료입니다. Claude Code는 이 요청을 받고 다음 명령들을 실행하겠다고 알려 준 뒤 승인을 받아 진행합니다.

```bash
npm create vite@latest my-map -- --template vanilla
cd my-map
npm install
```

![Claude Code가 npm create vite로 프로젝트를 생성하는 모습](images/ch08/ch08-f01.png){ width="760" }
/// caption
그림 8.1 — Claude Code가 npm create vite로 프로젝트를 생성하는 모습
///

AI가 실행한 명령을 읽어 봅시다. 이번 절에서 실행되는 명령은 이 세 줄뿐입니다.

- `npm create vite@latest my-map` — npm에게 Vite의 최신 프로젝트 생성기를 받아 `my-map`이라는 프로젝트를 만들라고 시키는 명령입니다.
- `-- --template vanilla` — 템플릿 지정입니다. Vite는 React, Vue 같은 프레임워크용 템플릿도 만들 수 있는데, 우리는 vanilla, 즉 프레임워크를 쓰지 않는 순수 자바스크립트를 골랐습니다. 이 책은 자바스크립트와 카카오지도 자체를 다루기 위해 프레임워크를 쓰지 않습니다.
- `npm install` — 템플릿이 만들어 준 `package.json`을 읽고, 프로젝트에 필요한 패키지(지금은 Vite 하나)를 인터넷에서 내려받아 `node_modules` 폴더에 설치합니다.

명령어를 직접 입력하지 않는데도 이런 해설을 두는 이유가 있습니다. AI가 무엇을 했는지 읽을 수 있어야 문제가 생겼을 때 어디를 확인할지 알 수 있기 때문입니다.

설치가 끝나면 Claude Code가 완료를 알립니다. 실제로 만들어졌는지는 직접 확인해야 합니다. 탐색기에서 방금 만들어진 `my-map` 폴더를 열어 보세요.

폴더가 잘 생겼으면 다음 절로 넘어가기 전에 한 가지를 확인해야 합니다. 위 명령의 `cd my-map`은 그 명령을 실행하는 동안에만 적용됩니다. 대화 중인 Claude Code 자신은 여전히 처음 `claude`를 실행한 부모 폴더를 작업 디렉터리로 잡고 있을 수 있습니다. 그래서 지금 세션을 끝내고 `my-map` 폴더 안에서 Claude Code를 다시 엽니다. 순서는 아래와 같습니다.

1. Claude Code 대화창에서 `/exit`를 입력해 세션을 끝냅니다.
2. 터미널에서 `cd my-map`을 입력해 프로젝트 폴더로 들어갑니다. 프롬프트에 표시되는 경로 끝에 `my-map`이 보이는지 확인하세요.
3. 그 자리에서 다시 `claude`를 입력해 새 세션을 엽니다.

새 세션이 열리면 "지금 작업 디렉터리가 어디야?"라고 물어보세요. 답변의 경로 끝이 `my-map`이면 됩니다.

!!! warning "주의"
    이 확인을 건너뛰고 작업 디렉터리가 부모 폴더에 남은 채 진행하면, 8.6에서 만들 `.env` 파일이 `my-map` 바깥에 생깁니다. 그러면 파일은 만들었는데도 9장에서 키가 `undefined`로 나오고 지도가 뜨지 않습니다. 파일 내용에는 문제가 없어서 원인을 찾기 어려운 경우입니다. 앞으로 이 책의 모든 실습은 Claude Code를 `my-map` 폴더 안에서 연 상태를 전제로 합니다.

## 8.3 폴더 구조 살펴보기: 무엇이 생겼나

`my-map` 폴더 안을 열면 아래와 같이 보입니다.

```
my-map/
├── node_modules/        ← 설치된 패키지 (직접 수정하지 않음)
├── public/              ← 그대로 서빙되는 정적 파일
├── src/                 ← 우리가 작성할 코드
│   ├── counter.js       ← 데모용 예제 코드
│   ├── main.js          ← 앱이 처음 실행하는 파일
│   └── style.css        ← 스타일
├── index.html           ← 브라우저가 가장 먼저 받는 파일
├── package.json         ← 프로젝트 정보와 패키지 목록
└── package-lock.json    ← 패키지 버전을 고정하는 파일
```

![생성된 my-map 프로젝트의 폴더 구조](images/ch08/ch08-f02.png){ width="620" }
/// caption
그림 8.2 — 생성된 my-map 프로젝트의 폴더 구조
///

하나씩 살펴봅시다. 책이 끝날 때까지 이 파일들을 계속 다룹니다.

`index.html`은 브라우저가 우리 사이트에 접속할 때 가장 먼저 받아 갑니다. 다른 모든 코드는 이 파일을 통해 연결됩니다.

`src/`에는 우리가 작성하는 코드가 모입니다. 이름은 source를 줄여서 붙였습니다. 이 책의 지도 앱도 `src/main.js`에서 출발해 장이 거듭될수록 `src/` 안에 파일이 하나씩 늘어납니다.

`node_modules/`에는 `npm install`이 내려받은 패키지들이 들어갑니다. 열어 보면 폴더가 수백 개 있습니다. 이 폴더는 직접 수정하지 않고 GitHub에도 올리지 않습니다. `package.json`에 목록이 적혀 있어서 `npm install` 한 번이면 언제든 다시 내려받을 수 있습니다.

`package.json`에는 프로젝트 정보와 패키지 목록이 들어갑니다. 열어 보면 우리 프로젝트는 이렇게 생겼습니다.

```json
{
  "name": "my-map",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "devDependencies": {
    "vite": "^7.1.0"
  }
}
```

읽는 법은 이렇습니다. `name`과 `version`에는 프로젝트의 이름과 버전이 들어갑니다. `0.0.0`은 Vite 템플릿이 넣어 주는 기본값이며, 버전 숫자나 Vite 버전이 책과 조금 달라도 문제되지 않습니다. 생성 시점에 따라 달라집니다. `scripts`에는 단축 명령을 모아 둡니다. 터미널에서 `npm run dev`라고 입력하면 npm이 이 파일을 보고 `vite` 명령을 대신 실행합니다. 개발 서버는 `dev`로, 배포용 파일 생성은 `build`로, 생성 결과 미리보기는 `preview`로 실행하며 이 세 가지를 계속 씁니다. `devDependencies`에는 개발할 때 필요한 패키지를 적어 두는데 지금은 Vite 7 하나뿐입니다. `npm install`이 이 목록을 보고 패키지를 내려받습니다.

`package-lock.json`은 패키지의 정확한 버전을 고정해 둡니다. 자동으로 관리되므로 직접 수정할 일은 없습니다.

!!! tip "팁"
    폴더 구조가 낯설면 Claude Code에 "이 프로젝트 폴더 구조를 초보자에게 설명하듯 알려줘"라고 물어보세요. 지금 열려 있는 프로젝트를 그대로 읽고 설명해 주므로, 일반적인 설명보다 정확합니다.

## 8.4 개발 서버 켜기: npm run dev와 5173

이제 개발 서버를 켜 봅시다. Claude Code에게 시켜도 되고, 이 명령은 자주 쓰게 되니 직접 입력해 보아도 됩니다. `my-map` 폴더의 터미널에서 실행합니다.

```bash
npm run dev
```

1~2초쯤 뒤에 터미널에 이런 출력이 나타납니다.

```
  VITE v7.1.0  ready in 421 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
  ➜  press h + enter to show help
```

![npm run dev 실행 후 개발 서버가 켜진 터미널](images/ch08/ch08-f03.png){ width="760" }
/// caption
그림 8.3 — npm run dev 실행 후 개발 서버가 켜진 터미널
///

`ready in 421 ms`는 1초도 안 되어 서버가 준비됐다는 뜻입니다. 그 아래에 `http://localhost:5173/`이 보이는데, 7장에서 카카오에 등록한 주소와 같습니다. localhost는 내 컴퓨터를 가리키고, 5173은 Vite가 기본으로 여는 포트 번호입니다. 그 포트가 지금 열렸습니다.

브라우저를 열고 `http://localhost:5173`에 접속해 보세요. 앞에서 "연결할 수 없음"이 나오던 주소에 Vite 로고와 카운터 버튼이 있는 기본 페이지가 뜹니다.

/// caption

개발 서버의 동작을 하나 확인해 봅시다. 서버를 켠 채로 `index.html`을 열어 아무 글자나 하나 바꾸고 저장해 보세요. 새로고침 버튼을 누르지 않았는데도 브라우저 화면이 바로 바뀝니다. Vite의 즉시 반영 기능이 동작한 결과이고, HMR[^3]이라고 부릅니다. 앞으로 지도 앱을 만드는 동안 Claude Code가 코드를 고치면 브라우저가 스스로 갱신되므로, 우리는 결과만 확인하면 됩니다.

여기서 알아 둘 것이 있습니다. 개발 서버는 터미널이 켜져 있는 동안만 동작합니다. 터미널에서 ++ctrl+c++를 누르면 서버가 꺼지고, 다시 `npm run dev`를 입력하면 켜집니다. 그리고 서버가 실행 중인 터미널은 다른 명령을 받지 못합니다. 그래서 개발 서버 터미널은 켜 둔 채 두 번째 터미널을 열어 거기서 작업해야 합니다. Claude Code에게 `npm run dev`를 시키고 같은 대화창에서 계속 작업하려 하면 대화가 멈추거나 서버를 꺼야 하는 상황이 됩니다.

두 번째 터미널은 이렇게 엽니다. Windows Terminal에서는 ++ctrl+shift+t++로 새 탭을 열고 `cd my-map`으로 프로젝트 폴더에 들어갑니다. VS Code에서는 터미널 패널 오른쪽 위의 ＋ 버튼이나 분할 버튼을 누르면 처음부터 프로젝트 폴더에서 시작합니다. 6장에서 다룬 Orca를 쓰고 있다면 카드마다 터미널이 따로 있으므로 그대로 쓰면 됩니다. 어느 쪽이든 한 터미널에 개발 서버를 두고 다른 터미널에 Claude Code를 둡니다.

!!! warning "주의"
    `npm run dev`를 실행했는데 주소가 5173이 아니라 `5174`처럼 다른 번호로 뜬다면, 5173 포트를 이미 다른 프로그램이 쓰고 있습니다. 대개 이전에 켜 둔 또 하나의 Vite가 원인입니다. 이대로 두면 카카오에 등록한 주소와 달라져서 9장에서 지도가 뜨지 않습니다. 먼저 켜져 있던 서버 터미널을 찾아 ++ctrl+c++로 끄고 다시 실행하세요.

## 8.5 데모 걷어내고 우리 페이지 만들기

Vite 기본 페이지의 카운터 버튼은 우리 지도 앱과 관련이 없습니다. 데모 코드를 지우고 우리 페이지로 바꿉니다. 이 작업도 직접 하지 않고 Claude Code에게 시킵니다.

!!! tip "이렇게 물어보세요"
    > Vite 기본 템플릿의 데모 코드를 정리해줘. counter.js와 데모용 이미지는 지우고, index.html은 한국어 페이지로 바꿔서 제목을 "나만의 지도"로 해줘. main.js와 style.css는 거의 비운 상태로 남겨줘.

Claude Code가 파일 몇 개를 지우고 고친 뒤 결과를 보고합니다. 정리가 끝난 `index.html`은 이런 모습입니다.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>나만의 지도</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

주요 부분만 읽어 봅시다. `lang="ko"`는 한국어 페이지라는 표시이고, `<title>`은 브라우저 탭에 표시될 이름입니다. `<body>` 안에는 앞으로 화면을 담을 `<div id="app">` 하나와, `src/main.js`를 불러오는 `<script>` 한 줄만 남았습니다. `type="module"` 속성이 있으면 자바스크립트 파일들이 서로를 import로 불러다 쓸 수 있는데, 이 구조는 다음 장부터 씁니다.

저장하면 브라우저가 다시 갱신됩니다. 화면은 비어 있고, 탭 제목은 "나만의 지도"로 바뀌어 있습니다. 이 빈 화면에 다음 장에서 지도를 띄웁니다.

## 8.6 .env: 키를 코드와 분리해서 보관하기

이제 7장에서 발급받은 JavaScript 키를 프로젝트에 넣습니다. 키를 코드에 직접 적으면 코드를 공개할 때 키도 함께 공개됩니다. 그래서 키는 코드와 분리해서 보관합니다.

`.env`라는 파일에 분리해서 보관합니다. 이름은 environment를 줄인 것이고, 코드에 직접 적지 않을 설정값을 여기에 모아 둡니다. Claude Code에게 시켜 봅시다.

!!! tip "이렇게 물어보세요"
    > 프로젝트 루트에 .env 파일을 만들고 VITE_KAKAO_JS_KEY라는 이름으로 카카오 JavaScript 키를 넣을 자리를 만들어줘. 실제 키값은 내가 직접 붙여 넣을게. 그리고 .env가 절대 git에 올라가지 않게 .gitignore도 확인해줘.

이 프롬프트에서 키값 자체는 AI에게 알려 주지 않았습니다. 7장에서 이야기한 대로 키는 필요한 곳에만 최소한으로 전달합니다. Claude Code가 만들어 준 `.env` 파일을 열면 이런 한 줄이 있습니다.

```
VITE_KAKAO_JS_KEY=여기에_여러분의_JS_키
```

이제 developers.kakao.com에 로그인해서 내 애플리케이션 → 앱 설정 → 앱 키에서 JavaScript 키를 복사한 뒤, `여기에_여러분의_JS_키` 자리에 붙여 넣고 저장하세요. 완성된 모습은 아래와 같습니다. 값은 예로 든 가짜 키입니다.

```
VITE_KAKAO_JS_KEY=0123abcd4567efgh8901ijkl2345mnop
```

등호 양옆에 공백을 넣지 않고, 따옴표도 쓰지 않고, 키 이름은 반드시 `VITE_`로 시작해야 합니다. `VITE_`로 시작해야 하는 이유는 다음 절에서 설명합니다.

![.env 파일에 VITE_KAKAO_JS_KEY를 넣은 모습](images/ch08/ch08-f05.png){ width="620" }
/// caption
그림 8.5 — .env 파일에 VITE_KAKAO_JS_KEY를 넣은 모습
///

Claude Code는 `.gitignore` 점검 결과도 함께 알려 줍니다. `.gitignore`에는 git이 기록 대상에서 제외할 파일을 적어 둡니다. Vite 템플릿에는 처음부터 이런 항목들이 들어 있습니다.

```
node_modules
dist
*.local
```

보다시피 이 목록에 `.env` 줄이 없습니다. Vite 기본 `.gitignore`는 `*.local`류만 가릴 뿐 `.env` 자체는 무시하지 않기 때문에, 우리가 프롬프트에서 시킨 대로 Claude Code가 한 줄을 추가합니다. 추가가 끝난 `.gitignore`는 이렇게 바뀌어 있어야 합니다.

```
node_modules
dist
*.local
.env
```

마지막 줄의 `.env`가 실제로 들어갔는지 파일을 직접 열어 눈으로 확인하세요. AI가 "확인했습니다"라고 보고만 하고 실제 추가를 빠뜨리는 일도 드물게 있으니, 결과 파일을 보는 것까지가 확인입니다.

더 확실히 확인하려면 git에게 직접 물어보는 방법도 있습니다. 8.4에서 연 두 번째 터미널에서 `git status`를 실행해 보세요. 개발 서버가 실행 중인 터미널이 아니어야 합니다.

- 3장에서 배운 습관대로 이 폴더에서 이미 `git init`을 해 두었다면, 출력의 파일 목록(Untracked files)에 `.env`가 없어야 정상입니다. `.gitignore`가 제 일을 하고 있다는 증거입니다. 목록에 `.env`가 보인다면 `.gitignore`의 철자와 위치(프로젝트 루트)를 다시 확인하세요.
- `fatal: not a git repository ...`라는 메시지가 나온다면, 아직 이 폴더를 git 저장소로 만들지 않았다는 뜻입니다. 잘못된 상황은 아닙니다. 24장에서 `git init` 직후에 같은 확인을 다시 한 번 하게 됩니다.

이로써 24장에서 프로젝트를 GitHub에 올릴 때, 키가 든 `.env`는 `node_modules`와 함께 업로드 대상에서 제외됩니다. 코드는 공개되지만 키는 내 컴퓨터에만 남습니다. `.gitignore`에 `.env` 줄이 빠진 채로 24장에 도착하면 키가 그대로 공개되므로, 지금 확인해 두어야 합니다.

!!! warning "주의"
    `.env`는 이름이 점(`.`)으로 시작해서 윈도우 탐색기 설정에 따라 보이지 않을 수 있습니다. 파일이 안 보이면 탐색기 상단 메뉴에서 "숨긴 항목 표시"를 켜거나, 에디터(VS Code 등)의 파일 목록에서 확인하세요. 그리고 `.env`를 메신저나 이메일로 보내거나 화면을 캡처해 공유하지 마세요. 이 책의 화면 캡처가 전부 가짜 키를 쓰는 것도 같은 이유입니다.

## 8.7 import.meta.env: .env의 키를 코드에서 읽는 법

`.env`에 키를 넣었으니, 코드에서 그 키를 읽는 방법을 봅시다. Vite 프로젝트의 자바스크립트 코드에서는 이렇게 씁니다.

```js
const KAKAO_KEY = import.meta.env.VITE_KAKAO_JS_KEY;
```

`import.meta.env`에는 Vite가 환경값을 모아 넣어 줍니다. Vite는 개발 서버를 켤 때 `.env` 파일을 읽어 두었다가, 코드에서 `import.meta.env.VITE_KAKAO_JS_KEY`라고 쓰면 그 자리에 `.env`의 값을 넣습니다. 파일을 여는 코드나 별도 설정은 필요 없고, 이름만 정확히 쓰면 됩니다.

여기서 앞 절의 규칙이 설명됩니다. 키 이름이 `VITE_`로 시작해야 하는 이유는, `.env`에 브라우저로 보내면 안 되는 값이 함께 들어 있을 수 있기 때문입니다. 그래서 Vite는 `VITE_`로 시작하는 변수만 브라우저 코드로 전달하고 나머지는 전달하지 않습니다. `VITE_` 접두사는 이 값을 브라우저에 보내도 된다는 표시입니다. `KAKAO_JS_KEY`라고만 적으면 전달되지 않아 코드에서는 `undefined`(값 없음)가 나옵니다.

실제로 전달되는지 확인해 봅시다. 시키고, 읽고, 확인하는 순서 그대로입니다.

!!! tip "이렇게 물어보세요"
    > main.js에 .env의 VITE_KAKAO_JS_KEY를 읽어서 콘솔에 앞 4글자만 출력하는 테스트 코드를 넣어줘. 키 전체가 콘솔에 찍히면 안 돼.

Claude Code가 `src/main.js`에 이런 코드를 넣어 줍니다.

```js
const key = import.meta.env.VITE_KAKAO_JS_KEY;
console.log('카카오 키 로드:', key ? key.slice(0, 4) + '... (OK)' : '없음!');
```

두 줄을 읽어 봅시다. 첫 줄은 환경값에서 키를 꺼내 `key`라는 변수에 담습니다. 다음 줄은 브라우저 콘솔에 확인 메시지를 출력합니다. `key ? A : B`는 키가 있으면 A를, 없으면 B를 쓰라는 조건 표현이고, `key.slice(0, 4)`는 키의 앞 4글자만 잘라냅니다. 전체 키를 콘솔에 출력하지 않는다는 제약이 코드에 그대로 반영됐습니다.

이제 실행 확인입니다. `.env`를 만들거나 고친 뒤에는 개발 서버를 껐다 켜야 합니다. Vite는 서버를 시작할 때 `.env`를 읽기 때문에, 켜진 채로는 새 값을 모릅니다. 터미널에서 ++ctrl+c++ 후 다시 `npm run dev`. 그리고 브라우저에서 ++f12++를 눌러 개발자도구의 Console 탭을 여세요.

```
카카오 키 로드: 0123... (OK)
```

![브라우저 콘솔에서 키 로드 확인](images/ch08/ch08-f06.png){ width="760" }
/// caption
그림 8.6 — 브라우저 콘솔에서 키 로드 확인
///

`(OK)`가 보이면 `.env`의 값이 코드까지 전달된 것입니다. `없음!`이 나온다면 세 가지를 점검하세요. 변수 이름이 `VITE_`로 시작하는지, `.env`가 src 안이 아니라 프로젝트 루트에 있는지, 서버를 껐다 켰는지 확인합니다. 이 테스트 코드는 다음 장에서 지도 코드로 바꿀 것이므로 그대로 두어도 됩니다.

## 8.8 마무리

이번 장에서 프로젝트의 기본 구조를 만들었습니다. Claude Code에게 시켜 Vite 프로젝트를 스캐폴드했고, 폴더 구조와 `package.json`을 읽는 법을 배웠고, `npm run dev`로 `http://localhost:5173`에 개발 서버를 띄웠습니다. 그리고 JavaScript 키를 `.env`에 넣고, `.gitignore`로 git에서 제외하고, `import.meta.env`로 읽어 오는 것까지 확인했습니다. 다음 장에서 이 페이지에 지도를 띄웁니다.

!!! abstract "이 장의 핵심"
    - Vite는 개발 서버와 빌드 도구를 함께 제공합니다. 개발 서버는 화면을 즉시 갱신하고, 빌드는 배포용 파일을 만듭니다.
    - `npm create vite@latest my-map -- --template vanilla`로 순수 자바스크립트 프로젝트를 스캐폴드하고, `npm install`로 부품을 설치합니다.
    - 스캐폴드 직후에는 `cd my-map`으로 이동해 그 폴더 안에서 Claude Code를 다시 엽니다. 작업 디렉터리가 부모 폴더에 남으면 `.env`가 엉뚱한 곳에 생깁니다.
    - 개발 서버 터미널은 켜 둔 채 두 번째 터미널에서 작업합니다. Windows Terminal은 ++ctrl+shift+t++로 새 탭을 열고, VS Code는 터미널을 분할합니다.
    - `package.json`의 `scripts` 덕분에 `npm run dev` 한 줄로 개발 서버가 켜지고, 주소는 `http://localhost:5173`입니다.
    - `node_modules`는 직접 수정하지도, GitHub에 올리지도 않는 폴더입니다.
    - 키는 코드가 아니라 `.env`에 `VITE_KAKAO_JS_KEY=...` 형태로 넣고, `.gitignore`로 git에서 제외합니다. `.gitignore`에 `.env` 줄이 실제로 추가됐는지 파일을 열어 보고, `git status` 목록에 `.env`가 없는지도 확인합니다.
    - 코드에서는 `import.meta.env.VITE_KAKAO_JS_KEY`로 읽으며, `VITE_` 접두사가 붙은 값만 브라우저로 전달됩니다. `.env` 수정 후에는 서버 재시작이 필요합니다.

[^1]: 스캐폴드(scaffold) — 공사장의 비계(임시 발판)에서 온 말로, 프로젝트의 기본 폴더·설정 파일 골격을 자동으로 만들어 주는 것. "스캐폴딩한다"처럼 동사로도 씁니다.
[^2]: 빌드(build) — 사람이 읽기 좋게 쓴 개발용 코드를, 브라우저가 빠르게 받을 수 있는 배포용 파일 묶음으로 변환하고 압축하는 과정. 결과물은 `dist`(distribution) 폴더에 담깁니다.
[^3]: HMR(Hot Module Replacement) — 코드를 저장하면 페이지 전체를 새로고침하지 않고 바뀐 부분만 갈아 끼워 즉시 반영하는 기능. "핫 리로드"라고도 부릅니다.
