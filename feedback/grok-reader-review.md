## 종합: 입문자가 실제로 빠지는 구멍

1. **16장 프롬프트 3개만 실행하면 `store`가 없다.** `openAddDialog` 결과 코드는 `store.add()`를 호출하는데, 이 장 어디에도 `src/store.js`를 만들라는 프롬프트가 없다. 모듈 로드가 실패하면 **검색까지 함께 죽는다.**
2. **설령 AI가 `store.js`를 알아서 만들어도, 지도 데이터 원천은 14장의 `DEFAULT_PLACES`에 남아 있다.** `store.add()`로 넣은 장소는 배열에만 쌓이고 마커는 안 찍힌다. 16장이 약속한 “추가 즉시 마커”와 17장이 약속한 “새로고침 후 유지”가 둘 다 거짓이 된다.
3. **17장 백업 훈련 2단계는 삭제 UI가 없는 상태에서 “지도에서 장소를 하나 삭제하라”고 한다.** 삭제는 19장이다.
4. **16장의 `stopPropagation` 수업은 같은 장 코드와 모순된다.** 연습 문제대로 한 줄을 지워도 아무 일도 안 일어난다.

완성 앱(`app/src/store.js`, `sidebar.js`, `main.js`)에는 구독(`subscribe`)·`store.all()` 필터·내보내기 HTML이 이미 들어 있다. 원고가 **장 단위 누적 상태가 아니라 최종 코드를 과거형으로 서술**한 흔적이다.

- **버블링 장문**은 현재 코드에선 죽은 지식이다. 분량을 쓰면서 입문자를 틀린 원인으로 안내한다. 빼거나, 핸들러를 다시 `<li>`에 단 잘못된 코드를 먼저 보여 준 뒤 고치는 구조로 바꿔야 한다.
- 한 장에 기본값 인자, 옵셔널 체이닝, 클로저, 스프레드, 버블링, CRUD가 동시에 올라온다. 입문자 한 세션 분량을 넘는다.

## 17장 — localStorage 저장

원리 실험(17.1~17.3)은 입문서답게 잘 짜여 있다. 무너지는 지점은 **16장의 미완 전제를 잇고, 19장 UI와 18장 구독을 끌어다 쓰는 것**이다.

### ① 따라 하면 막히는 지점

| 심각도 | 위치 | 내용 |
|---|---|---|
| **치명** | 17.4 185~186행 | “장소를 추가하고 F5 → 그대로 있다.” 지도는 여전히 `DEFAULT_PLACES`를 그린다. localStorage에 JSON이 쌓여도 **화면은 기본 다섯 개**다. Application 탭에 `my-map-places-v1`이 보여도 입문자는 “저장이 안 된 것”으로 판단한다. 성공 조건이 화면과 저장소를 한 줄로 묶어 버렸다. |
| **치명** | 17.5 훈련 2 (261행) | “지도에서 장소를 하나 **삭제**합니다.” 삭제 버튼·`store.remove` UI는 **19장**. 콘솔에서 `store`를 부를 수도 없다(전역이 아님). 이 훈련은 여기서 멈춘다. |
| **중요** | 17.5 프롬프트 vs 결과 | 프롬프트는 사이드바 **아래쪽 버튼**까지 요구한다. 결과 코드는 `getElementById('btn-export')` 등 JS만 보여 주고, `index.html`의 `<footer>` / `#import-file`이 없다. 버튼이 안 생기면 이 줄에서 `null.addEventListener`로 사이드바 초기화가 죽는다. 필터까지 날아갈 수 있다. |
| **중요** | 17.5 240행 `await file.text()` | `async`/`await`/Promise를 본문에서 처음 실사용한다. 각주 4가 한 줄로 때운다. 읽기만 하면 넘어갈 수는 있으나, “따라 읽고 이해” 목표에는 전제가 비어 있다. |
| **경미** | 17.4 125행 `structuredClone` | 프롬프트에 없고 설명도 “깊은 복사” 한 방이다. 최신 크롬에서는 동작한다. |

### ② 장 간 연결

| 심각도 | 위치 | 내용 |
|---|---|---|
| **치명** | 17장 ↔ 14장 | `load()`는 `store`의 `places`를 채운다. 화면은 `filteredPlaces()` → `DEFAULT_PLACES`. **저장과 화면이 다른 배열**이다. |
| **중요** | 18. 도입부 15행 vs 17.4 `save()` | 18장은 “17장에서 `listeners`와 `save()` 끝 `forEach`를 미뤄 두었다”고 한다. 17장에 그 코드가 **없다.** 17장 `save()`는 `setItem`과 `console.warn`뿐이다. 입문자는 안 배운 줄을 놓친 줄 알고 17장을 다시 읽게 된다. |
| **중요** | 17.4 152~177행 | `update` / `remove` / `replaceAll`을 “모든 문의 마지막 줄에서 save()”로 보여 준다. 호출 UI는 19장(수정·삭제)·17.5(가져오기는 `replaceAll`이 아니라 `places = data`). 입문자에게는 아직 못 누르는 문이다. |
| **중요** | 17.2 49행 “Application 탭” | 한국어 크롬은 **「애플리케이션」**. F12 영어 탭 이름을 그대로 쓰면 입문자가 헤맨다. |
| **경미** | 17.4 180행 | “8장부터 지켜 온 제1원칙, 한 가지 일은 한 곳에서.” 8장의 원칙은 키 분리·모듈이지, 이 문장은 9장 loader / 16장 재사용 쪽에 더 가깝다. |

### ③ 프롬프트 vs 결과 코드

| 프롬프트 | 정합 | 메모 |
|---|---|---|
| 17.4 영속화 | 핵심은 맞음 | 키 `my-map-places-v1`, `save()` 한곳, try-catch, 깨지면 기본 데이터 — 코드와 맞다. `structuredClone`은 프롬프트에 없음. |
| 17.5 내보내기/가져오기 | **빠짐** | `exportJson`의 `JSON.stringify(places, null, 2)`, `importJson` 검증은 맞다. **HTML 마크업·CSS가 결과에 없고**, `importJson`은 프롬프트의 “store를 통째로 교체”를 `replaceAll`이 아니라 직접 `places = data; save();`로 한다. `replaceAll`은 죽은 메서드로 남는다. |
| 가져오기 후 화면 | 미지정 | 구독이 없으면 가져오기 성공 토스트만 뜨고 마커는 그대로다. 새로고침해도 14장 데이터 원천이면 복구가 안 보인다. |

`importJson`은 `id`를 검사하지 않는다. 손댄 JSON이 이름·좌표만 있으면 통과하고, 19장 삭제/상세가 `id`로 찾으면 조용히 실패한다. 지금은 **중요** 쪽 품질 빚이다.

### ④ 군더더기

17.1~17.3(메모리 vs 서랍, 콘솔 실험, JSON 왕복)은 입문자에게 필요한 분량이다.

**17.5가 이 장을 과적한다.** localStorage를 갓 배운 세션에 Blob, `createObjectURL`, 숨은 file input, `await file.text()`, throw/catch 분업, 스키마 검증을 얹는다. 백업은 22장 대량 데이터·26장 공유 한계에서 다시 쓰이므로, 17장은 “F5 후에도 남는다”까지로 자르고 내보내기는 뒤로 빼는 편이 맞다.

`update`/`remove` 전문을 여기서 보여주는 것도 같은 과적이다. 16장에서 연 구멍(`add`만)을 메우려다 저장소 API 전체를 한 번에 깐다.

## 장별 우선 수정 순서 (참고, 미수정)
