# 5장 GitHub CLI로 깃허브 연결

!!! note "이 장에서 배우는 것"
    - 깃허브(GitHub)가 무엇이고 왜 필요한지 이해합니다
    - GitHub 계정을 만들고, GitHub CLI(`gh`)를 winget으로 설치합니다
    - `gh auth login`으로 터미널과 깃허브를 브라우저 인증으로 연결합니다
    - `gh repo create`로 첫 원격 저장소를 만들고 `git push`로 올려 봅니다

---

## 5.1 깃허브: 코드를 인터넷에 백업하는 곳

3장에서 Git을 설치하면서 되돌릴 수 있어야 시도할 수 있다고 이야기했습니다. Git은 내 컴퓨터 안에서 코드의 변경 이력을 기록합니다. 그런데 그 이력이 전부 내 컴퓨터 안에만 남습니다.

노트북을 잃어버리거나 하드디스크가 고장 나면 지금까지 쌓은 커밋이 통째로 사라집니다. 사진을 구글 포토나 아이클라우드에 백업하듯 코드도 인터넷에 백업해 두어야 합니다. 깃허브(GitHub)[^1]가 그 역할을 합니다.

깃허브는 Git 저장소를 인터넷에 보관합니다. 내 컴퓨터의 저장소를 깃허브에 올리는 동작을 푸시(push)라고 부릅니다. 한 번 올려 두면 컴퓨터가 고장 나도 코드는 남습니다. 다른 컴퓨터에서 내려받아 이어서 작업할 수도 있고, 링크 하나로 다른 사람에게 보여 줄 수도 있습니다.

이 책에서 깃허브는 세 가지 역할을 맡습니다.

1. 백업. 매일의 작업을 인터넷에 보관합니다.
2. 포트폴리오. 완성한 지도 웹앱의 코드가 내 깃허브 프로필에 쌓입니다. 개발 직군에서는 이 프로필을 이력서와 함께 확인하는 경우가 많습니다.
3. 배포. 25장에서 깃허브의 무료 호스팅 기능인 GitHub Pages로 지도 웹앱을 공개합니다. 깃허브에 올라가 있어야 배포할 수 있습니다.

깃허브는 백업 말고 다른 용도로도 쓰입니다. 전 세계 개발자들이 깃허브에 코드를 공개해 두고 서로의 코드를 읽고 고칩니다. 이 책에서 쓰는 Node.js, Git, GitHub CLI도 모두 깃허브에 코드가 공개되어 있습니다.

그런데 깃허브를 터미널에서 다루려면 도구가 하나 더 필요합니다. GitHub CLI를 설치하면 `gh` 명령으로 깃허브를 조작할 수 있습니다. CLI는 Command Line Interface를 줄인 말이고, 마우스 클릭 대신 명령어로 조작하는 프로그램을 가리킵니다. 깃허브에 저장소를 만들려면 원래 브라우저를 열고 로그인한 뒤 버튼을 여러 번 눌러야 합니다. `gh`를 쓰면 터미널에서 명령 한 줄로 만듭니다. 저장소 만들기, 목록 보기, 삭제, 나중에 배울 풀 리퀘스트까지 터미널에서 처리할 수 있습니다.

`gh`를 설치하는 더 중요한 이유는 Claude Code가 이 명령을 쓰기 때문입니다. "이 프로젝트 깃허브에 올려 줘"라고 시키면 Claude Code가 내부적으로 `gh` 명령을 실행합니다. Claude Code는 터미널에서 동작하므로 브라우저 화면은 조작하지 못합니다. 미리 `gh`를 설치하고 로그인해 두면 그때부터 깃허브 관련 작업을 Claude Code에게 맡길 수 있습니다.

!!! tip "팁"
    Git과 GitHub는 이름이 비슷해서 자주 헷갈립니다. Git은 내 컴퓨터에서 실행되고, GitHub는 그 Git 저장소를 인터넷에 올려 두는 웹 서비스로 동작합니다. GitHub 말고도 GitLab, Bitbucket 같은 서비스가 있지만 GitHub를 가장 많이 씁니다.

## 5.2 GitHub 계정 만들기

이미 깃허브 계정이 있다면 이 절은 건너뛰고 5.3절로 가셔도 됩니다. 처음이라면 함께 만들어 봅시다. 계정 생성은 무료이고, 신용카드도 필요 없습니다.

브라우저에서 github.com 에 접속한 뒤 오른쪽 위의 Sign up 버튼을 누릅니다.

![GitHub 가입 페이지 (예시)](images/ch05/ch05-f01.png){ width="560" }
/// caption
그림 5.1 — GitHub 가입 페이지 (예시)
///

가입 절차는 화면 안내를 따라가면 됩니다. 순서는 아래와 같습니다.

1. Email: 자주 확인하는 이메일 주소를 입력합니다. 인증 메일이 오니 실제 쓰는 주소여야 합니다.
2. Password: 15자 이상, 또는 숫자와 소문자를 포함한 8자 이상이어야 합니다.
3. Username: 깃허브에서 나를 가리키는 이름입니다. 프로필 주소가 `github.com/사용자이름` 이 되니 신중하게 고릅시다. 영문 소문자와 숫자, 하이픈(-)만 쓸 수 있습니다.
4. 이메일 인증: 입력한 메일함으로 온 인증 코드(또는 퍼즐 확인)를 입력하면 가입이 끝납니다.

!!! tip "팁"
    Username은 나중에 포트폴리오 주소가 됩니다. `github.com/kimcoding` 처럼 깔끔한 이름이 `github.com/qwer1234asdf` 보다 훨씬 보기 좋습니다. 본명 로마자, 닉네임, 블로그 아이디 등 오래 써도 부끄럽지 않을 이름을 추천합니다. 나중에 바꿀 수는 있지만, 바꾸면 기존 주소 링크가 끊어질 수 있습니다.

가입을 마치면 몇 가지 설문(팀 규모, 관심사 등)이 나올 수 있는데, 아래쪽의 건너뛰기(Skip) 링크를 눌러도 됩니다. 유료 플랜을 권하는 화면이 나와도 마찬가지입니다. 이 책의 모든 작업은 무료 플랜(Free)으로 할 수 있습니다. 공개 저장소는 개수 제한 없이 만들 수 있고, 비공개 저장소도 무료로 쓸 수 있으며, 25장에서 쓸 GitHub Pages 배포까지 전부 무료 범위 안입니다. 대시보드 화면이 나오면 계정 준비 완료입니다.

시간이 있다면 프로필 설정에서 2단계 인증을 켜 두기를 권합니다. 화면에는 Two-factor authentication으로 표시됩니다. 이 기능을 켜면 비밀번호가 유출돼도 휴대폰 인증 앱의 확인 없이는 로그인되지 않습니다. 깃허브 계정에는 앞으로 작성한 코드가 모두 쌓이므로 보호해 둘 필요가 있습니다. 오른쪽 위 프로필 아이콘 → Settings → Password and authentication 메뉴에서 켤 수 있습니다. 지금 하지 않아도 이 장을 진행하는 데는 지장이 없습니다.

!!! warning "주의"
    가입에 쓴 이메일 주소를 기억해 두세요. 3장에서 `git config user.email`에 설정한 주소와 깃허브 가입 주소가 같아야, 내가 올린 커밋이 내 프로필 활동(잔디밭)으로 집계됩니다. 다르게 설정했다면 `git config --global user.email "깃허브가입메일"` 로 맞춰 주면 됩니다.

## 5.3 GitHub CLI 설치: winget 한 줄이면 끝

이번 설치는 간단합니다. 2장의 Node.js처럼 홈페이지에서 설치 파일을 내려받아 마법사를 넘길 필요가 없습니다. 윈도우에 기본으로 들어 있는 패키지 관리자 winget[^2]을 쓰면 명령 한 줄로 끝납니다. 패키지 관리자란 프로그램의 다운로드·설치·업데이트를 명령어로 대신해 주는 도구입니다. 클릭할 화면이 없으므로 설치 과정에서 잘못 고를 항목도 없습니다.

PowerShell이나 Windows Terminal을 열고 아래 명령을 입력하세요.

```powershell
winget install GitHub.cli
```

처음 실행하면 약관(msstore 이용 약관) 동의를 묻는 경우가 있습니다. `Y`를 입력하고 Enter를 누르면 다운로드와 설치가 자동으로 진행됩니다.

버전 번호가 나오면 설치된 것입니다. 숫자는 책과 달라도 괜찮습니다. `'gh' 용어가 cmdlet... 이름으로 인식되지 않습니다` 같은 빨간 오류가 나온다면 대부분 터미널을 새로 열지 않은 경우이니 창을 닫고 다시 열어 보세요. 그래도 안 되면 컴퓨터를 재부팅해 보세요.

## 5.4 gh auth login: 터미널과 깃허브 연결하기

`gh`를 설치했지만 아직 `gh`는 내가 누구인지 모릅니다. 이 상태로 저장소를 만들려고 하면 먼저 로그인하라는 안내만 돌아옵니다. 이 터미널이 방금 만든 계정의 주인이 쓰는 것임을 깃허브에 증명하는 절차가 필요합니다. 이것을 인증(authentication)이라고 하고, 명령은 `gh auth login` 입니다.

단계가 여러 개로 보이지만 실제로는 3분이면 끝납니다. 순서는 이렇습니다. 터미널이 8자리 코드를 보여 주고, 브라우저가 열리고, 그 코드를 입력하면 끝입니다. 하나씩 따라가 봅시다.

새 터미널에서 입력합니다.

```powershell
gh auth login
```

그러면 터미널이 물음표(?)가 붙은 질문을 차례로 던집니다. 화살표 키(↑↓)로 고르고 Enter로 확정합니다.

질문 1. 어디에 로그인할까요?

```
? Where do you use GitHub?  [Use arrows to move, type to filter]
> GitHub.com
  other
```

GitHub.com 을 선택합니다. 회사에서 쓰는 별도 깃허브 서버에 접속하는 경우가 아니면 항상 이 항목을 고릅니다.

질문 2. Git 통신 방식은?

```
? What is your preferred protocol for Git operations on this host?
> HTTPS
  SSH
```

HTTPS 를 선택합니다. SSH는 인증용 키 파일을 따로 만들어야 하는 방식인데, 이 책의 작업은 HTTPS로 모두 처리됩니다.

질문 3. Git 인증도 깃허브 계정으로?

```
? Authenticate Git with your GitHub credentials?
> Yes
```

Yes 를 선택합니다. Yes로 해 두면 나중에 `git push` 할 때 아이디와 비밀번호를 따로 묻지 않습니다.

질문 4. 어떻게 로그인할까요?

```
? How would you like to authenticate GitHub CLI?
> Login with a web browser
  Paste an authentication token
```

Login with a web browser 를 선택합니다. 토큰 방식은 문자열을 직접 발급받아 붙여 넣는 방식으로, 지금은 필요 없습니다.

![gh auth login 질문 4단계](images/ch05/ch05-f04.png){ width="760" }

그림 5.4 — gh auth login 질문 4단계
///


브라우저 화면의 입력 칸에 아까 복사한 코드를 붙여 넣고 Continue를 누릅니다. 이어서 "GitHub CLI가 계정에 접근하는 것을 허용할까요?"라고 묻는 Authorize github 화면이 나오면 초록색 Authorize 버튼을 누릅니다. "Congratulations, you're all set!" 같은 완료 메시지가 보이면 브라우저에서 할 일은 끝입니다.

터미널로 돌아와 보세요. 몇 초 안에 이런 출력이 나타납니다.

```
✓ Authentication complete.
- gh config set -h github.com git_protocol https
✓ Configured git protocol
✓ Logged in as 여러분의아이디
```

![인증 완료, Logged in as](images/ch05/ch05-f07.png){ width="760" }
/// caption
그림 5.7 — 인증 완료, Logged in as
///

`Logged in as` 뒤에 내 아이디가 나오면 연결된 것입니다. 이 과정에서 실제로 일어난 일은 이렇습니다. 브라우저에서 Authorize를 누르면 깃허브가 이 터미널을 위한 접근 토큰을 발급해 `gh`에게 전달합니다. `gh`는 이 토큰을 내 컴퓨터에 저장해 두고, 이후 깃허브와 통신할 때마다 비밀번호 대신 토큰을 보냅니다. 비밀번호는 브라우저의 깃허브 화면에 한 번 입력했을 뿐이고 터미널에는 저장되지 않습니다. 코드를 브라우저에 입력하는 절차가 번거로워 보여도, 비밀번호가 여러 프로그램에 남지 않게 하려는 설계입니다.

이 인증은 한 번 해 두면 계속 유지됩니다. 컴퓨터를 껐다 켜도 다시 로그인할 필요가 없습니다. 다만 컴퓨터를 새로 장만하거나 포맷하면 토큰도 사라지므로 그때는 `gh auth login`을 다시 하면 됩니다. 언제든 상태가 궁금하면 `gh auth status` 를 입력해 보세요. 어떤 계정으로 로그인돼 있는지, 어떤 프로토콜을 쓰는지 알려 줍니다.

!!! warning "주의"
    일회용 코드에는 유효 시간이 있습니다. 코드를 받아 놓고 한참 뒤에 입력하면 만료되어 실패합니다. 만료됐다면 터미널에서 `gh auth login` 을 처음부터 다시 실행하면 새 코드가 나옵니다. 그리고 인증 과정에서 깃허브 비밀번호는 브라우저의 github.com 화면에만 입력합니다. 터미널이 비밀번호를 묻는 일은 없습니다.

## 5.5 첫 원격 저장소: gh repo create와 git push

연결이 됐으니 첫 저장소를 깃허브에 올려 봅시다. 지도 앱은 8장부터 만들 것이므로, 여기서는 연습용 저장소로 순서만 확인합니다. 폴더를 만들고, `git init`으로 내 컴퓨터에 저장소를 만들고, `commit`으로 기록한 뒤, `gh repo create`로 깃허브에 올립니다.

이번에는 이 과정을 Claude Code에게 시켜 보겠습니다. 연습 폴더를 하나 만들어 Claude Code를 띄운 뒤 이렇게 요청합니다.

!!! tip "이렇게 물어보세요"
    > hello-github 라는 연습용 저장소를 만들고 싶어. 이 폴더에 나를 소개하는 README.md를 한국어로 짧게 만들고, git 저장소로 초기화해서 첫 커밋을 한 다음, gh로 내 깃허브에 public 리포로 올려 줘.

Claude Code는 4장에서 본 확인 창으로 권한을 물어 가며 다음 명령들을 실행합니다. 직접 입력할 일은 없지만, 무엇이 실행되는지는 알고 승인해야 합니다.

```powershell
git init
git add README.md
git commit -m "첫 커밋: README 추가"
gh repo create hello-github --public --source=. --push
```

한 줄씩 뜯어 보면 이렇습니다.

- `git init` — 이 폴더를 Git 저장소로 만듭니다(3장 복습). 아직 내 컴퓨터 안 이야기입니다.
- `git add` / `git commit` — README 파일을 기록 대상에 올리고 "첫 커밋"이라는 메시지로 저장합니다.
- `gh repo create hello-github --public --source=. --push` — 깃허브에 `hello-github`라는 저장소를 만들고(`--public`: 누구나 볼 수 있게), 현재 폴더(`--source=.`)를 그 저장소와 연결한 뒤, 지금까지의 커밋을 올립니다(`--push`).

여기서 개념 하나만 짚고 갑시다. 내 컴퓨터의 저장소와 깃허브의 저장소가 연결되면, 깃허브 쪽을 원격 저장소(remote)라고 부르고 보통 origin이라는 별명을 붙입니다. 이후로 커밋을 깃허브에 올릴 때는 이렇게 씁니다.

```powershell
git push
```

`push`는 내 컴퓨터에 쌓인 새 커밋을 origin(깃허브)으로 올리는 명령입니다. 반대로 깃허브의 내용을 내 컴퓨터로 가져오는 명령은 `git pull`입니다. 올릴 때는 push, 받을 때는 pull입니다.

실제로 올라갔는지 확인해 봅시다. 터미널에 아래를 입력하면 방금 만든 저장소가 브라우저로 열립니다.

```powershell
gh repo view --web
```

브라우저에 `github.com/내아이디/hello-github` 페이지가 뜨고, 방금 만든 README가 보이면 성공입니다. 저장소 페이지를 살펴봅시다. 가운데에 파일 목록이 있고, 그 아래에 README 내용이 자동으로 펼쳐져 보입니다. 파일 목록 위의 "1 commit" 같은 표시를 누르면 커밋 이력을 볼 수 있습니다. 커밋이 쌓일수록 이 이력이 길어지고, 프로필의 기여 그래프에도 초록 칸이 하나씩 채워집니다.

이 순서는 이 책 전체에서 반복됩니다. 작업이 하나 끝날 때마다 커밋하고(commit) 올립니다(push). 저자는 기능 하나를 완성할 때마다 Claude Code에게 "커밋하고 푸시해 줘"라고 시킵니다. 이 두 단계를 습관으로 해 두면 하루 작업이 통째로 사라지는 일을 막을 수 있습니다. 24장에서는 지도 웹앱을 이 방법 그대로 올리고, 25장에서는 그 저장소로 배포합니다.

!!! tip "팁"
    연습이 끝난 `hello-github` 저장소는 지워도 되고 그냥 두어도 됩니다. 지우려면 깃허브 저장소 페이지에서 Settings 탭 맨 아래 Danger Zone의 Delete this repository를 누릅니다. 실수로 지우는 것을 막기 위해 저장소 이름을 직접 입력해야 삭제됩니다.

## 5.6 마무리

이것으로 작업 환경이 갖춰졌습니다. Node.js(2장) 위에서 도구들이 실행되고, Git(3장)이 변경 이력을 기록하고, Claude Code(4장)가 코드를 작성하고, GitHub CLI(5장)가 그 결과를 인터넷에 올립니다. 앞으로 어떤 장에서든 "지금까지 작업 깃허브에 올려 줘"라고 시키면 커밋과 푸시가 함께 실행됩니다. 터미널에서 `gh auth status` 한 줄로 언제든 연결 상태를 확인할 수 있다는 것도 기억해 두세요.

!!! abstract "이 장의 핵심"
    - GitHub는 Git 저장소를 인터넷에 백업하는 곳이자 포트폴리오이며, 25장의 배포도 여기서 합니다.
    - GitHub CLI(`gh`)는 `winget install GitHub.cli` 한 줄로 설치하며, 설치 후에는 터미널을 새로 열어야 합니다.
    - `gh auth login`은 GitHub.com → HTTPS → Yes → 브라우저 로그인 순서로 답하고, 일회용 코드를 브라우저에 입력하면 끝납니다. 인증은 한 번이면 계속 유지됩니다.
    - `gh repo create 이름 --public --source=. --push`로 현재 폴더를 깃허브 저장소로 만들어 즉시 올릴 수 있습니다.
    - 올릴 땐 `git push`, 받을 땐 `git pull`. 깃허브 쪽 저장소의 별명은 origin입니다.

!!! info "더 찾아보기"
    - `SSH 키 인증` — HTTPS 대신 키 파일 한 쌍으로 인증하는 방식. 서버 작업이 많아지면 익혀 둘 만합니다.
    - `gh pr` — 협업의 핵심인 풀 리퀘스트(Pull Request)를 터미널에서 만들고 리뷰하는 명령 모음.
    - `Personal Access Token` — 브라우저 없이 문자열 토큰으로 인증하는 방법. CI 서버 등 자동화 환경에서 쓰입니다.
    - `프라이빗 저장소` — `--public` 대신 `--private`을 붙이면 나만 볼 수 있는 저장소가 됩니다.
