!!! note "이 장에서 배우는 것"

## 3.1 git은 왜 필요한가: 되돌릴 수 있어야 시도할 수 있습니다

2장에서 Node.js를 설치했으니 이번에는 git을 설치하겠습니다. git은 처음 접하면 낯설게 느껴집니다. 버전 관리 시스템이라고 불리는 데다, 프로그래머가 쓰는 전문 도구라는 인상도 강한 편입니다. 코드를 직접 짜지도 않는데 왜 설치해야 하는지 궁금할 수 있습니다.

말로 시켜서 AI가 코드를 쓰는 방식으로 작업하기 때문입니다. "지도에 마커를 찍어줘"라고 한마디 하면 AI는 몇 초 만에 파일 서너 개를 만들거나 고칩니다. 그러니 중간에 하나하나 확인해 가며 따라갈 수는 없습니다. AI가 기대한 것과 다른 방향으로 코드를 고쳐 놓을 수도 있습니다. 잘 돌아가던 화면이 갑자기 하얗게 변하거나, 어제까지 멀쩡했던 버튼이 사라지는 일이 실제로 일어납니다.

이때 필요한 말이 딱 하나 있습니다.

"방금 전으로 되돌려줘."

이 한마디가 통하려면 컴퓨터 어딘가에 방금 전의 상태가 기록되어 있어야 합니다. git이 그 기록을 남겨 줍니다. 프로젝트 폴더의 상태를 원하는 순간마다 저장해 두면, 언제든 그 시점으로 폴더 전체를 되돌릴 수 있습니다.

되돌릴 수 있으면 작업이 어떻게 달라지는지 예를 들어 보겠습니다. 이 책의 후반부에서 여러분은 지도에 카테고리 필터를 붙이게 됩니다. 그때 AI에게 "필터 버튼 디자인을 좀 더 예쁘게 바꿔줘"라고 시켰는데, AI가 버튼만 고치지 않고 화면 전체의 스타일 파일을 다시 써서 지도가 화면 밖으로 밀려났다고 합시다. 어디가 어떻게 바뀌었는지 파일을 일일이 뒤져 원래대로 돌리기는 어렵습니다. 직전에 저장해 둔 시점이 있으면 사정이 달라집니다. "되돌려줘" 한마디로 이전 상태로 돌아간 뒤, "버튼 색만 바꿔줘, 다른 파일은 건드리지 마"라고 범위를 좁혀 다시 시키면 됩니다. 되돌리는 데 드는 시간이 짧으면 그만큼 여러 번 시도해 볼 수 있습니다.

Ctrl+Z로도 되는지 궁금할 수 있습니다. Ctrl+Z는 파일 하나만, 그것도 편집기를 열어 둔 동안만 되돌립니다. AI는 한 번에 여러 파일을 고치고, 새 파일을 만들고, 어떤 파일은 지우기도 합니다. 편집기를 닫으면 Ctrl+Z 기록도 사라집니다. git은 프로젝트 폴더 전체를 되돌리며, 컴퓨터를 껐다 켜도 몇 달이 지나도 남아 있습니다.

!!! tip "팁"
    저자는 AI에게 큰 작업을 시키기 전에 반드시 커밋을 하나 만들어 둡니다. 그리고 결과가 마음에 들지 않으면 되돌립니다. 커밋이 자주 있을수록 되돌아갈 지점이 촘촘해지고, 그만큼 더 큰 요청을 해 볼 수 있습니다.

git은 소프트웨어 개발 현장에서 표준으로 쓰입니다. 앞으로 쓸 GitHub(5장), Claude Code(4장), Orca(6장)도 모두 git을 바탕으로 동작합니다. 이제 설치해 봅시다.

## 3.2 이미 설치되어 있는지 확인하기

설치 파일을 받기 전에, 내 컴퓨터에 git이 이미 있는지부터 확인합니다. 다른 프로그램을 설치할 때 함께 깔렸을 수도 있습니다. 2장에서 했던 것과 똑같이, 시작 버튼을 눌러 터미널(또는 PowerShell)을 열고 아래를 입력한 뒤 Enter를 누릅니다.

```powershell
git -v
```

두 가지 결과 중 하나가 나올 겁니다. `git version 2.51.0.windows.1`처럼 버전 번호가 나온다면 이미 설치되어 있으니 3.5절의 첫 설정으로 건너뛰셔도 됩니다. 아래처럼 빨간 글씨의 오류가 나온다면 아직 git이 없다는 뜻입니다.

"용어가 인식되지 않습니다"라는 문구는 2장에서 본 것과 같습니다. 윈도우가 `git`이라는 이름의 프로그램을 어디서 찾아야 할지 모를 때 이렇게 나옵니다. 지금부터 설치하면 됩니다.

![gitforwindows.org 다운로드 페이지](images/ch03/ch03-f02.png){ width="760" }
/// caption

다운로드 목록에서 64-bit Git for Windows Setup을 고릅니다. 요즘 윈도우 PC는 거의 전부 64비트라고 보시면 됩니다. 내려받은 `Git-2.xx.x-64-bit.exe` 파일을 더블클릭해 실행하세요. "이 앱이 디바이스를 변경할 수 있도록 허용하시겠어요?"라는 사용자 계정 컨트롤 창이 뜰 텐데, 예를 누르시면 됩니다.

설치 마법사가 시작되면 라이선스 안내 화면이 먼저 나옵니다. GNU General Public License를 안내하는 화면이고, git이 누구나 무료로 쓸 수 있는 오픈소스라는 뜻이니 Next를 누르고 넘어갑니다. 설치 경로 선택 화면도 기본값 그대로 두고 Next를 누릅니다. 그다음 구성 요소 선택 화면에서는 바탕화면 아이콘과 탐색기 메뉴 연동 등을 고르게 되는데, 여기도 기본값 그대로 Next를 누르시면 됩니다.

여기까지는 선택할 것이 없습니다. 다음 화면부터 고를 것이 나올 겁니다.

## 3.4 설치 옵션, 뭘 골라야 할까

Git for Windows 설치 마법사는 선택 화면이 많은 편입니다. 에디터 선택, 브랜치 이름, PATH, 줄바꿈 처리처럼 열 개가 넘는 질문이 연달아 이어집니다.

모르는 화면은 기본값 그대로 Next를 누르면 됩니다. Git for Windows의 기본값은 대부분의 사용자에게 무난한 선택지라서, 그대로 두어도 이 책의 모든 실습을 문제없이 진행하실 수 있습니다. 이 화면들에서 무엇을 고르든 설치 후에 전부 바꿀 수 있습니다. 다만 두 화면은 짚고 넘어가겠습니다.

### 화면 하나: 기본 에디터 선택 (Choosing the default editor used by Git)

git이 메시지를 입력받아야 할 때 어떤 편집기를 열지 여기서 고릅니다. 기본값은 Vim으로 되어 있는데, 이 항목만은 바꾸기를 권합니다. Vim은 조작법이 다른 편집기와 많이 달라서, 처음 접하면 종료하는 방법조차 찾기 어려울 수 있습니다.

목록을 펼쳐 Use the Notepad as Git's default editor를 선택하세요. 메모장이 열립니다. Visual Studio Code를 이미 설치해 두었다면 Use Visual Studio Code as Git's default editor를 골라도 됩니다. 익숙한 편집기가 열리도록 해 두면 됩니다.

![기본 에디터 선택 화면 — 기본값은 Vim](images/ch03/ch03-f03.png){ width="620" }

    에디터 선택을 하지 않고 Vim인 채로 설치를 마쳤더라도 괜찮습니다. 나중에 터미널에서 `git config --global core.editor notepad` 한 줄이면 메모장으로 바꿀 수 있습니다. 잘못 골랐다고 해서 재설치해야 하는 것은 아닙니다. 이 장의 설치 옵션은 전부 설치 후에 바꿀 수 있습니다.

### 화면 둘: PATH 설정 (Adjusting your PATH environment)

2장에서 만난 PATH가 여기서 다시 나옵니다. git 명령을 어디서 쓸 수 있게 할지 정하는 화면이고, 선택지가 셋입니다.

- Use Git from Git Bash only을 고르면 git 전용 터미널인 Git Bash에서만 git을 쓸 수 있습니다. 이 책에서 쓰는 PowerShell에서는 `git` 명령이 동작하지 않으므로 고르지 않겠습니다.
- Git from the command line and also from 3rd-party software를 고르면 PowerShell을 포함한 모든 터미널과 다른 프로그램에서 git을 쓸 수 있습니다. Recommended 표시가 붙은 기본값이며, 이 책에서는 이 항목을 씁니다.
- Use Git and optional Unix tools from the Command Prompt는 유닉스 도구까지 PATH에 등록합니다. 윈도우 기본 명령과 이름이 겹쳐 문제가 생길 수도 있고 설치 화면에도 경고가 뜨니 고르지 않겠습니다.

가운데 옵션이 기본으로 선택되어 있을 테니, 확인만 하고 Next를 누르면 됩니다.

### 나머지 화면들: 전부 기본값으로

이후로도 질문이 이어집니다. HTTPS 연결 방식, 줄바꿈 처리, 터미널 에뮬레이터, `git pull`의 기본 동작, 자격 증명 관리자를 차례로 묻습니다. 화면에는 Checkout Windows-style, MinTTY, Git Credential Manager 같은 영문 항목 이름이 표시됩니다. 전부 기본값 그대로 Next를 누르면 됩니다. 각각이 무슨 뜻인지 지금 다 알아야 하는 것은 아닙니다. 마지막 화면에서 Install을 누르면 설치가 진행되고, 잠시 뒤 Finish로 끝납니다.

새 저장소의 첫 브랜치 이름을 묻는 "Adjusting the name of the initial branch in new repositories" 화면이 나올 수도 있습니다. 이것도 기본값인 Let Git decide로 두시면 됩니다. 브랜치가 무엇인지는 이 장의 끝에서 설명하겠습니다.

## 3.5 설치 확인과 첫 설정

### 버전 확인

설치가 끝났으면 제대로 설치됐는지 확인합니다. 2장에서와 마찬가지로 터미널을 새로 열어야 합니다. 설치 전에 열어 둔 터미널에는 바뀐 PATH가 반영되지 않으므로 `git` 명령이 인식되지 않습니다. 열려 있던 터미널 창을 닫고 새 터미널을 열어 아래를 입력합니다.

```powershell
git -v
```

![git 버전 확인 성공](images/ch03/ch03-f05.png){ width="760" }
/// caption
그림 3.5 — git 버전 확인 성공
///

`git version 2.xx.x.windows.1`처럼 버전 번호가 나오면 설치가 끝난 겁니다. 뒤의 숫자는 설치 시점에 따라 다를 수 있는데, 달라도 문제가 되는 것은 아닙니다.

!!! warning "주의"
    새 터미널을 열었는데도 "인식되지 않습니다" 오류가 난다면 순서대로 점검해 보세요. 먼저 정말로 새 창인지 확인합니다. 탭을 새로 여는 것으로는 부족하고, 창을 완전히 닫았다가 다시 열어야 합니다. 그다음 컴퓨터를 재부팅하고 다시 시도합니다. PATH 변경이 재부팅 뒤에야 반영되는 경우가 있습니다. 그래도 안 되면 설치 파일을 다시 실행해 3.4절의 PATH 화면에서 가운데 옵션이 선택되어 있는지 확인하며 재설치합니다. 2장에서 Node.js를 설치할 때와 같은 순서입니다.

### 이름과 이메일 등록하기

설치 확인이 끝났으면 두 줄짜리 첫 설정을 하겠습니다. git은 커밋을 만들 때마다 "누가 저장했는지"를 함께 기록합니다. 그래서 여러분의 이름과 이메일을 미리 알려 주어야 합니다. 터미널에 아래 두 줄을 한 줄씩 입력합니다. 따옴표 안의 내용은 여러분의 것으로 바꾸세요.

```powershell
git config --global user.name "홍길동"
git config --global user.email "hong@example.com"
```

`--global`을 붙이면 이 컴퓨터의 모든 프로젝트에 같은 설정이 적용됩니다. 한 번만 해 두면 앞으로 어떤 폴더에서 작업하든 다시 설정하지 않아도 됩니다. 이름은 한글이든 영어든 닉네임이든 상관없습니다. 다만 이메일은 5장에서 만들 GitHub 계정에 쓸 주소와 같은 것으로 해 두기를 권합니다. 그래야 나중에 GitHub에 올린 기록이 여러분의 계정 활동으로 이어집니다.

두 줄을 실행해도 터미널에는 아무 반응이 없을 겁니다. 이 명령은 원래 아무것도 출력하지 않습니다. 잘 저장됐는지 확인하고 싶으시면 아래를 입력해 보세요.

```powershell
git config --global --list
```

![user.name과 user.email이 등록된 모습](images/ch03/ch03-f06.png){ width="760" }
/// caption
그림 3.6 — user.name과 user.email이 등록된 모습
///

목록에 `user.name=홍길동`과 `user.email=hong@example.com`이 보이면 설정이 끝난 겁니다. 오타를 냈더라도 같은 명령을 다시 실행하면 새 값으로 덮어써지니 걱정하지 않으셔도 됩니다. 이 설정은 컴퓨터에 파일로 저장되어 계속 유지되므로, 이 두 줄은 이 책을 통틀어 한 번만 입력하시면 됩니다.

!!! tip "팁"
    이메일을 공개하고 싶지 않다면 다른 방법이 있습니다. GitHub는 실제 이메일 대신 쓸 수 있는 가림용 주소를 제공합니다. `아이디@users.noreply.github.com` 형태로 발급됩니다. 5장에서 GitHub 계정을 만든 뒤 이 주소로 바꿔 등록해도 됩니다.

그림 3.7 — 저장소·커밋·브랜치 한 컷 개념도

저장소(repository)는 git이 변경 이력을 기록하는 프로젝트 폴더를 가리킵니다. 평범한 폴더에서 `git init`을 실행하면 폴더 안에 `.git`이라는 숨김 폴더가 생기고, 그때부터 그 폴더가 저장소가 됩니다. 겉보기에는 그대로 폴더이지만 `.git` 안에 변경 이력이 쌓이기 시작합니다.

커밋(commit)은 지금 이 순간의 폴더 전체 상태를 기록에 남기는 동작을 말하며, 그렇게 남은 기록 하나하나도 커밋이라고 부릅니다. 커밋할 때는 시각, 앞에서 등록한 이름과 이메일, 그리고 무엇을 했는지 적는 한 줄 메시지가 함께 저장됩니다. 메시지에는 "지도에 마커 표시 기능 추가"처럼 적습니다. 커밋이 쌓이면 프로젝트의 변경 이력이 되고, 그 이력의 어느 시점으로든 되돌아갈 수 있습니다. 3.1절에서 말한 되돌리기를 이 기능으로 합니다.

커밋 메시지를 쓰는 요령도 미리 알아 두세요. 몇 주 뒤에 읽어도 무엇을 저장한 시점인지 알 수 있게, "수정", "작업중" 같은 말 대신 "검색 결과 클릭하면 지도 이동하게 함"처럼 무엇이 달라졌는지를 적습니다. 바이브코딩에서는 이 메시지조차 AI가 대신 써 주는 경우가 많지만, AI가 써 준 메시지가 적절한지 판단하는 것은 여러분의 몫입니다. 메시지가 구체적일수록 어느 시점으로 되돌아갈지 고르기 쉬워집니다.

브랜치(branch)를 쓰면 원래 줄기를 건드리지 않고 새로운 시도를 할 수 있습니다. 커밋이 이어지는 줄기에서 갈래를 하나 내어 그 갈래에서만 코드를 고치는 방식입니다. 예를 들어 지도 디자인을 다크 모드로 크게 바꿔 보고 싶은데 지금 상태를 유지하고 싶다면, 갈래를 하나 내고 거기서 고칩니다. 결과가 좋으면 원래 줄기에 합치고, 그렇지 않으면 갈래를 지웁니다. 원래 줄기는 그대로 남습니다. 이 책의 실습은 대부분 `main`이라는 기본 줄기 하나로 진행하니, 지금은 이런 기능이 있다는 것만 알아 두면 됩니다. 6장에서 다룰 Orca의 워크트리도 이 브랜치를 이용해 여러 AI 에이전트를 동시에 작업시킵니다.

세 단어는 이렇게 이어집니다. 저장소에 커밋을 쌓아 가고, 결과를 모르는 시도는 브랜치에서 합니다. AI가 코드를 어떻게 고쳐 놓아도 커밋이 남아 있으면 이전 시점으로 돌아갈 수 있습니다.

    > 지금까지 작업한 걸 "지도 마커 기능 추가"라는 메시지로 커밋해줘.

    > 방금 네가 고친 것 때문에 화면이 하얗게 나와. 마지막 커밋 상태로 전부 되돌려줘.

    두 번째 프롬프트가 이 장에서 말한 되돌리기에 해당합니다. 이 요청이 통하려면 첫 번째 프롬프트처럼 평소에 커밋을 남겨 두셔야 합니다.

## 3.7 마무리

!!! abstract "이 장의 핵심"
    - git은 프로젝트 폴더 전체를 시점별로 기록해 두고 되돌립니다. 되돌릴 수 있어야 AI에게 큰 작업도 맡겨 볼 수 있습니다.
    - 설치는 gitforwindows.org에서 64비트 설치 파일을 받아 진행하며, 옵션은 기본값을 그대로 두셔도 됩니다. 단 기본 에디터는 Vim 대신 Notepad나 VS Code로 바꾸는 편이 낫습니다.
    - PATH 화면에서는 권장 옵션인 "Git from the command line and also from 3rd-party software"를 그대로 둡니다.
    - 설치 후 새 터미널에서 `git -v`로 확인하고, `git config --global`로 이름과 이메일을 한 번만 등록합니다.
    - 저장소는 기록 대상이 되는 프로젝트 폴더를 가리키고, 커밋은 한 시점의 상태를 저장하며, 브랜치는 원래 줄기를 건드리지 않고 시도할 갈래를 냅니다.

!!! info "더 찾아보기"
    - `git log` — 지금까지 쌓인 커밋 목록을 시간순으로 보여 주는 명령
    - `.gitignore` — 기록에서 제외할 파일을 지정하는 목록 파일. 비밀 키를 지킬 때 씁니다(8장·24장에서 실전 등장)
    - `GitHub Desktop` — 명령어 없이 마우스로 git을 다루는 공식 GUI 프로그램
    - `Git Bash` — Git for Windows가 함께 설치해 주는 리눅스풍 터미널
    - `git checkout` / `git restore` — 과거 시점으로 되돌아갈 때 실제로 쓰이는 명령 키워드
